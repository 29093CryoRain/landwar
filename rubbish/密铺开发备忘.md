## 1. 踩坑记录（现象 → 根因 → 修复）

### 1.1 横纹 / 一片同向三角（用户："几乎只在勾选强制边缘为海时出现"）
- 试过 3 个方案都失败/被否：1 环平滑 + 三角对平均（用户明确否决）、抗锯齿重采样
  （粗场网格 + 双线性插值，只缓解）、回退最朴素逐格采样（作为基线）。
- **真正根因**：forceCoast 的**边缘衰减带**用格索引 `d = min(r, rows-1-r, c,
  cols-1-c)` 估距离，在六/三角上衰减带沿整行/整列垂直延伸 → 阈值量化后横贯整行成
  直线海陆边 = "横纹"；三角正/反格共享同一 (r,c) 减同一衰减 → 趋海被拉平 = "同向三角"。
- **修复**：衰减改用**格中心世界坐标到矩形边界的欧氏距离**
  `d = min(wx, worldW-wx, wy, worldH-wy)`，edgeBand 以 baseCell（世界尺度）为单位。
- **教训**：用户实验给的条件（"只在 forceCoast 时出现"）是定位利器，第一时间用它缩小
  范围，别急着在噪声采样上做文章。

### 1.2 边缘陆（"最外围一圈海"的判定）
- 用户规范：勾选"强制边缘为海"且陆地比例 100% 时，**只有最外围一圈是海**。
- 试过 3 个判据，前两个都错：
  1. 格中心距边界 < rim → 六偶数行最右列中心距右缘 √3a≈1.075 漏判；
  2. 格多边形顶点贴边（≤eps）→ 六偶数行最右列右顶点距右缘 √3a/2≈0.537 不贴边，漏判。
- **真正语义 = 与方形一致的"索引外圈"**（用户规范的本意就是方形 d==0 的直接推广）：
  - hex：`r==0 || r==rows-1 || c==0 || c==cols-1`（**含凹进的偶数行最右列**）；
  - tri：`r==0 || r==rows-1 || i==0 || i==cols-1`（三角对索引，最左/最右对 = 视觉最外列带）。
- **教训（最重要）**：密铺下"到边界的几何距离"无法两全——hex 左第二列与右最列到边缘
  距离相同（都 √3a/2），几何距离永远分不清"该海/该陆"；**索引语义才是与方形行为一致的
  锚点**。凡是"外圈/第几圈"这类用户规范，先按索引想，别按欧氏距离想。
- 另一个教训：**别在修 A 时顺手改 B**。衰减（世界距离）与外圈（索引）职责不同，
  曾因顺手改动引入边缘陆回归。

### 1.3 三角城市基建形状
- 旧实现：形状表 = 世界偏移 `{dx,dy,orient}`，但解析只 `worldToCell(偏移点)`，
  **orient 字段完全没参与**；且 `recomputeCityGeometry` 强制锚下标为偶（恒正三角）。
  后果：锚为反格（finishTerrain 遍历任意格作锚）时形状整体错位；1 级城恒正。
- **新语义（用户定稿）**：**正锚模式**——表按"锚=正三角"定义；锚为反三角时
  `Map::shapeCells` 对 **dy 垂直镜像**（orient 随之翻转）→ 自动得到朝向变体。
  - L1 = 1 格（正/反 2 种）；L2 = 正 + 同列下方反（**公共边水平**，即正格 k0 底邻）；
  - L4 = 边长 2b 大三角 4 格（正/反 2 种）；L6 = 6 格正六边形（左右顶点、上下平边）；
  - L8 = L6 + 顶上正 + 底下反（偏移 `(0,2h)` 和 `(0,-2h/3)`，注意是 -2h/3 不是 -4h/3）。
- **教训**：形状表的"朝向/锚"字段必须**真正参与解析**；parity-free 用世界偏移（直边布局
  下斜邻列偏移 ±1 随行奇偶变，格坐标偏移不 parity-free，世界偏移才 parity-free）。

### 1.4 三角地图尺寸语义
- width 语义 = **视觉列数（每行三角数）**，生成/配置时列对数 = `(width/2) & ~1`
  （强制偶：105→52、106→52、108→54）。cellCount = width×height 与方形一致。
- **两处必须同一公式**：`MapGenerator::generate` 与 `Map::configure`（否则 lwmap 头的
  cols 与 geom_.cols 不匹配，loadFromLwmap 报 size mismatch）。菜单"长"步进 ±2 + 强制偶。
- 六边形没有此问题：cellCount = cols×rows = width×height，与方形一致；只是世界矩形略扁
  （宽 1.075×、高 0.93×），观感接近。

## 2. 关键经验与纪律

- **基线**：任何 config 序列化 / 生成 / 几何变化都会移动 `state_hash`（hash = 全状态
  序列化的 FNV-1a）。`config.toJson()` 里密铺形状表一变，**连方形基线一起动**（纯序列化，
  行为不变）。**改动隔离验证法**：若改动只在某分支（如 forceCoast=true），CLI 基线
  （false）不变 → 用基线是否移动来证明改动没污染其他路径。
- **测试**：行为变化先补单测再动代码（外圈恒海、L2 水平公共边、L4 正反模式、正/反锚
  连通、格数=等级数）。临时探针测试验证完**删掉**，并还原 CMakeLists（**显式源列表，
  新文件必须手动加**）。慢测试是 `Determinism.*` 基线项（各跑 20000 tick，需数分钟）；
  日常迭代用 `--gtest_filter='-Determinism.*'` 跳过。
- **几何**：直边布局下"正格 k0 底 = 同列下反格"（跨行同列），斜邻同行列偏移 ±1 随
  行奇偶（p=r&1）；世界偏移取"目标格中心 − 锚格中心"（=中心差），偏移点落在格内部
  解析才稳定（贴边/贴顶点会被 worldToCell 扫描序归属到别的格）。顶点穿越（crossEdge
  返回 -1）用 nudge ε 后 worldToCell 重定位，确定性。
- **渲染**：描边必须用 `TilingGeom::cellEdge`（多边形顶点序 ≠ 邻接边序）；粗线段用
  `Renderer::fillThickSegment`（实心四边形，别用偏移平行线）；SDL_RenderGeometry 顶点
  缓冲上限 ~65535 → 分批提交（6000 顶点/批）；地图边界灰线线宽固定 2px 不随缩放。
- **工具链**：landwar.exe 在跑时链接报 `Permission denied`（先杀进程）；PowerShell
  变量名大小写不敏感（`$B=$b[...]` 会把字节数组覆盖成字节——工具脚本里命名要避开）；
  内联 pwsh 传参给 powershell -File 的转义容易坏，能用脚本文件就别内联。

## 3. 锚格朝向解析（现行机制）

- **问题**：形状表按"同边数第一个基础格"朝向编写偏移；锚格为同边数但不同朝向的基础格
  （旋转/镜像）时，偏移解析到错误格（如 Arch31212 L9 反朝向锚解析成错误类型组合）。
- **机制**：
  - `TilingGeom` 加载表后为每个基础格计算相对"同边数第一个基础格"的变换
    （`rotAngle` 旋转角 + `reflect` 镜像，用邻格中心偏移集匹配，0 NO MATCH）。
  - 新增 `baseCellTransform / shapeReferenceBase / applyAnchorOrientation`
    （Tiling.h/.cpp）：形状解析时把偏移先按参考变换求逆、再按锚格变换应用
    （合成序 R(-ref) → F(ref) → F(anchor) → R(anchor)）。
  - `Map::shapeCells` 与 `canPlaceCityImpl` 的半正/Laves 分支调用
    `applyAnchorOrientation`（运行时 90° 旋转之后）。
  - `shapeReferenceBase`：anchorBaseMask 非 0 → 取最低置位（Arch3464 L1/L2 的 b=2/8）；
    否则 → 同边数第一个基础格。
- **验证**：`TilingTable.AnchorOrientationShapesResolveCorrectlyAtAllBaseCells`（359 组
  形状×基础格全解析）与 `AnchorTransformSelfConsistent`（参考格变换恒等）单测锁定；
  正反两朝向自动成立，无需重复表项。

## 5. 扭棱四密铺接入与城市生成概率（现行）

- 数据：`data/tiling_specs_arch.json` / `data/tiling_specs_laves.json` 已合并 arch_33336 /
  arch_33434 / laves_33336 / laves_33434 周期域；四个密铺可生成/加载/移动/放单格城。
- 方向规范：四密铺满足方向规范时不存在水平周期向量，当前轴对齐矩形周期引擎无法表示；
  未来需升级 TilingGeom 周期域表示（分析见扭棱解决方案 §9）。
- 城市生成（现行模型）：
  - MapGenerator 城市概率取消沿海/海拔影响，保留山地惩罚，权重在 `map.cityMountainWeight`
    （config.json，默认 0.3）。
  - Map::finishTerrain 第二遍随机顺序；先算目标城市数，再按修正幂律分配各级数量
    （最大余数法），大城优先随机安置，小城后置，最后放首都。
  - 跨密铺总城市生产力归一化：以方形为基准，`targetCities = baseTarget × E_square / E_tiling`。
  - 采样公式：`P(x) ∝ n_x·(x+β)^(-s)`，`s = levelIncomeExponent + levelRankExponent`，
    `β=(1-minLevel)/2`；同等级多个形状变体计为多个元素。
- 城市渲染：普通城市使用 `render.city.iconFitScale` 时不再乘 `iconScale`；
  `render.city.iconFitOffsetY` 逐变体竖直偏移；首都面积与普通贴图面积一致，不施加竖直偏移。
- 交互工具 `city_icon_fit_tool`：支持缩放/竖直平移/暂存区/使用上一个值/自动保存；
  `tools/apply_city_icon_fit_scales.py` 按密铺+贴图等级取最小 scale、逐变体写 offsetY。

## 6. Arch3636 L3/L5 偏少原因分析（维持现状）

- 实测：L2/L8 数量正常偏多、L3/L5 偏少；单看"能放下"的锚数并不少。
- 真因：`finishTerrain` 按格下标序逐个掷城并立即放置。L2 只要锚格空着必成功；
  L8 数量多且先行占掉大量三角形；轮到 L3/L5 时所需邻格常已被占用 → `canPlaceCity` 失败 →
  回退最小等级（L2）落在同一六边形锚上。于是 L3/L5 被"洗"成 L2。
- 改进方向（未采纳）：① 放置失败不回退；② 大城优先两阶段放置；③ 只改采样权重。
  **用户拍板：暂不改**，维持现状。
