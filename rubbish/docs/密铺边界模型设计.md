# 密铺地图边界模型设计（修复兵种边界行为异常）

> 背景：思路.txt「下一阶段 · bug修复」第 467 行——很多非方格密铺上，兵种在地图边界
> 行为异常（常见速度变慢、方向不对、在某处往返、甚至完全卡住）。本文档分析根因并给出
> 简洁一致的修复模型。**只改逻辑，不动几何/数据语义**（除方向纠偏外）。
>
> **2026-08 决策（用户定夺）**：
> 1. **废除地图环绕功能** → 边界统一为"反弹"；wrap 相关逻辑/量/渲染双副本全部移除，
>    无需再维护"周期"量与 `MoveContext::wrap`。
> 2. **地图尺寸语义可接受** → `worldWidth/Height` 返回真实范围（含 overhang，格完整显示）。
> 3. **方向纠偏接受** → 把 90° 纠偏烘入数据（gen 脚本 rot90），删除运行时旋转。
> 4. **性能以后再做** → 本文档只解决正确性；worldToCell O(B×9×n) 优化见「密铺性能优化分析.md」。

---

## 1. 现状与症状

### 1.1 症状（用户实测 + 自建测试台复现）

- `arch_488` 军队沿水平方向（角度 0）向右移动：走到 `x = worldWidth` 处**永久冻结**，
  角不变、位置不变、`worldToCell` 返回 -1（stuck guard 刷屏）。
- 边界处偶发"往返抖动"（角度互相翻转）。
- （wrap 相关绕圈症状已随"废除环绕"一并移除。）

### 1.2 worldToCell 本身没有错（已证实）

我用自建测试台对全部表驱动密铺采样：
- **所有格中心**：`worldToCell(center) == 该格下标` 100% 通过。
- **所有格内部点**（朝每个顶点偏移 60% 的点）：同样 100% 通过。

结论：`worldToCell` 对"严格在某个格内部"的点完全正确。问题只出在两类"非内部"点：
1. **测度零的顶点/缝**（恰好落在格多边形顶点或共边上，不属于任何格内部）；
2. **凸出界外的 overhang 区**（见下）。

## 2. 根因分析

### 2.1 表驱动基础域"凸出周期盒"（overhang）

表驱动密铺数据（`data/tiling_specs_*.json`）的每个格以周期向量
`W=(wx,0)`、`H=(hx,hy)` 平移复制（`center = base.ctr + c·W + r·H`）。但**基础域的格
会越出周期盒 `[0,wx)×[0,hy)`**。下表为**运行时旋转后的几何**（`worldWidth/worldHeight`
实际作用于该几何）各密铺格在周期方向的凸出量（span = 格跨幅，R/L/T/B = 右/左/上/下凸出）：

| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| arch_33434 | 2.449×2.449 | 2.778×2.778 | 0.000 | 0.328 | 0.328 | 0.000 |
| arch_33336 | 5.584×3.224 | 4.145×6.381 | 0.691 | 0.230 | 0.798 | 0.000 |
| arch_3464 | 2.632×4.559 | 5.041×3.467 | 0.278 | 0.204 | 0.834 | 0.000 |
| arch_3636 | 1.861×3.224 | 3.224×2.792 | 0.269 | 0.000 | 0.931 | 0.000 |
| arch_31212 | 1.861×3.224 | 3.473×2.792 | 0.393 | 0.000 | 0.931 | 0.000 |
| arch_4612 | 4.559×2.632 | 3.392×5.041 | 0.380 | 0.380 | 0.380 | 0.102 |
| arch_488 | 1.414×1.414 | 1.828×1.828 | 0.414 | 0.000 | 0.414 | 0.000 |
| laves_33434 | 2.000×2.000 | 3.000×3.000 | 0.366 | 0.634 | 0.634 | 0.366 |

| laves_488 | 2.000×2.000 | 3.000×3.000 | 1.000 | 0.000 | 1.000 | 0.000 |

**根因**：`worldWidth() = wx·cols`、`worldHeight() = hy·rows` 只等于**周期**长度；
但单个基础域的格在周期方向上**跨幅 > 周期**（例如 arch_488 格跨幅 1.828 > 周期 1.414）。
因此 `cols`/`rows` 展开后，最右列/最顶行的格 overhang 越出边界（或最左/最底行越出
`[0,·)`），该 overhang 区 `worldToCell`（按 `c∈[0,cols)`、`r∈[0,rows)` 扫描）找不到格
→ 返回 -1。军队撞入该区即异常。

> 说明：overhang 是**表驱动矩形化**（`export_arch_specs.py` 用 `limit_denominator` 把斜周期
> 折成矩形）的固有产物——格本当在真实（斜）周期下复制，矩形周期"多装"了相邻周期的
> 一部分。这不是数据 bug，而是表示方式的固有 overhang。**但该 overhang 恰好构成自洽的
> 周期密铺**（面积守恒、边邻居匹配、内部点全覆盖——均已验证），真正的 tiling 是合法的。

### 2.2 军队"贴界顶点"被 clamp 兜底误判（卡死直接原因）

`moveArmyTiled`（`MovementSystem.cpp`）：

```cpp
const auto relocate = [&]() {
    cellIdx = g.worldToCell(pos.x, pos.y);
    if (cellIdx < 0) {                    // 贴界/角点防御
        pos.x = clamp(pos.x, kEps, ww - kEps);   // ← 把位置拉回 (0, ww)
        pos.y = clamp(pos.y, kEps, wh - kEps);
        cellIdx = g.worldToCell(pos.x, pos.y);   // ← 又解析回边界格
    }
};
```

军队沿格的**顶点对角线**运动（如 arch_488 斜方形的水平对角，角度 0）时：
1. `crossEdge` 命中顶点 → 返回 **-1**，位置推进到顶点（x = worldWidth）；
2. 顶点分支 `pos += ε·cos(0)` → x = worldWidth + ε（越界 overhang）；
3. `relocate()`：`worldToCell(x+e, y) = -1` → clamp 回 `ww - kEps` → 解析回**边界格**；
4. `cellIdx >= 0` → `continue`；下轮 `crossEdge` 又从同一点命中同一顶点 → -1 → 循环；
5. 守卫计数到上限 → 强行 break → **永久冻结**。

**本质**：clamp 把"军队真到了地图边界"这个信号抹掉了，把它误判成"仍在边界格内"，
于是边界 bounce/wrap 逻辑永远不触发。

### 2.3 边界一律反弹（废 wrap 后）

废除环绕后，地图边界行为统一为**反弹**（沿所撞边的直线角反射 + 随机小偏置，与方形
`bounce` 语义一致）。不再有"传送对侧"分支，也不需要"周期"量——只需"真实世界范围"。

## 3. 关键设计决定：单一「真实世界范围」

废除环绕后只需**一个**量：真实世界范围（含 overhang）。不再区分"周期 vs 范围"。

### 3.1 真实世界范围

基础域 overhang 量（相对周期盒，轴对齐 `hx=0`）：
```
xmin = min_b min_v(cell_b.v)         // 域内格最左
xmax = max_b max_v(cell_b.v)         // 域内格最右
ymin = min_b min_v(cell_b.v.y)
ymax = max_b max_v(cell_b.v.y)
```
`cols × rows` 展开后的真实范围（列 `c` 的格仅 x 偏移 `c·wx`，行 `r` 的格仅 y 偏移 `r·hy`）：
```
世界宽 = (cols-1)·wx + xmax - xmin      // 最左格在 xmin，最右格在 (cols-1)·wx + xmax
世界高 = (rows-1)·hy + ymax - ymin
```
`worldWidth()/worldHeight()` 返回此真实范围。hex/tri/square **无 overhang**
（格跨 == 周期，`xmin==0、xmax==wx`），两者相等，现有行为不变。

### 3.2 消费方

| 消费方 | 用途 |
| :--- | :--- |
| `TilingGeom::worldWidth/Height` | 渲染/相机/预览/地图范围（真实范围） |
| `worldToCell` | 界内判定；越界返回 -1 |
| `SpatialHash::bucketIndex` / spawn / projectile / effect 的 clamp | 夹取到 [0, 真实范围) |
| `moveArmyTiled` 边界 | 越界 → 反弹 |

## 4. 修复方案（简洁一致）

### 4.1 让 `worldToCell` 在真实范围内"全定义"（关键）

对表驱动分支，加一个**对顶点/缝的宽松兜底**：当严格凸包含全部失败时，若点在
**真实世界范围内**，返回"最近的候选格"（记为 bestD2 的格）。这解决"测度零顶点/缝
返回 -1"——顶点是相邻格共点，返回任一共点格都合法。**越出真实范围的点仍返回 -1**
（那是真越界，需交给移动端 bounce）。

```cpp
// 原有 9 窗口严格扫描；失败时记录 bestD2/bestIdx。
if (bestIdx >= 0 && bestD2 <= 4·rx·rx
    && wx >= -kTol && wx <= worldW() + kTol
    && wy >= -kTol && wy <= worldH() + kTol)
    return bestIdx;
return -1;   // 真越界
```

### 4.2 删除 `moveArmyTiled` 的 clamp 兜底，统一"越界即反弹"

`moveArmyTiled` 逻辑收敛为（**不做位置 clamp 拉回，没有 wrap 分支**）：

```
while (remLength > 0):
    战斗检查
    crossed = crossEdge(cellIdx, pos, angle, remLength)
    if crossed == -2:                      # 走完
        终点格补征服; return
    if crossed == -1:                      # 顶点命中
        pos += ε·(cos,sin);  cellIdx = worldToCell(pos)
        if cellIdx >= 0: continue          # 已穿入相邻格
        # 顶点两测都无格 → 贴地图边界顶点/角
        angle += π + 4ε + jitter
        continue
    # crossed = 边序号
    neighborRaw → (nr,nc)
    if (nr,nc) 出界:                       # 撞地图边界边
        bounceLine(edgeLineAngle)
        continue                           # 下一轮 worldToCell 重取
    nb = neighbor(cellIdx, crossed)
    进格处理 processEnteredCell(...) (含山/海/征服/反弹)
    if 未反弹: cellIdx = nb
```

要点：
- **不再 clampWorld/relocate 的 clamp**：位置只在 crossEdge 内推进，越界即由
  `worldToCell`（真实范围版）检测为 -1 或 `neighborRaw` 出界 → 立即反弹。
- 反弹后**位置仍在边界格内**（且该格是真实范围内顶点紧邻的有效格），下一轮
  `crossEdge` 反向推进，自然离开边界。不会 clamp 回同一点。
- `crossEdge` 的 `-1` 顶点分支：先 nudge+worldToCell（宽松版能解析顶点），解析到
  相邻格就 `continue`——顶点头正常穿越；解析不到才是真边界 → 反弹。

### 4.3 删除 wrap 相关

随"废除环绕"一并移除：
- `MoveContext::wrap`、`Options.map.wrap`、`Menu` 环绕复选框、`Cli --wrap`/`wrapSet`、
  `Headless` 的 wrap 分支。
- `ArmyRenderer`/`Application`/`RendererUtil` 的环绕双渲染、`WrapDraw.h`/`wrapdraw.cpp`、
  点选对副本处理。
- `moveArmySquare`/`moveArmyTiled` 中 wrap 分支、`wrapPos`。
- 相关单测（`WrapDraw.*`、`Movement.Wraps*`、`Headless.WrapDeterministicAndDiffersFromOff`、
  `Options` 的 wrap 断言、`Tiling` 的环绕接缝测试）删除或改为 非wrap 断言。

## 5. 实施步骤

1. **数据/方向纠偏**：`gen_tiling_specs_v2.py` 烘入 90° 纠偏（rot90），重生成
   `data/tiling_specs_*.json`；删除 `loadTable` 的运行时旋转（几何点逐点一致，已交叉验证）。
   随后计算 `xmin/xmax/ymin/ymax`（域内全部格顶点范围，基于最终几何）。
2. **几何接口**：
   - `worldWidth()/worldHeight()` → 真实范围（含 overhang，公式见 §3.1）。
   - `worldToCell` 表驱动分支：加 §4.1 宽松兜底。
3. **世界范围消费方**：`SpatialHash::bucketIndex`、`SpawnSystem`、`ProjectileSystem`、
   `EffectSystem` 的 clamp 用真实范围（原 `worldWidth` 即真实范围，语义自动对齐）。
4. **移动**：按 §4.2 重写 `moveArmyTiled`，删 `clampWorld`/`relocate` 的 clamp；
   边界统一"越界即反弹"。
5. **废除 wrap**：按 §4.3 移除 `MoveContext::wrap`、`Options.map.wrap`、菜单复选框、
   `Cli --wrap`/`wrapSet`、Headless 分支、环绕双渲染（`WrapDraw`/`ArmyRenderer`/
   `RendererUtil`/`Application` 点选）、`moveArmySquare`/`moveArmyTiled` 的 wrap 分支、
   `wrapPos`，及对应单测。
6. **chooseTableDomain**：宽高比让稳定（真实范围；沿用 `worldWidth/Height` 后自动对齐）。

## 7. 风险与取舍

- **风险**：`worldToCell` 宽松兜底会改变某些"奇异点"的返回值（顶点从 -1 变为某格）。
  这些点测度零、不影响格内/中心解析，但可能轻微影响依赖 `worldToCell` 的其他路径
  （如城市形状放置，锚点在格内不受影响）。
- **世界范围语义**：`worldWidth/Height` 改为真实范围后，相机/渲染/预览的地图边界按
  "格完整显示"呈现（此前边界处格被裁掉一角）。用户已接受此语义。
- **废除 wrap 的影响面**：涉及选项/菜单/CLI/渲染/移动/测试多系统，需一并清理；
  属既定方向（用户定夺），风险在于改动面大——按 §4.3 清单逐项删净即可。
- **不新增数据语义**：仅方向纠偏（gen 脚本 rot90）+ overhang 由几何接口计算（不写回 JSON）。

## 8. 结论

设计已收敛：**单一「真实世界范围」（含 overhang）+ 边界统一反弹 + worldToCell 宽松兜底
+ 方向纠偏烘入数据 + 废除 wrap**。为正确性修复，不涉及性能（另文处理）。可据本文档
分步实施并验证（§5 步骤、§6 验证指标）。
