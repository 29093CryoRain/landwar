# 代码卫生

> **接手必读**。本文管与模块无关、每次写代码都适用的习惯与门禁。
> 模块/接口约定见 `.docs/工程规范.md`，文档规则见 `.docs/文档卫生.md`。
> 冲突时以模块约定为准；两者都没有的，按本文第 0 节判断。

## 0. 指导思想

- 项目处于快速迭代期：**旧格式、旧接口、旧参数默认不保留、不兼容**，该删就删，不写迁移层和兼容分支。
- 能删的代码是负债不是资产。
- 一个事实只允许一份实现。重复实现是本项目反复踩过的头号教训。
- 兜底机制只是在掩饰小 bug，酿成大 bug：边界硬校验，内部不静默兜底。
- 宁可启动即报错，不要带着坏数据继续跑。

## 1. 不变量与断言

- 双簿记不变量（如 `Faction.cityCount == cityIds.size()`）加 `assert`（Debug 生效）。
- `assert` 只表达"内部不可能发生"；外部输入用显式校验 + 报错，不用 `assert` 代替。
- 断言表达式内不写副作用。

## 2. 单一事实源（SSOT）

- 先找唯一入口再动手：路径 `src/core/Paths.h`、UI 缩放 `src/ui/UiScale.h`、颜色 `src/ui/UiText.h`、
  坐标 `math::toScreenXf/Yf`、LOD `TintCache::pickSizeIndex()`、绘制原子 `src/render/RendererUtil.h`。
- 禁止复制粘贴后微调；需要变体就改唯一入口加参数。
- 新增共享常量/换算，必须回填 `.docs/工程规范.md` 对应清单。

## 3. 兜底与错误处理

- 边界层（config、存档、地图文件、CLI、用户输入）必须校验，失败要明确报错。
  config 缺键回退默认值是设计，**未知键（打错）必须告警**，同步义务见 `.docs/工程规范.md` §4。
- 内部层：不变量被破坏就 `assert`/报错，不"修一修继续跑"。
- 禁止空 `catch`、`catch(...)` 吞异常、用默认值掩盖缺失字段。
- 报错信息必须能定位：带键名/路径/实际值。

## 4. 日志

- `error` = 流程或数据已失败；`warn` = 可疑但可继续；`info` = 低频状态；`debug` = 排查。
- 禁止热路径/每帧日志；循环内同类错误去重或限流。

## 5. 兼容与清理

- 旧格式、旧接口、旧参数、旧文件：无特殊说明一律直接删；不确定用途先移入 `rubbish/`，不长期留主目录。
- 不留 `#if 0`、注释掉的大段代码、无人调用的死接口。
- 清理与行为变更分开提交，便于回滚与二分。

## 6. 编译与门禁

- 目标统一 `-Wall -Wextra`，**新代码零新增警告**；修根因，不用 `(void)`/抑制掩盖。
- 新功能落地：`ctest --preset release` 全绿 + `build-release/landwar.exe --headless --seed 42 --ticks 1000 --summary`。
- 修 bug 先写可复现测试，再改代码。
- 新逻辑必须可无头测试；测试文件 `tests/test_xxx.cpp` 手动加入 `CMakeLists.txt`。
- 渲染/UI 语义基线更新流程见 `.docs/工程规范.md` §3。

## 7. 文本与格式

- UTF-8 无 BOM、LF、4 空格缩进、文件尾换行；注释保留中文，不混 GBK。
- 头文件统一 `#pragma once`。
- 命名沿用现状：命名空间 `lw` / `lw::render` / `lw::ui` / `lw::comp`；类型 `PascalCase`、方法
  `camelCase`、常量 `k` 前缀、成员 `_` 后缀。裸 `namespace render/ui/app` 是旧写法，见到即改。

## 8. 依赖

- 不擅自新增第三方依赖；确需新增：许可 + `THIRD_PARTY.md` + CI 可见。`_deps` 整体替换时注明版本。

## 9. 提交

- 一个提交一件事；中文 `主题：动作/结论`；不混入全文件格式化、构建产物、本机路径。

## 提交前自检

- [ ] 有没有重复实现？唯一入口用对了吗？
- [ ] 有没有新增兜底/兼容分支？
- [ ] 失败路径会响吗？报错能定位吗？
- [ ] 零新增警告？`ctest` + 无头烟测过了？
- [ ] 该删的旧代码删了吗？相关文档同步了吗？
