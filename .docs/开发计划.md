## 0. 现状回顾（开发基线）

- **架构**：SDL2 + entt ECS + Dear ImGui；`Simulation`（纯逻辑）持有
  `Config/map/factions/Rng/registry/turnOrder/pendingSpawns/deaths/goSeaProbability/tickCount`，
  每 tick 依次跑 Movement→Combat→Effect→Economy→Production→Death 系统；渲染只读不写。
- **确定性**：所有随机来自注入 `Rng`（mt19937）；`(seed, config, map)` 唯一决定整局；
  实体 id 单调分配（`Simulation::createEntity`），存档/读档可续跑。
  **本扩充版新增：`options`（势力出场/地图选择/玩家配置）影响 init 阶段的 RNG 消耗，
  因此确定性键扩为 `(seed, config, map, options)`。** 无玩家输入时（headless / 回放）
  各方默认 aiId=0，行为与旧基线一致。
- **config**：全部魔法数字外置 `data/config.json`（`Config` 结构 + json 双向，`toJson()`
  与 `loadFromJson` 严格对称，快照往返无损）。新增键必须同步更新 `.docs/配置说明.md`。

  （排序键=已花费+单价）；`Faction` 持有 `armyCost[6]/producedCost[6]`。

## 1. 开发顺序总览

### 1.1 排序原则（扩充版）

1. **先做"入口与容器"**：菜单/选项系统是势力配置、地图选择、地图类型、边界开关、随机图
   参数的共同入口——必须先有它，后续功能才有地方接入。
2. **先做"抽象"再堆功能**：
   - **产兵 AI 抽象**（默认 AI = 公平调度堆）→ 玩家 AI 是"一个特殊的产兵 AI"（P1→P2）。
   - **面板抽象**（多面板可隐藏/移动）→ 消息/科技/统计面板都挂其上（P3→P4/P8/P11）。
   - **地形抽象**（海/陆 → +山地）→ 随机地图生成山、山地移动/渲染（P5→P6）。
   - **边界抽象** → 边界贯通、异种地图（P10→P12）。
   - **增益抽象**（势力特色统一为增益）→ 科技（科技=增益的一种）（P7→P8）。
   - **兵种行为抽象**（死亡特效/周期动作从类型解耦）→ 射弹兵（P9 任务 0）。
3. **先做"低风险高价值"**：玩家游玩（可玩性，验证 AI 抽象）；面板/消息（UI 基础设施）。
4. **最难的最后**：异种地图（六边形/三角形密铺）需要严密的几何改造，放最后并单列。
5. **经济重构章（P13–P15）排在异种地图之前**：思路 9 明示"这个放在异种地图之前做就行"。
   城市系统重做（P13）是地基（提供 `City.level`/多格基建/整城易主挂点），经济重构（P14）与
   首都系统（P15）依赖它；P14 经济公式为 P8 科技（经济振兴/经济建设/扫荡）预留 hook。
6. **依赖驱动**：山地 → 随机地图（生成山）；增益 → 科技；消息 → 科技/统计（事件通道）；
   射弹 → 统计（击杀/占领计入该兵种产生的效果）。

### P1 — 菜单与选项系统 + 产兵 AI 抽象

**目标**：启动进菜单，配置选项并保存为 json；引入产兵 AI 接口，默认 AI 行为不变。

**详细任务**：

1. **选项数据结构**（新 `src/core/Options.h/.cpp`，纯逻辑、可序列化）：
   ```cpp
   namespace lw {
   struct FactionSlot {
       bool enabled = true;  // 势力是否出场（false → 不放置首都、alive=false）
       int  aiId   = 0;      // 产兵 AI id：0=默认 AI；1=玩家（P2 生效，最多一个势力=1）

       enum class Kind { File, Random } kind = Kind::File;
       std::string file = "data/map_bigIslands.bmp";  // Kind::File：地图文件路径（默认=基线图）
       std::uint32_t randomSeed = 0;       // Kind::Random：P6 随机图种子（独立于局种子）

       bool wrap = false;                  // P10 边界贯通开关（思路 5 的"作为选项界面选项"）
   };
   struct Options {
       std::array<FactionSlot, kPlayerFactionCount> factions;  // 下标 0..7 ↔ 势力 id 1..8
       MapSelection map;
       // P12 密铺类型（思路 2.1）预留字段
   };

   Options loadOptions(const std::string& path);
   void saveOptions(const Options&, const std::string& path);
   }
   ```

### P2 — 玩家游玩（玩家作为产兵 AI）

**目标**：玩家可选一个势力（≤1）操控产兵；其余势力用默认 AI。

**前置**：P1（Options/ProductionAI）。

**详细任务**：

1. **玩家意图通道**（`Simulation` 纯逻辑侧新增）：
   ```cpp
   struct PlayerIntent {
       bool active = false;      // 本势力是否由玩家操控（aiId==1）
       int factionId = 0;
       int selectedType = -1;    // -1 = 未选兵种 → 不产
       int selectedCity = -1;    // -1 = 未选城市 → 不产；否则 Faction::cities[] 下标
   };
   // Simulation 增加：setPlayerIntent(...) / playerIntent() ；
   // PlayerAI::nextProduction 读 intent：
   //   if economy < armyCost[selectedType] || selectedCity<0 → 不产
   //   else 在 cities[selectedCity] 处产 selectedType 一兵，扣成本（faction.producedCost 累计），
   //        重复直到库存不足（每 tick 可产多个，仅此一个兵种/一个城市）。
   ```
   - 产兵只"仅尝试在经济足够的情况下生产这种兵"，**不再自动产其他兵种**（思路 额外1）。
   - 确定性：玩家意图是**外部输入**，不写入快照、不进 `Rng`；headless/回放无意图 →
     玩家势力不产兵（且 headless 默认全 aiId=0，基线不受影响）。

2. **兵种选择交互**：
   - `InputManager` 增加 `selectUnitType` 动作：数字键 `1`–`6` 对应 6 兵种（`ArmyType`）。
   - DebugPanel（主面板）新增**兵种图标栏**：一行 6 个 `ImGui::ImageButton`，用
     `SpriteSheet` 的 `army.png` 子图；点击选中、被选中图标**高亮边框**；图标下方标注该兵种
     产兵所需经济（`armyCost[type]`，含势力 costDiv 修正）。
   - 选择结果写入 `PlayerIntent.selectedType`（仅玩家势力生效）。

3. **城市选择交互**：
   - **悬停指示圈**：`Application` 每帧计算鼠标所在世界格，若在其 `hoverCityRadius`（config，
     建议 2–3 格，含格本身）内有己方城市，取最近者 → 渲染**旋转带纹路指示圈**（色相=势力色，
     明度/饱和度 config 可调）。

     所在城。
   - **指示圈贴图由 AI 程序化生成**（思路 额外1："指示圈贴图让 ai 画"）：加载时用 SDL 生成一张
     小纹理（如 128×128：圆环 + 径向纹路/虚线），按势力色着色；旋转角用 `ttime`（世界时钟）
     或渲染本地时钟——**绝不动 sim RNG**。
   - 绘制层：新 `render/CityMarkerRenderer.{h,cpp}`（或并入 `EffectRenderer`）。
   - 点击己方城市 → 设为 selectedCity（ImGui 捕获时抑制，沿用现 `mouseCaptured_`）。

4. **信息栏标注**：DebugPanel 在玩家势力行高亮显示当前经济（留存值 `faction.economy`），
   并显示"已选兵种/已选城市"摘要。

   `sim.setPlayerIntent(...)`。

**涉及文件**：新 `sim/ai/PlayerAI`、`core/Simulation`、`app/InputManager`、`app/Application`、
`ui/DebugPanel`、`sim/systems/ProductionSystem`、新 `render/CityMarkerRenderer`、`core/Config`
（新增 `player.hoverCityRadius`、指示圈明度/饱和度）。

### P4 — 消息系统（含势力灭亡检测）

**目标**：重大事件（势力灭亡、取得科技等）在独立消息面板弹出，留存后渐隐；消息过多立即
消失（思路 6.0.5）。

**前置**：P1；P3（消息面板）。

**详细任务**：

1. **事件 → 消息通道**（`Simulation` 纯逻辑侧新增）：
   ```cpp
   enum class GameEventKind { FactionAnnihilated, Unification, TechAcquired, Custom };
   struct GameEvent {
       GameEventKind kind;
       int factionId = 0;      // 相关势力（TechAcquired 为取得方）
       int data = 0;           // 附加量（如科技 id / 等级）
       std::string text;       // 组装好的文案（渲染层直接显示）
       std::uint64_t tick;
   };
   // Simulation 持有 std::vector<GameEvent> events_；tick() 末尾产生事件；
   // Application 每帧取走（takeEvents()）→ MessagePanel。
   ```
2. **势力灭亡检测**（判定时机：tick 末尾，DeathSystem/EffectSystem 已结算后）：
   - 势力 `alive && cityCount==0 && countArmies(faction)==0 && countEffects(faction)==0`
     → 发 `FactionAnnihilated`，置 `alive=false`。
   - `countArmies/countEffects` 用 registry 视图按 `FactionId` 组件统计；**注意特效也算**：
     "地雷/爆炸/激光/射弹等效果也全部消失"才灭亡（地雷拖 60s 自爆期间势力不算灭亡）。
   - 每次判定遍历 1..8 各势力，线性 8 次视图查询，开销可忽略；若后续兵量大再增量计数。
3. **统一检测**：alive 势力数（id 1..8）== 1 → 发 `Unification` 事件（P11 统计以此为截止）。
4. **MessagePanel**（新 `ui/panels/MessagePanel`，挂到 P3 PanelManager）：
   - 消息模型 `{text, tick, ttlTicks, priority}`；面板内从上到下展示，留存 `ui.messageTtlTicks`
     （config，建议 600 tick）后**渐隐**（每帧 alpha 递减）；消息数超 `ui.messageMaxShown`（如 12）
     时**立即丢弃最旧**。
   - 文案中文，复用 ImGui 中文字体。
5. **扩展点**：事件系统做成通用通道——P8 科技取得、P11 统计截止都往里发。

**涉及文件**：`core/Simulation`（events_ + takeEvents + 灭亡/统一检测）、新 `ui/panels/MessagePanel`、
`app/Application`（每帧 drain + 组装文案）、`core/Config`（`ui.messageTtlTicks/messageMaxShown`）。

**测试计划**：
- 灭亡检测：清空一势力城市+兵+特效 → 发事件；残留一个地雷 → 不发。
- 统一检测：只剩一 alive 势力 → `Unification` 恰一次。
- MessagePanel：ttl 渐隐、超量丢最旧（mock 时间）。
- 事件不进快照（与 PlayerIntent 同理，纯展示通道）；快照往返不受影响。

**验收**：
1. 势力灭亡在消息面板弹消息并渐隐。
2. 无特效残留时**不误报**（有地雷/激光/爆炸残留的势力不算灭亡）。
3. 统一时刻触发统一消息。
4. P8 后科技消息可用同一通道。
5. `ctest` 全绿；`--headless` 基线不变（检测为纯逻辑，不新增 RNG 消耗）。

**风险与注意**：灭亡判定要放在**特效结算之后**（效果还挂着时别判死）；`countEffects` 的
特效是"该势力创建的"还是"该势力拥有的"——用 `FactionId` 组件（特效归属势力）即可，与
`Creator.factionId` 语义区分清楚。

### P5 — 山地地形

**目标**：新增"山地"地形（第三种地形），含移动规则与渲染；山只出现在不与海相邻的陆地上。

1. **地形数据**：`MapCell` 增加 `bool mountain`（山是陆地的一种，`land` 仍为 true）。
2. **BMP 读取约定**（思路 4："具体怎么读取出山还需日后的功能"——本计划定约定）：
   - 新增 config `terrain.mountainBrightMin/Max`（建议初值 [150, 210]）：
     陆地像素亮度在此区间 → `mountain=true`。
   - **基线保护**：先跑 `tools/gen_golden_map.py` 统计现有 `map.bmp` 各陆地亮度分布，确认
     所选区间在现有图上**无命中**（否则现有地图全部变山，破坏基线）；若命中则调区间或仅对
     "已标注的山区地图"启用（`terrain.mountainFromBmp` 默认 false，新地图再开）。
   - 城市判定不受影响（亮度仍按原公式）。
3. **邻海修正规则**：加载后一遍纯循环——任何 `mountain==true` 且 8 邻域（含对角）有海格的
   → 置 `mountain=false`（普通陆地）。确定性，无 RNG。
4. **移动规则**（`MovementSystem`，类比"陆→海"）：
   - 新增 `comp::MountainState { bool inMountain = false }`。
   - **陆→山**（goal 是山且自己不在山）：`chance = terrain.mountainEnterChance`（config），
     `rng.chance(chance)` 成功 → 进入山地、`speed *= terrain.mountainSpeedMult`、
     `rem` 同步缩放、`inMountain=true`；失败 → 反弹（水平/垂直规则同海）。
   - **山→陆/海**：离开山地 → `speed /= terrain.mountainSpeedMult`（复原）、`inMountain=false`，
     方向不变（类比登陆）。
   - **山→海 / 海→山** 也按此路径（山是陆地子集，先判山、再判海）。
   - 配置：`terrain.mountainEnterChance`（建议 0.5）、`mountainSpeedMult`（建议 0.5）。
   - **确定性**：山地概率只在目标格为山时调用 `chance`；现有地图无山 → 零调用 → 基线不变。
5. **渲染**：
   - **山**：先画陆地基色，再叠画"线条风格山峰"贴图（近黑但不纯黑，如 `mix_color(势力色, 黑, 0.92)`）。
     新贴图 `data/mountain.png`（AI/程序化生成线条峰形，透明背景）。
   - **城市渲染改版**（思路 4 明确要求）：改为先画陆地基色，再叠画"线条风格城市"贴图
     （比势力默认色略深但不黑，如 `mix_color(势力色, 黑, 0.15)`）。新贴图 `data/city.png`。
     > **注意**：这是**有意的视觉基线变化**（原 `翻新计划 §2.9` 城市 = `mix_color(色,黑,0.8)`），
     > 视觉对拍时以此为准。
   - 山+城同格：山在下、城在上（绘制顺序）。
   - `MapRenderer` 改为：海→黑；陆→基色；山→基色+山贴图；城→基色+城贴图（若有山再加山贴图）。

### P6 — 随机地图生成

**目标**：用算法生成海陆图（可含山），独立种子，参数可调，可保存/加载（思路 3）。

**前置**：P1；P5（山地）。

> **决策（2026-08-06，用户定夺）**：随机地图生成**用 C++ 实现**（`world/MapGenerator.{h,cpp}`，
> 菜单内实时生成 → 落盘 BMP → 走现有 `loadFromBmp` 开局），**不用 Python 外置**——保证游戏内
> 直接生成、不依赖玩家机装 Python。Python 仅作离线造图/转换工具（`tools/` 先例：
> `gen_probability_maps.py`/`gen_golden_map.py`）。两段式结构（① 海拔场生成 → ② 阈值切海陆 +
> 编码地形基图 BMP）与下方任务 1/2 一致；生成器持独立 `Rng(seed)`，与局种子完全独立。

**详细任务**：

1. **生成算法**（新 `world/MapGenerator.{h,cpp}`）：
   - 先用**广为流行的已知算法**生成精细海拔图（思路 3 补充：如 **value noise / Perlin fBm**
     叠加 octave），得到每个格子的海拔 `h∈[0,1]`；再用阈值切出海/陆（阈值由目标海陆比反推，
     如取排序后分位数）。
   - 可选 coast smoothing（少数轮"陆→海 邻海则转海"式腐蚀/膨胀），参数外置。
   - 生成山：在非海邻接的陆地格中，按海拔从高到低选取直至达到 `mountainDensity` 目标占比
     （依赖 P5 的"山只在内陆"规则）。
   - 独立 `Rng`（`MapGenerator::generate(seed, params)` 内部持 `Rng(seed)`），**与局种子完全
     独立**（思路 3："需要使用单独的随机数种子"）。
2. **输出/加载**（保持单一加载路径，最严谨）：
   - 生成器把结果**写成地形基图 BMP**（复用 P5 改版的 RGB 概率权重编码：任一分量<32=海、
     山概率=ramp(R)、城概率=ramp(G)），然后走**现有 `Map::loadFromBmp`** 正常加载
     （海陆确定性 + 山/城概率掷骰 + 首都放置 + 邻海修正全部复用）。
   - 生成器需按城市目标密度选取陆地格的 G 值（g=128+127·p_city）与山的 R 值：
     期望城市密度 `ρ` → 按 `ρ` 反推陆地格 g 分布使得期望城市数 ≈ `ρ×内陆格数`。
   - 保存路径：`data/gen_<seed>.bmp`（菜单可指定文件名）。
3. **参数界面**（菜单"随机生成"面板，`ui/Menu` 内）：
   - 参数：长、宽（默认 105×95，允许其他大小）、海陆比、山密度、城市密度、种子。
   - 交互：滑块 + 输入框；**支持复制/粘贴/填充**（数字文本框，思路 3："可以用填入, 粘贴,
     复制, 或滑块方式与玩家交互"）。
   - 按钮：「随机种子」「生成并预览」（生成后渲染一帧小预览到菜单内，可选）、
     「保存到本地」`data/gen_<seed>.bmp`、「用此图开始游戏」。
4. **接入**：`Options.map.kind=Random` + `randomSeed` + 参数 → 菜单点开始时
   `MapGenerator` 生成 BMP → `Simulation` 用该文件初始化（即 `buildSimulation` 里先落盘再
   `cfg.map.file=该文件`）。
5. **密铺扩展占位**：生成器内部海拔层独立于密铺类型；P12 让生成器支持所选密铺（渲染/边界
   层差异）。

**涉及文件**：新 `world/MapGenerator`、`ui/Menu`、`core/Options`（随机图参数字段）、
`world/Map`、`core/Config`、`tools/gen_golden_map.py`（校验生成图）。

**测试计划**：
- 同 seed 同参数 → 两次生成 BMP 逐字节一致（确定性）。
- 生成图可被 `Map::loadFromBmp` 正常加载，城市/山分布符合参数（抽样断言）。
- 邻海山被修正；海陆比落在容差内。
- 亮度→城市密度的映射误差在容差内。

**验收**：
1. 菜单可选"随机生成"并出参；同种子生成一致。
2. 生成图可保存、可重新加载、可"用此图开始"。
3. 山分布符合规则（仅内陆、目标密度）。
4. 与局种子独立（改局种子不影响生成图）。

**风险与注意**：生成 BMP 的亮度编码必须与 P5 山地约定一致；城市密度通过亮度分布控制，
`Map::loadFromBmp` 的城市概率 RNG 消耗次数取决于陆地格数——不同参数产生不同图 → 确定性
由 `(生成种子, 参数, 局种子, config)` 共同决定，写进文档。

### P7 — 增益系统

**目标**：把势力特色统一为"增益"形式，支持同种叠加/减益，为科技铺路（思路 6.1）。

**前置**：P1。

**详细任务**：

1. **增益数据模型**（新 `sim/Buff.{h,cpp}`）：
   ```cpp
   enum class BuffType {
       CostDiv, SpeedMult, SeaMult, BounceMult, PioneerSpeedMult,
       LaserBeams, LaserDurationMult, LaserLengthMult,
       BombRadius, MineTriggerRadius, FreeArmyChance,
       // P8/P9 扩展：MountainSpeedMult、ProjectileRate 等
   };
   struct Buff {
       BuffType type;
       double magnitude = 0;    // 语义随 type（如 CostDiv 用乘数 0.9=造价 ×0.9）
       int stacks = 1;          // 叠加次数（同 type 可合并为一条，见叠加规则）
       std::string source;      // 来源（"faction" / "tech:<id>"），UI 溯源
   };
   // Faction 增加 std::vector<Buff> buffs；
   // Faction::effective(BuffType) -> double（聚合叠加，见下）。
   ```
2. **叠加规则**（**必须明确定义**，思路 6.1 点名）：
   - **乘算型**：`CostDiv / SpeedMult / SeaMult / BounceMult / PioneerSpeedMult / BombRadius /
     MineTriggerRadius / FreeArmyChance` → 各条 `magnitude` 相乘（如两条造价 ×0.9 与 ×0.8
     → 0.72）。
   - **加算型**：`LaserBeams`（条数）→ 直接相加。
   - **乘算封顶**：速度/概率类结果 clamp 到 `[config.buff.minMult, config.buff.maxMult]`
     （如 [0.1, 10]），防爆炸值。
   - 叠加方式作为 `config.buffs.stackMode.<type>` 数据驱动（默认如上）。
3. **统一读取**：各系统把 `Faction` 现有 `costDiv/speedMultAll/seaMult/bounceMultAll/
   pioneerSpeedMult/extraLaserBeams/laserDurationMult/laserLengthMult/bombRadius/
   mineTriggerRadius/freeArmyChance` 的**直接读取**改为 `faction.effective(BuffType)`。
   - `Config::Faction` 字段保留作"势力定义"；`initFromDef` 把它们翻译成初始 `buff` 列表
     （`source="faction"`）。**不重复读两套**，防止分叉。
4. **迁移策略（行为保持）**：
   - 一步迁移完所有读取点；每迁移一处跑对应单测；最后跑基线断言 `state_hash` 不变。
   - 迁移后 `--headless --seed 42` 摘要与迁移前逐项一致（land/city/army/经济）。
5. **减益**：`magnitude` 或负向乘数即减益；叠加规则同正向（文档注明）。
6. **扩展**：P8 科技 = 追加 `source="tech:<id>"` 的 buff；UI（科技面板）可展示来源。

**涉及文件**：新 `sim/Buff`、`world/Faction`、`core/Config`（`buffs.stackMode` + clamp）、
各系统读取点（Movement/Economy/Production/Effect/Death）、`.docs/配置说明.md`。

**测试计划**：
- `effective`：乘算/加算/封顶各分支；无 buff → 1.0 基础。
- 势力默认值迁移后 `effective == 原字段值`（对每个势力×兵种全组合断言）。
- 基线回归：迁移完 `state_hash` 不变。

**验收**：
1. 默认配置下行为与迁移前一致（`--headless --seed 42` `state_hash` 不变）。
2. 可动态叠加同种 buff 并正确生效（单测验证叠加公式）。
3. 减益可用。

**风险与注意**：这是"行为保持型"重构，风险最高的是**漏改一个读取点**——用全量基线 + 全
组合单测锁死；改完逐系统排查 `grep` 原字段名确认无残留读取。

**✅ 完成记录（2026-08-06，P7）**：增益系统（纯数值迁移，行为保持）。**后续机制类增益由用户
另行设计后分批实现**（见 2026-08-06 讨论：批量写规格 → 批量分诊 → 按系统分组实现）。

### P8 — 科技系统

**目标**：科技=增益的一种；科技点系统；默认 AI 随机选科技并升级；玩家游玩给出"n 选 1"；

   - 基础：每 `tech.pointsEveryTicks`（建议 2400，即 40s）得 `tech.pointsPerTick`（建议 1）。

2. **科技表**（数据驱动，`config.json` 新增 `techs[]`）：
   ```jsonc
   { "id": "cost_vanguard", "name": "先锋造价降低", "maxLevel": 5,
     "levels": [
       { "cost": 1, "buff": { "type": "CostDiv", "magnitude": 0.9, "param": "vanguard" } },
       { "cost": 2, "buff": { "type": "CostDiv", "magnitude": 0.85, "param": "vanguard" } }
       // 每级 cost 递增；升级 = 取下一级

   ```
   - 例表（覆盖思路 6.2 全部例子）：某兵种造价降低 / 速度提升 / 品红式"占领新城概率免费得兵"
     （每兵种一条科技，概率不同）/ 解锁新兵种（P9 兵种，`buff.unlockUnit`）/ 兵种效果提升

   之后按需定）：

     ∩ 该科技未满级），`rng.get(n)` 随机选一个 → 扣 points → `Faction` 追加该级 buff →

#### 1. 密铺几何（面积相等推导边长）

世界单位 1 格 = 正方形边长 = `blockSize` px（`cellPx = blockSize × zoom` 保持为
"格大小"基准）。三种单元面积相等：

| 密铺 | 面积 | 边长（世界单位） | @blockSize=15（px） | 单元屏幕 AABB |
|---|---|---|---|---|
| 正方形 | s² | s = 1 | 15 | 1×1 |
| 正六边形（尖顶） | (3√3/2)·a² | a = √(2/(3√3)) ≈ 0.62040 | ≈ 9.31 | 宽 √3a≈1.0746、高 2a≈1.2408 |
| 正三角形 | (√3/4)·b² | b = 2·3^(−1/4) ≈ 1.51967 | ≈ 22.80 | 宽 b、高 √3b/2=3^(1/4)≈1.31607 |

边长常数为固定推导值（世界单位），不落 config；`Map` 提供
`worldWidth()/worldHeight()`（世界单位），供相机/环绕/夹取/剔除使用
（`width()/height()` 在非方形下语义改为 列/行数，全代码审计所有"格数当世界尺寸"的使用点）。

#### 2. 坐标系统与世界范围

##### 2.1 六边形（尖顶、even-r 横向行偏移布局）

- 行 r（0 底 → H-1 顶）中心：`x = √3a·(c + (r mod 2)/2)`，`y = a + 1.5a·r`。
- 世界矩形 `[0, N·√3a] × [0, 1.5a·H]`；环绕周期 = (N√3a, 1.5a·H)。
- 边邻（even-r 规则）：偶行 (r,c) → 下 (r+1,c−1),(r+1,c)；奇行 → 下 (r+1,c),(r+1,c+1)；
  上/左/右同理（实现用轴向坐标，见 §3.1，天然无奇偶分支）。
- **水平环绕**：全行同列数 N（奇数行右侧凸出 √3a/2 恰补偶数行左侧凹进 √3a/2，
  与三角形"左边凹右边凸"同构）；**垂直环绕**：H 必须为偶数（行偏移奇偶模式以 2 行为周期
  才闭合）——即"偶数行"要求的由来。菜单 `randH` clamp 到偶数。

##### 2.2 三角形（P12 直边布局：行内正/反交替，所有行同列位、行间无 b/2 平移）

- 行 r（0 底 → H-1 顶），h = √3b/2，p = r mod 2。每行三角 j ∈ [0, 2N)，三角 j 左角
  x = j·b/2，朝向 = (j+r) 偶 → 正（底边在下）、奇 → 反（顶点在下）：
  正格(i)：底左角 x = b·i + p·b/2，底边 y = r·h，区间 `[b·i+p·b/2, b·(i+1)+p·b/2]`；
  反格(i)：顶点 x = b·i + (1-p)·b/2 + b/2（y = r·h），底边 y = (r+1)·h，
  区间 `[b·i+(1-p)·b/2, b·(i+1)+(1-p)·b/2]`；i = 0..N−1。每行 2N 格，总格数 2NH。
  **N = 列对数 = 参数宽/2**（2026-08：width 语义 = 视觉列数，减半后 cellCount =
  width×height 与方形一致，见 P12 完成记录修复轮 7）。
  格心：正 = (b·i + p·b/2 + b/2, r·h + h/3)；反 = (b·i + (1-p)·b/2 + b/2, r·h + 2h/3)。
- 世界矩形 `[0, N·b] × [0, H·h]`；环绕周期 = (N·b, H·h)。
- **左右直边**：所有行左起格左角贴 x=0、右起格尖出 N·b + b/2（环绕无缝）；**顶/底平**：
  顶行反三角底边构成平顶、底行正三角底边构成平底 ✓；**左右互补**：最右反三角右移 −W 后
  与最左正三角共享斜边 ✓（W = N·b 无缝）。
- 边邻（p = r mod 2；三角邻格恒为反向）：正 k0 底 → 反(i, r-1)（同列下邻）；k1 左斜 →
  反(i+p-1, r)；k2 右斜 → 反(i+p, r)。反 k0 顶 → 正(i, r+1)（同列上邻）；k1 右斜 →
  正(i+1-p, r)；k2 左斜 → 正(i-p, r)。
- **垂直环绕亦要求 H 为偶数**：顶行反底边（y = H·h，x 偏移 (1-((H-1)&1))·b/2）环绕到 y=0
  后须与底行正底边（偏移 0）重合 → (H-1) 奇、H 偶。

##### 2.3 环绕与边界

- 位置环绕按**世界周期**归一（`wrapX = x mod worldW` 等），取代现 `MovementSystem`
  的 4 个边界分支（对六/三，"边界"只存在于显示上：灰线画外轮廓；环绕图接缝处画不画灰线
  由渲染自然处理——外轮廓仍是地图矩形显示边界）。
- **先锋连占**在环绕图上不跨接缝（决策 13）：邻格越界 → no-op（与正方形现状一致）。
- **城市形状**不可跨接缝（决策 5）：canPlaceCity 校验形状全部格在世界界内。

#### 3. 城市等级与基建地块形状

##### 3.1 表示：偏移格集合（取代矩形 {w,h}）

`Config::City` 改为**按密铺**的 `levels[]` + `shapes[]`；`City` 存锚点 + 形状下标，
`w/h` 移除。形状 = 相对锚格的偏移集合，**parity-free 坐标系**：

- 六边形：**轴向 (q,r) 相对偏移**（r 向上增；锚 = (0,0)）。邻格偏移集固定：
  {(1,0),(−1,0),(0,1),(0,−1),(1,−1),(−1,1)}——无奇偶分支，放置时经轴向→世界转换。
- 三角形：**锚格（正三角）+ 世界相对中心偏移（Δx,Δy 以 b/h 为单位）+ 朝向**存储
  （行奇偶已在世界坐标中消解，parity-free）；锚 = 形状左下正三角。

#### 4. 城市图标缩放算法（方形回归验证）

- 通用算法：形状 AABB（世界单位 × blockSize × zoom 折算 px）→ `fitW = min(boxW, boxH/A)`
  （A = 塔源纵横比，沿用现状）→ `iconW = fitW × iconScale[level−1]`，`iconH = 宽×A`。
- **正方形回归点**：AABB = 现 w×h 框 ⇒ 算法与现状逐像素一致（iconScale=0.85 全部等级）。
- 六/三角：`render.city.iconScaleHex[9]` / `iconScaleTri[9]`（不存在的等级留占位）；
  各等级数值 = **0.85 × (形状内接框 / AABB)** 预计算入 config（"恰好一点点距离"沿用
  方形观感：图标边与基建最外缘保持 ≈ 框的 7.5%/侧）。内接框 = 以几何中心为中心、能放进
  形状凸包的最大轴对齐矩形；L7 六边形等空角形状由此自动收进（凸包 < AABB 的部分不计）。
- 细线围区（高缩放档）：矩形外廓 → **形状凸包多边形描边**（六/三），颜色/加深逻辑不变。
- `render.capital.*` 同构适配（首都图标按等级表、保底尺寸不变）；首都/候补判定逻辑不动。

#### 5. 移动 / 战斗 / 特效泛化（风险核心）

1. **`findNextXY` 泛化**：方形"撞轴对齐格线"→"沿方向与当前格全部边（六 6 / 三 3）求交，
   先撞者即穿越"，返回"穿过的边"；移动/激光据此取 `worldToCell(pos + eps·dir)` 进邻格。
   **RNG 纪律：穿越判定 0 次 RNG**；顶点撞点（六 3 格共点、三 6 格共点）用**确定性平局规则**
   （按固定边序取首个，不掷骰）。方形路径保留原 `-2/-3` 语义不动（黄金/基线零回归）。
2. **`MovementSystem::moveArmy`**：边界分支（4 个 bounce/wrap）→ 按**世界周期**环绕
   （wrap 开）或反弹（关）；格归属/下海/山地/征服判定改 `worldToCell`；夹取改世界范围。
3. **先锋连占**（决策 13）：`conquerCell` 改为"目标格全部边邻格"，固定顺序
   （六：6 邻轴向序；三：3 邻；方：现上/下/左/右不变）——势力8 免费兵 RNG 顺序跨密铺确定。
4. **激光 `solveLaser`**：与移动共用穿越循环（现复制 findNextXY 分支，一并泛化）；
   "进入非己方陆地停止 + 尖端格征服"语义保留。
5. **爆炸 `solveBomb`**：`(i+0.5, j+0.5)` 格心距 → `worldToCell` 包围盒 + 格心距离；
   **迭代顺序固定**（保 RNG 确定性）。
6. **`SpatialHash`**：桶下标 = `worldToCell`；`build` 参数改世界范围；query 半径本就是
   世界单位，几何无关。
7. **首都放置**：随机格采样改"均匀随机格"（一次 `rng.get(总格数−1)` + 反解索引，或保留
   两次调用语义但坐标映射自洽——实现时定稿）；首都间距用**格心世界距离**。
8. **速度**：不变（决策 10）；平均弦长差（方 0.785 / 六 0.844 / 三 0.689，±10%）记录在案。

### P13 — 城市系统重做（多格基建地块 + 等级 + 幂律分布）

**目标**：城市从单格绑定改为**多格基建地块**绑定；n 级城市（正方形格网上仅 1/2/4/6/9 级）按
固定形状铺在 n 个基建格上，等级大致服从幂律分布；整块基建同时被同一方占领才易主；渲染分
缩放档（放大细线围区 / 缩小图标不继续缩小）。为 P14 经济（`level^alpha`）与 P15 首都（等级
缩放/细线）提供地基（思路 9.1）。

**前置**：P5（地形基图/可产城格 `cityAllowed`）、P6（随机图/城概率骰）。

> **本计划定的决策**：
> - 等级形状**固定朝向**（思路 9.1 表格 列×行，不旋转，锚点 = 形状左上格）→ 无额外 RNG。
> - 基建格须 `land`（山地可，spec："无所谓是山地还是平原"）；**锚点格**（成城格）须
>   `cityAllowed`（基图允许该格成城，与 P5"首都只落在可产城格"同语义）；形状扩展格不要求
>   `cityAllowed`（可能是基图"必然无城"格，属预期）。
> - 城市密度与是否沿海/山上无关（per-cell 城概率只发生在锚点候选格，形状只需陆地）。

**详细任务**：

1. **城市数据模型**（核心重构）：
   ```cpp
   // Faction::City 从单格 {x,y,lastProduceArmyN} 改为（形状固定 → 基建格集合可由锚点+形状导出）：
   struct City {
       int id = -1;                // 全局城市 id（Map 注册表下标）
       int ownerId = 0;            // 归属势力 id
       int level = 1;              // 1/2/4/6/9
       int baseX = 0, baseY = 0;   // 锚点（形状左上格，世界坐标）
       int w = 1, h = 1;           // 形状 列×行（由 level 查 config.shapes 推导）
       int lastProduceArmyN = 0;   // 产兵计数（保留现有语义）
       std::uint64_t lastCapturedTick = 0;  // 最近一次整城易主/建立 tick（P15 首都"最久未被攻破"
                                            // 用；也供 P8 经济建设科技计时）
   };
   ```
   - 全局城市注册表：`Map` 持有 `std::vector<City> cities_`；`MapCell.city`（bool）**改为**
     `int cityId = -1`（-1 = 非城市格；**快照 v4 序列化**）。`if (cell.city)` 读取点全量迁移
     为 `if (cell.cityId >= 0)`（`grep` 复核无残留）。
   - 基建格集合 = `(baseX, baseY, w, h)` 隐式导出（`for dy in [0,h) for dx in [0,w)`），
     **不存格列表**——降低快照体积与一致性维护成本。
   - `Faction.cities` 改为 `std::vector<int> cityIds`（注册表是唯一权威数据，避免结构分叉）；
     `cityCount = cityIds.size()`。城市中心/产兵锚点 = `(baseX + w/2.0, baseY + h/2.0)`。
2. **等级形状表**（config 新增 `city` 段）：
   ```jsonc
   "city": {
     "levelIncomeExponent": 1.0,   // alpha：n 级城收入 = n^alpha × 1 级城（>=1，数值待实验，P14 读取）
     "levelRankExponent": 0.5,     // beta：幂律 P(L>=n) ∝ n^{-(alpha+beta)}（>0，思路默认 0.5）
     "shapes": [                    // 正方形格网暂时仅此 5 级（思路 9.1 表格：列数*行数）
       { "level": 1, "w": 1, "h": 1 },
       { "level": 2, "w": 2, "h": 1 },
       { "level": 4, "w": 2, "h": 2 },
       { "level": 6, "w": 3, "h": 2 },
       { "level": 9, "w": 3, "h": 3 }
     ]
   }
   ```
3. **等级采样（幂律）+ 形状放置**（`Map::loadFromBmp`，走 `mapRng_` 地图种子）：
   - 迭代次序不变（y 先行后列）。每格：
     - `cityId != -1`（已被既有形状占用）→ **跳过**（不再掷城概率，RNG 位置保持确定性）。
     - 陆格掷城概率（现 `rampProb(G)`）通过 → **先采样等级、再尝试放置**：
       ```
       s = alpha + beta（config）
       P(L=1)=1-2^{-s}; P(L=2)=2^{-s}-4^{-s}; P(L=4)=4^{-s}-6^{-s};
       P(L=6)=6^{-s}-9^{-s}; P(L=9)=9^{-s}
       u = rng.unit()；按累计概率确定 level（1 次 RNG）
       ```
     - 放置检查（锚点 = 当前格）：形状全格在界内 ∧ `land` ∧ 锚点格 `cityAllowed` ∧ 形状格全部
       `cityId==-1` → 放置成功：注册 `City{id 递增, level, baseX, baseY, ...}`、形状格置
       `cityId = 该 id`、`lastCapturedTick = 0`。
     - 放置失败（越界/重叠/锚点不可成城）→ **回退 1 级**：锚点格单独可放则建 1 级城；仍不可
       → 本格不成城。
   - `placeCapitals`（首都放置）改为在锚点格注册 1 级 `City` 实体（`cityId` 关联）；initFactions
     征服首都即成为己方 1 级城——首都语义在 P15 才生效，本阶段首都 = 普通 1 级城。
   - **确定性**：全部经 `mapRng_`；城市布局由 `(mapSeed, config)` 唯一决定（与主种子无关）。
   - `Map::finalize` 重写：`totalCities` = 城市注册表数量（**城市实体数**，非格子数）。过渡期
     旧经济公式的 `cityRatio = cityCount/totalCities` 语义随之变为"城市数比"（P14 整体替换）。
4. **城市易主重构**（`Faction::conquer` / `MovementSystem` 征服调用点）：
   - 攻占基建格：土地 `belongi` 正常变更；若该格 `cityId != -1` → 城市易主检测——检查该城市
     **全部基建格 `belongi` 是否均为征服方**：
       - 是 → 整城易主：`City.ownerId` 更新、旧 owner 移除城市（`removeCity(id)`）、新 owner
         添加、`lastCapturedTick = now`，触发势力8 免费产兵**一次**（非每格）。
       - 否 → 城市**不转移**（部分占领只改土地归属；第三方占其中一格也不满足"全部=同一方"，
         spec："全部基建地块同时被另一方占领时城市才易主"）。
   - **P15 挂点**：整城易主时若该城是某势力正式首都 → 触发首都沦陷逻辑（P15 在此挂事件）。
   - 玩家产兵城（`PlayerIntent.selectedCity`）已按坐标解析（P2），多格城市取城市中心判定；
     `cityIndex` 语义改为 `cityIds[]` 下标，越界/易主每帧校验（沿用 P2 防御）。
5. **城市渲染**（新 `render/CityRenderer`，改造 `MapRenderer` 城市绘制）：
   - 基建格：画陆地势力色；山地基建格**山贴图在下、城市贴图在上**（沿用 P5 绘制顺序）。
   - **高缩放**（屏上格大小 > `render.city.lineMinCellPx`）：每城市画**细线围基建地块区域**
     （基建格外廓多边形）。**低缩放**：不画细线，城市图标**不随缩放继续缩小**
     （`render.city.minIconSizePx`），无视重叠直接绘制。
   - 图标：1/2/4/6/9 五个**互不相同**图标（新贴图 `data/city_l<n>.png`，用户提供或程序化生成，
     读入规格待定）；贴图**左右对称、对称轴在图片中央**（规格要求）；按等级画对应图标于城市
     中心，缩放随等级（`render.city.iconScale[level]`）。
   - ~~每城市 y 渲染偏移 `City.renderOffsetY`（或由 id hash 派生），render config 外置。~~
     （2026-08-07 移除：图标中心 = 基建地块几何中心，见 P13 完成记录"后续修订"）
   - 渲染常数全外置 `render.city` 段（`lineMinCellPx/minIconSizePx/iconScale[]/lineThickness`）。

**设计模型（关键）**：把当前 `data/army_base.png`（32×352，11 行兵表，源列红）**直接当作
双色系统下"红势力（主红 255,0,0 / 副浅灰 191,191,191）的成品渲染效果**——即反解目标。
对每个像素反解出 主色比例、副色比例、黑白比例、色相偏移，形成**模板**；渲染其他势力时把
该势力的主副色代入模板重合成。这样不需要"中央/边缘区"的几何分割，且：

- **红势力还原**：`合成(反解(p), 红, 浅灰) ≡ p`（逐像素，±1~2/通道）；
- **兼容旧观感**：副色=浅灰191 时，新合成 ≡ 旧 HueRotate（数学等价，见下）→ 默认调色板下
  兵种观感与现状逐像素一致（唯一例外：签名兵种不再用特殊版彩图，统一走基础版双色——用户指定）；
- **特效行（6/7/8）自动兼容**：激光白芯（白=灰）天然保留、有色像素的色相偏移照旧平移。

**数学规格**（`render/TintMath.h` 纯函数，可单测）：

1. **反解** `decomposeTwoTonePixel(r,g,b,a) → {v, m, Δ, a}`：
   - `v = max(r,g,b)`；`m = min(r,g,b)`（模板 G 通道 = min，避免存饱和度再换算的取整损失）；
   - `Δ = hue(r,g,b)`（灰像素 max==min → Δ=0），量化 0..255 ↔ 0..360°；
   - 意义：红族像素 (v,m,m) 可拆为 主色比例 `rFrac = v−m`（0..255）+ 灰度 `g = m`（0..255）；
     灰度再对基准灰 191 拆 副色/白/黑 比例（见 2）。
2. **合成** `compositeTwoTone(t, Pc, Sc, refGray=191) → rgba`：
   - `base = (rFrac/255)·Pc + grayPart`；其中
     `g ≥ 191`：`grayPart = ((255−g)/64)·Sc + ((g−191)/64)·白`；
     `g < 191`：`grayPart = (g/191)·Sc`（黑比例 = 1−g/191 隐式，贡献 0）；
   - `final = hueRotatePixel(base, Δ)`；`α` 原样保留。
   - 逐通道不会溢出（红族下 base 恰为 (v,m,m)，其它势力各通道 ≤ 对应原通道 ≤ 255）。
   - **等价性**：`Pc.max 通道 = 255` 且 `Sc = (191,191,191)` 时，逐像素
     `compositeTwoTone(decompose(p), Pc, 灰191) ≡ hueRotatePixel(p, hue(Pc)−hue(红))`
     ——新管线是旧色相旋转管线的严格推广（单测锁定）。

F5 则连带重建）→ 肉眼观察 地块格/城市图标/兵种/中立占位 配色是否美观。代码不做自动评判。

**验收标准**：
1. 默认配色（副色全 191）下，兵种观感与现状逐像素一致（除签名兵种停用特殊版）；
   红势力合成还原源图（单测 ±2/通道）。
2. 地块格 = 主:副:白、城市图标 = 主:副:黑（比例默认 0.35:0.35:0.30 / 0.60:0.20:0.20，config 可调）；
   中立灰 = 深灰+浅灰（id0 color 96 + secondary 191）。
3. F7 重烘焙不重建模拟；F5 连带重烘焙。
4. `userdata/two_tone_template.png` 可检查反解。
5. config 结构变化 → 基线 `state_hash` 更新为 `0xbd90b94d52be9413`（land=3139 army=276 与
   上一基线相同——纯 config 序列化变化，sim 行为未变）。
6. 单测：`test_config.cpp`（secondary/比例解析 + `factionTileColor/factionCityColor` 公式 +
   数据文件断言）、`test_tint.cpp` 追加 双色反解还原 + 与 HueRotate 等价性 + 灰→副色 + Δ 保留。

## 3. 横切关注点（所有阶段都遵守）

1. **确定性**：
   - 确定性键升级为 `(seed, config, map, options)`；新系统一律用注入 `Rng`。
   - **行为保持阶段**（P1/P5/P7/P9 任务 0/P10 关闭态）：跑基线断言 `state_hash` 不变
     （当前 `0x2ed42e7153d7e990`）。
   - **新增功能阶段**（P6/P8/P9 新兵种/P11/P12/P13/P14/P15）：完成后重跑基线并**记录新 hash**
     到本文档。P13 起地图加载新增"等级采样 + 形状放置"RNG 消耗（走 `mapRng_` 地图种子）——
     城市布局的确定性键为 `(mapSeed, config)`，主种子不再影响地图上的城市布局。

3. **config 外置**：新参数进 `config.json`，同步更新 `.docs/配置说明.md`；`toJson/loadFromJson`
   键严格对称（快照往返依赖）。
4. **文档**：交互/渲染/架构改动同步更新 `README.md`、`.docs/交互系统.md`、`.docs/翻新计划.md`；
   本计划新增阶段完成时在对应小节回填"已完成"记录（沿用翻新计划体例）。
5. **存档兼容**：`Snapshot` 新增字段（`MapCell.mountain`、`MountainState`、`Behavior`、
   `Projectile`、`Buff`、`techPoints`、`Statistics`、`Creator.unitType`）用 `value(key, default)`
   向前兼容；新组件按 entt `storage.reach()` 顺序序列化；**不序列化** `PlayerIntent`/事件。
   **P13–P15 额外**：`MapCell.city` 改为 `MapCell.cityId`（int，-1 = 非城市格），新增
   `City{id,ownerId,level,baseX,baseY,w,h,lastProduceArmyN,lastCapturedTick}` 注册表与

   统计/灭亡计数在兵量大时改增量维护。

   P4/P8/P11 复用；P7→P8 连续做；P9 与 P11 有 credit 依赖按序做；P12 最后且可与 P6-P8 并行
   （互不依赖，仅与 P10 有边界依赖）。经济重构章 **P13→P14→P15** 依思路 9 排在 P12 之前，
   可与 P8（科技）并行设计——P14 为其预留经济类科技 hook（经济振兴/经济建设/扫荡）。
