# 配置说明（`new_project_landwar/data/`）

> `Config::loadFromFile` 读取 `data/config.jsonc` 后，会按同目录合并 `render.jsonc`、`techs.jsonc`、
> `factions.jsonc`、`units.jsonc`；其中 `techs`/`factions`/`units` 为 **CSV+JSONC 混合**：
> 必填且内容单一的列在 `techs.csv`/`factions.csv`/`units.csv`，同名 `.jsonc` 只保留独有/可选字段。
> 本文件说明合并后的全部配置键。配置文件使用 JSONC，支持 `//` 与 `/* */` 注释；
> 行为规格见 `.docs/old/2026_0731_翻新计划.md`，数值以 `data/` 下配置文件现值与代码为准。
> 表中「默认」列为 `data/` 随包现值；`data/` 未覆盖的键取 `src/core/Config.h` 内置默认。
> 运行时可改：支持 `F5` 热加载（**重建模拟、同种子重启，破坏当前局面**）。
> 缺键回退默认值（设计）；未知键告警；A 的类型/范围错误时回退 `default/config.jsonc`，B 也不可用时才回退
> `src/core/Config.h` 中的内置默认值，保证无配置文件也能运行。

顶层 `_comment` 仅供人读；势力 `name` 会进入运行时定义，用于菜单、排行榜和事件消息。

> 键名校验规则（未知键告警、`_` 前缀豁免、新增/删除键的同步义务）见 `.docs/工程规范.md` §4。
> 配置文件约定：`config.jsonc` 保留核心/模拟段；`render.jsonc` 使用带段名的根对象
> （如 `{ "render": { ... } }`）；`techs.jsonc`/`factions.jsonc`/`units.jsonc` 是稀疏覆盖层，
> 与同目录同名 `.csv` 按连接键（`techs.id`/`factions.id`/`units.type`）合并。A 缺失或损坏时回退到
> `default/config.jsonc`；分片 `.jsonc` 缺失时尝试 `default/` 中对应副本（CSV 侧车与同目录 `.jsonc`
> 成对使用，不跨目录回退）。
> 对应 Schema 全部位于 `data/schema/`；发行版回退副本全部位于 `data/default/`，不在 `data/` 根目录重复维护。

## CSV 侧车（`units.csv` / `factions.csv` / `techs.csv`）

> 三个"记录表"分片把**几乎必填且内容单一**的列外置为 CSV 主表，`.jsonc` 只写各记录的
> 独有/可选字段；两者按连接键叠加，得到合并结果。
> 即使某个 `.jsonc` 被搬空（只剩注释），文件仍然保留——它的存在是"这段由 CSV 供数"的标记。

| 分片 | 连接键 | CSV 列（`data/<分片>.csv`） | `.jsonc` 保留内容 |
|---|---|---|---|
| `units` | `type` | `type,cost,speedMult,sizeMult,bounceMult,visualRadius` | `mountainEnterMult`、`mountainNoSlow`、`deathEffect`、`periodic`、`periodTicks`、`bullet*` 等独有/可选字段 |
| `factions` | `id` | `id,name,description,nameColors,colorR,colorG,colorB,secondaryR,secondaryG,secondaryB` | `unitPreference`、`buffs` |
| `tech` | `id` | `id,name,desc`（文件 `techs.csv`） | 全局标量（`thresholdBase` 等）与每个科技的 `levels`、`preferenceUnits` |

**CSV 格式（实现见 `src/core/Config.cpp` 的 `parseCsv`）：**

- UTF-8 BOM 自动跳过；空行与**整行**以 `#` 开头的注释跳过（行首允许空白）——`#` 只作整行注释，
  不是行内注释。
- 第一条非注释行为表头；列名去首尾空白，末尾空列（多写的逗号）忽略。
- 字段可用双引号包裹以承载逗号/换行/双引号（`""` 转义）；未加引号时去首尾空白。
- 列数与表头不符的行丢弃并告警；数字/颜色单元格非法时该键退回 `.jsonc`/内置默认并告警。
- **空单元格 = 该键缺省**（退回 `.jsonc` 或内置默认），便于将来按需增补列。
- 多值列：`nameColors` 用 `|` 分隔（如 `primary|secondary`）；颜色拆成 `colorR/colorG/colorB`、
  `secondaryR/secondaryG/secondaryB`（0..255 整数），解析为原来的 `[r,g,b]` 数组。
- 顺序与新增：CSV 决定记录顺序；`.jsonc` 中按连接键匹配的记录覆盖/补充 CSV 字段，未匹配的记录
  追加到末尾并告警。`.jsonc` 同名字段优先，便于临时手改。
- 缺失行为：`.jsonc` 文件缺失时按既有规则尝试 `default/` 副本；`.jsonc` 存在但为空对象（`{ }`，
  即"被搬空"）时该段仅由 CSV 供数；CSV 缺失时该段仅由 `.jsonc` 供数。
  `Config::validateFile`（`--validate-config`）在分片存在时要求同目录 CSV 必须存在。


## 长度单位约定

项目统一使用连续世界单位 `U`：正方形地图的单格边长为 `1 U`，其他密铺通过几何缩放使平均单格面积与正方形相同。因此非方形密铺的单格边长不一定是 `1 U`。世界面积使用 `U²`。

渲染换算为：`1 U = blockSize × zoom` 个逻辑屏幕像素；当前 `blockSize=15`。真实窗口像素还会经过 SDL 的逻辑画布缩放。配置中写“格数”时，表示离散格数量；写“世界单位 U”时，表示连续几何长度，二者只在正方形中可直接按 1:1 看待。

城市等级始终表示基建区域面积（`U²`）。正方形、六边形、三角形和 Laves 当前每格面积为 `1 U²`，所以等级数值恰好等于离散格数；半正密铺的单格面积不同，等级数值通常不等于格数。

## allyGate — 盟友边界闸门

> 规格见 `.docs/兵运动与盟友系统开发文档.md` §12，算法出处 `.docs/包围检测.md`。
> 每兵一个 CUSUM 统计量 `S`（`comp::AllyGate.cusum`）：
> `S ← max(0, S − (leakPerCell + tolerancePerCell) × 本 tick 步长) + 本 tick 盟友边界反弹数`。
> 泄漏项乘**步长**（= 该兵速度）→ 判据按"每格尝试次数"计，与兵速无关；`S ≥ alarmThreshold`
> 时下一次穿越盟友边界**放行一次**（不反弹、不征服）并清零 `S`。无联盟时无观测，永不触发。

| 键 | 含义 | 默认 |
|---|---|---|
| `leakPerCell` | c：参考泄漏率（次/格）。边界尝试率低于此值的兵视为"路过"，边界近似绝对硬，必须 ≥ 0 | 0.03 |
| `tolerancePerCell` | η：容忍裕度（次/格），与 c 同量纲；判据有效泄漏率为 `c+η`，必须 ≥ 0 | 0.003 |
| `alarmThreshold` | h：报警阈值（证据量）；`S ≥ h` → 下一次穿越盟友边界放行一次，必须 > 0。**判据松紧主旋钮**：误放行概率 ≈ `(r/(c+η))^h`（几何下降）、放行延迟 ≈ `h/(r−c−η)`（线性上升）。默认 5（40 格封闭地块约 4.4 s 放行）；想更精确调 6/8（约 5.3/6.5 s），想更快调 4/3/2（约 3.4/2.6/2.5 s） | 5.0 |

## terrain — 地形基图

**基图编码（24bit BMP，画图软件可直接编辑，每像素 BGR）：**
- **海/陆 确定性**：任一分量 `r/g/b < seaChannelMin` → **海**；否则 → **陆**（不掷骰）。
- **山概率 = R 通道**、**城概率 = G 通道**、**B 闲置**（仍参与海陆判定：b<32 → 海）。
- 每陆格独立掷骰：先 `rng.chance(ramp(G))` 定城、后 `rng.chance(ramp(R))` 定山；海格不掷骰。
  山与城可同格共存；山=陆地子集（`land=true 且 mountain=true`），可被占领、山格可放城。

| 键 | 含义 | 默认 |
|---|---|---|
| `seaChannelMin` | 任一分量 < 该值 → 海（确定性） | 32 |
| `probFloor` | 概率分量 < 该值 → 概率 0 | 128 |
| `probScale` | ramp = (分量-128)/127（255 → 1.0） | 127 |
| `mountainEnterChance` | 山地进入基础概率（× 兵种 `mountainEnterMult`；失败反弹） | 0.5 |
| `mountainSpeedMult` | 山地内速度乘数（进入 ×、离开 /，互逆；开拓不减速） | 0.5 |

> **山地移动规则**：兵运动时下一格若为山（**不管当前格是什么**，
> 含陆→山/海→山/山→山）都掷「进入/反弹」；进入概率 = `mountainEnterChance × 兵种
> `mountainEnterMult`（普通/先锋 0.5、开拓 min(1, 0.5×2)=1.0）。进山后山地内速度 ×mountainSpeedMult
> （开拓 `mountainNoSlow=true` 不减速）。若下一格**既为敌方领土又为山地**，山地阻挡与敌方
> 阻挡**独立计算**（两骰独立）：非先锋 `bounceMult=1.0` 必然反弹；先锋 0.6 两骰都过才不反弹。
> 山→海先复原山地速度再下海；海→山先掷山地骰、通过才登陆进山。

> **调色板指南（画图软件编辑）**：
>
> | 画 | 颜色 | 含义 |
> |---|---|---|
> | 海 | 任一分量 <32（如纯黑 `(0,0,0)`、纯蓝 `(0,0,255)`） | 确定性海 |
> | 普通陆 | 全分量 ≥32 且 r,g<128（如灰 `(128,128,128)`） | 无山无城 |
> | 山 | r∈[128,255] 且 g<128（如 `(255,64,64)`） | 越红越可能成山 |
> | 城 | g∈[128,255] 且 r<128（如 `(64,255,64)`） | 越绿越可能成城 |
> | 山+城 | r,g≥128（如 `(255,255,64)`） | 两骰独立，可共存 |
> | B | 闲置，但须 ≥32 才判陆 | 未来扩展 |
>
> 邻海修正保留：山格 8 邻域（含对角）有海 → 置普通陆（`src/world/Map.cpp`）。
>
> **首都规则**：8 个首都只落在"可产城"格（源 g>128，基图允许成城）——
> 基图"必然无城"的格子不会被首都强行塞进城市；若地图可产城格不足/太挤则回退任意陆地（保证可玩）。

## economy — 经济与产兵

**朴素逐 tick 收入模型**（`EconomySystem::accumulate`）：
```
landIncome    = perLandIncome × landCount                    // 普通领地（含城市基建格，归该格 belongi 势力）
cityIncome    = perLandIncome × cityBaseMult × Σ level^alpha // 每城（**含正式首都**）；alpha = city.levelIncomeExponent
capitalIncome = capitalBase（正式首都）                       // 直接加一个数值（flat 加成）
income        = mods.economyGainMult × (landIncome + cityIncome + capitalIncome)
faction.economy += income
```
- **城市基建格双计**（spec 语义）：既是普通领地（产 `landIncome`，归该格 `belongi` 势力）又属
  城市（产 `cityIncome`，归城市 owner）——两笔按各自归属进账，勿去重。
- 灭亡势力（`alive=false`）跳过全部收入（含 land + city）。
- 具体数值全部走 config（调参只动 config、不动代码），下表默认以 config.json 现值为准。

| 键 | 含义 | 默认（占位） |
|---|---|---|
| `initialEconomy` | 初始库存（产兵启动资金） | 1.1 |
| `perLandIncome` | 普通领地每 tick 收益 | 0.00007 |
| `cityBaseMult` | 1 级城收入 = 该值 × 普通领地 | 20.0 |
| `capitalBase` | 正式首都收入**直接加值**（`capitalIncome = capitalBase`，flat 加成；首都的 level^alpha 收入已计入 cityIncome，勿重复计率） | 0.2 |

## city — 城市系统（多格基建地块 + 等级 + 幂律分布）

> 城市绑定多个**基建地块**（固定形状）。城市等级统一等于基建区域面积（U²）；在单格面积为
> `1 U²` 的密铺上，等级数值才恰好等于离散格数。**全部密铺形状表外置到 `data/city_shapes.jsonc`**，
> `config.jsonc` 不内联 `city.shapes/hex/tri`。文件内每个密铺为
> `{levels, shapes:[{level, cells:[[dx,dy],…]}]}`，`cells` 统一为相对锚格中心的**世界单位 U 偏移**
> （square 整数格偏移、hex/tri 已由轴向/三角坐标换算成世界坐标）。
> 三角不同朝向由形状表显式定义，并通过 anchorBases 限制基础格；运行时不自动镜像。
> 锚点格须 `cityAllowed`（基图允许成城）；扩展格仅须陆地（可含山）。形状**不可跨环绕接缝**。
> 等级分布服从幂律 `P(L>=n) ∝ n^{-(alpha+beta)}`（等级集按密铺）。
> 城市经济收入 = n^alpha × 1 级城。

| 键 | 含义 | 默认 |
|---|---|---|
| `levelIncomeExponent` | alpha：n 级城收入 = n^alpha × 1 级城（>=1，数值待实验） | 1.3 |
| `levelRankExponent` | gamma：等级幂律指数增量（采样总指数 s=alpha+gamma；采样公式 P(x) ∝ n_x·(x+β)^{-s}，β=(1-minLevel)/2，S 为形状表展开的可重等级集） | 0.3 |
| `shapes` / `hex` / `tri` | 形状表已外置到 `data/city_shapes.jsonc`，`config.jsonc` 不内联该段 | — |

## tech — 科技系统（思路"科技细节"节为准）

> 科技点 = **城市产出**：每逻辑 tick 每座 `n` 级城产 `n × pointsPerCityLevel × mods.techGainMult` 点
> （`techGainMult` 由"观星台"科技提升）。**阈值门槛**：`points ≥ threshold` → 获得一次科研机会、
> 科技点清空、`threshold += thresholdStep`。
> - **AI 势力**（`aiId≠1`）：到阈值立即随机选一个可升级科技（`rng`，确定性）。
> - **玩家势力**（`aiId==1`）：采样 `playerCandidateCount` 个候选（`rng` 不放回，确定性）→ 游戏
>   暂停 → 三选一（升级项旧值黄、新值绿，格式 `desc 新值（旧 旧值）`）→ 可跳过（跳过也消耗本次
>   科研机会——清空已积攒科技点；**但阈值/等级不变**）。
>   玩家结算经 `Simulation::choosePlayerTech`。
> - 科技 = 追加 `source="tech:<id>"` 的 buff；升级 = 用该级**累计效果**替换旧 buff。
> - **叠加规则**（思路"科技细节"）：数值**增加默认加算**、数值**减小默认乘算**、条数加和（见
>   `sim/Buff.cpp computeMods`）。
> - 科技状态（`tech.levels`/points/threshold/candidates/pending）随快照序列化；
>   buffs 仍不入快照，读档从定义 + 科技等级重建。

## 双色势力渲染系统 — 数据源并入 config.json

> 主副色与混合比例全部来自 `data/config.jsonc` 及其配置分片，渲染色唯一数据源：
> - **主色** = `factions[i].color`；**副色** = `factions[i].secondary`
>   （默认浅灰 `(191,191,191)`；**中立灰占位 id 0 = 深灰 `(96,96,96)` + 浅灰**，
>   factions 数组含 id 0 项）；
> - **地块格填色** = 主:副:白 加权平均（`render.tile`，默认 0.5:0.3:0.2，主副接近）；
>   arch/laves 密铺再按格类型（arch：边数升序）/朝向（laves：朝向角排序、以朝向种类数
>   最小质因子循环）分档，用 `render.tile.variation`（半宽，默认 0.05）让各档在
>   `[(P-variation,S+variation,W) → (P+variation,S-variation,W)]` 区间取不同色（档数 2 → 两端、
>   3 → 左中右；**三角** 正/反两朝向同 laves 分两档；方/六与单色情形不分档）；
> - **城市图标填色** = 主:副:黑 加权平均（`render.city.mix`，默认 0.7:0.1:0.2，主显著高）。
> 兵种贴图（army_base.png）按"红势力成品渲染"逐像素反解 主/副/黑白比例+色相偏移 模板，
> 按各势力 (主色,副色) 软件合成（`render/TwoToneTintCache`）。
> **调试工作流**：改 `config.jsonc` 里上述键 → 游戏内按 **F7** 重烘焙渲染色（不重建模拟；
> F5 连带重建）→ 肉眼评美；代码不做自动评判。反解模板导出 `userdata/two_tone_template.png`
> （R=v、G=min、B=色相偏移、A=α）可肉眼检查。
> 键名校验同 config 纪律（未知键 `_` 前缀豁免、其余 warn；`Config.cpp validateConfigKeys`）。
