# GitHub 发布前改进建议

## 必做

- 增加许可证文件，明确代码、图片、地图和第三方依赖的授权边界。
- 增加 GitHub Actions：至少执行 Windows/MSYS2 或 Linux 构建、单元测试和 `--headless` 烟测。
- 锁定或记录 ImGui、EnTT、SDL2、spdlog、nlohmann-json 的版本；当前 ImGui 使用本地未锁版本目录，复现构建风险较高。
- 将发布目录制作改成可复用脚本，并在干净目录验证 DLL、`data/` 资源、`userdata/` 可写和启动路径。
- 在 README 增加贡献方式、问题反馈模板、已知限制和配置扩展示例，尤其说明势力 ID 必须连续、最多 63 个可玩势力。
- 明确图片、地图、字体和第三方库的版权来源，避免把无法再分发的素材推到公开仓库。

## 建议完善

- 增加配置 schema 或独立 `--validate-config` 命令，将当前依赖日志的错误反馈变成可自动化检查。
- 为动态势力增加专门测试：追加势力、菜单/选项往返、首都数量、爆炸半径特性、免费产兵、渲染调色板和快照往返。
- 为快照增加明确的版本迁移策略。当前快照校验严格匹配版本，配置势力数量变化后旧快照不一定适合继续使用。
- 把固定容量 `kMaxFactionCount=64`、统计数组和基础格位掩码上限集中写入开发文档，并在配置校验失败时给出明确原因。
- 在 CI 中执行格式检查和编译警告检查；当前项目要求 `-Wall -Wextra`，但没有自动化门禁。
- 添加最小可运行资源包或测试资源，减少新贡献者必须依赖本机 MSYS2 路径和完整美术资源的问题。

## 发布前检查清单

- 干净环境构建成功。
- 全量测试通过；若有已知基线漂移，已更新测试和变更记录。
- `--headless --seed 42 --ticks 1000 --summary` 退出码为 0。
- 窗口启动、主菜单选择势力、加入测试势力、开始游戏和截图流程可用。
- 删除或忽略 `build-*`、`userdata/`、临时地图和本机配置后，仓库仍可从零构建。
- 发布包不包含密钥、本机路径、不可再分发的依赖或未授权素材。
