# 配置扩展待修复

## 检查结论（已完成）

配置系统现在支持通过 `data/config.jsonc` 及其配置片段追加连续势力定义，并由主菜单动态选择是否加入游戏。新的特性字段仍需注册到 C++，但已注册的通用势力特性不再绑定固定势力 ID。

实际势力配置文件名为 `data/factions.jsonc`（复数）。启动时 `Config::loadFromFile()` 读取 `config.jsonc`，再用同目录的 `factions.jsonc` 覆盖顶层 `factions` 段。运行中按 F5 可重载配置。

## 当前可以直接生效的修改

在已有势力对象中修改以下已支持字段，重启或 F5 重载后可以生效：

- `color`
- `secondary`
- `unitPreference`
- `speedMultAll`
- `seaMult`
- `bounceMultAll`
- `pioneerSpeedMult`
- `extraLaserBeams`
- `laserDurationMult`
- `laserLengthMult`
- `bombRadiusBonus`
- `mineTriggerBombRadiusBonus`
- `freeArmyChance`

例如：

```json
{
  "id": 3,
  "speedMultAll": 1.8,
  "seaMult": 0.5,
  "unitPreference": {
    "vanguard": 4.0
  }
}
```

配置解析入口：`src/core/Config.cpp` 的 `Config::loadFromJson()`。

## 当前不能只改 JSON 实现的内容

### 增加新的特性字段

类似下面的字段不会自动注册为游戏行为：

```json
{
  "id": 3,
  "teleport": true,
  "damageMult": 2.0
}
```

当前程序会将未知字段记录为 warning，然后忽略。要使新字段生效，需要同时完成：

1. 在 `Config::Faction` 中增加字段。
2. 在 `Config::loadFromJson()` 中解析字段。
3. 在 `Config::validate()` 中增加数值范围或跨字段校验。
4. 在 `Config::toJson()` 中增加序列化支持（如需要存档或配置往返）。
5. 在对应模拟系统、渲染系统或 UI 中读取并执行该字段。
6. 增加配置解析、行为和存档兼容性测试。

### 增加新的势力（现已支持）

运行时势力数量来自配置：

- 约定势力 ID 连续为 `0..N`，0 是中立，N ≤ 63。
- `kFactionTotal`/`kPlayerFactionCount` 仅保留旧默认值，不再作为游戏循环上界。

`factions.json` 追加 `id: 9` 等连续对象后会被加载，菜单的“添加势力”弹窗会提供对应条目；确定后该势力按加入顺序追加到本局列表。运行时数量已同步覆盖：

- 统计数组保留 `kMaxFactionCount=64` 的安全上限，渲染颜色缓存改为运行时长度。
- 选项中的有序已选势力列表。
- 动态首都数量和回合顺序。
- UI、渲染和模拟循环的运行时势力范围。
- 存档校验中的动态势力数量、回合顺序和势力 ID 范围。

以后新增势力只需追加连续 ID 并填写已支持字段；若新增特性类型，仍需按下文同步代码和测试。

### 修改势力名称（现已支持）

`factions.json` 中的 `name` 会改变菜单、排行榜、科技/首都/灭亡消息等显示文本。

### 势力特性

已处理的固定 ID 特性：

- `bombRadiusBonus` 按当前势力定义读取。
- `mineTriggerBombRadiusBonus` 按当前势力定义读取。
- `freeArmyChance` 大于 0 的任意势力都可触发免费产兵。

例如把 `bombRadiusBonus` 写入任意新势力，该势力的爆炸半径会按定义生效。

## 后续修复方向

1. 新增特性仍需同步结构、解析、校验、序列化、执行系统和测试。
2. 若未来需要超过 63 个可玩势力，需重新评估位掩码/统计数组上限。
3. 为新增字段、未知字段、特性行为、势力数量和存档兼容性补充测试。
