# 配置扩展待修复

## 检查结论

当前配置系统支持通过 `data/config.json` 及其配置片段修改已经由 C++ 定义的配置项，但不支持在 JSON 中任意增加新的势力特性类型，也不支持只通过追加 JSON 对象增加新势力。

实际势力配置文件名为 `data/factions.json`（复数）。启动时 `Config::loadFromFile()` 读取 `config.json`，再用同目录的 `factions.json` 覆盖顶层 `factions` 段。运行中按 F5 可重载配置。

## 当前可以直接生效的修改

在已有势力对象中修改以下已支持字段，重启或 F5 重载后可以生效：

- `color`
- `secondary`
- `unitPreference`
- `speedMultAll`
- `seaMult`
- `bounceMultAll`
- `pioneerSpeedMult`
- `extraLaserBeams`
- `laserDurationMult`
- `laserLengthMult`
- `bombRadiusBonus`
- `mineTriggerBombRadiusBonus`
- `freeArmyChance`

例如：

```json
{
  "id": 3,
  "speedMultAll": 1.8,
  "seaMult": 0.5,
  "unitPreference": {
    "vanguard": 4.0
  }
}
```

配置解析入口：`src/core/Config.cpp` 的 `Config::loadFromJson()`。

## 当前不能只改 JSON 实现的内容

### 增加新的特性字段

类似下面的字段不会自动注册为游戏行为：

```json
{
  "id": 3,
  "teleport": true,
  "damageMult": 2.0
}
```

当前程序会将未知字段记录为 warning，然后忽略。要使新字段生效，需要同时完成：

1. 在 `Config::Faction` 中增加字段。
2. 在 `Config::loadFromJson()` 中解析字段。
3. 在 `Config::validate()` 中增加数值范围或跨字段校验。
4. 在 `Config::toJson()` 中增加序列化支持（如需要存档或配置往返）。
5. 在对应模拟系统、渲染系统或 UI 中读取并执行该字段。
6. 增加配置解析、行为和存档兼容性测试。

### 增加新的势力

当前势力数量在代码中固定：

- `kFactionTotal = 9`，势力 ID 为 `0..8`。
- `kPlayerFactionCount = 8`，可玩势力 ID 为 `1..8`。

因此在 `factions.json` 中追加 `id: 9` 的对象会被加载器跳过。除此之外，以下部分也依赖固定数量：

- `std::array<..., kFactionTotal>` 统计数组和颜色缓存。
- 选项中的 8 个势力槽位。
- 8 个首都和固定长度的回合顺序。
- 多个 UI、渲染和模拟循环中的 `1..8` 判断。
- 存档校验中的势力数量、回合顺序和势力 ID 范围。

后续若要支持新增势力，需要统一改造势力数量来源、选项、首都布局、回合顺序、渲染颜色、统计、UI、模拟循环和存档格式，不能只修改 JSON。

### 修改势力名称

`factions.json` 中的 `name` 当前不会改变实际界面或事件文本。势力简称仍由 `src/core/GameDefs.h` 中的 `factionShortName()` 按固定 ID 返回。

### 固定 ID 的特性

部分字段虽可从 JSON 读取，但执行逻辑仍绑定固定势力 ID：

- `bombRadiusBonus` 仅在势力 `id == 6` 的爆炸路径中使用。
- `mineTriggerBombRadiusBonus` 仅在势力 `id == 7` 的地雷路径中使用。
- 免费产兵逻辑仅在势力 `id == 8` 触发，并使用 `freeArmyChance`。

例如把 `bombRadiusBonus` 写入 `id == 3`，字段本身会被读入，但不会产生爆炸半径效果。

## 后续修复方向

1. 将势力特性改为通用的数据驱动定义，而不是由固定字段和固定 ID 分散表达。
2. 复用现有 `Buff` / `FactionMods` 机制，或扩展一套明确的特性类型、参数和聚合规则。
3. 让配置中的势力名称进入运行时定义，并替换 UI、消息和排行榜中的固定名称映射。
4. 评估是否需要支持可变势力数量；若支持，需要同步重构数组、选项、首都、渲染、统计、回合和存档格式。
5. 为新增字段、未知字段、特性行为、势力数量和旧存档兼容性补充测试。

## 相关代码位置

- `src/core/GameDefs.h`：势力总数和可玩势力数量常量。
- `src/core/Config.h`：`Config::Faction` 定义。
- `src/core/Config.cpp`：默认势力、JSON 解析、未知键检查、校验和序列化。
- `src/sim/Buff.cpp`：初始势力增益和增益聚合。
- `src/world/Faction.cpp`：势力运行时状态和免费产兵逻辑。
- `src/sim/systems/DeathSystem.cpp`：爆炸半径特性。
- `src/sim/systems/EffectSystem.cpp`：地雷爆炸半径特性。
- `src/replay/Snapshot.cpp`：存档势力数量和 ID 校验。
