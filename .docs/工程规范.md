# 工程规范（供后来开发者阅读）

> 本文件汇总本项目**模块/接口约定**。**接手先读** `.docs/代码卫生.md`（写码习惯与门禁）、
> `.docs/文档卫生.md`（文档规则），再读本文件。

---

## 1. 目录与路径约定

- **资产（只读、随源码分发）** 一律在 `data/`：`army*.png`、`config.jsonc`、`towers.png` 等；原生开发地图统一放在 `data/maps/`，使用 `.landmap`。
- **运行期产物（可写、可丢弃、不进版本库）** 一律在 `userdata/`：
  - `userdata/options.json` —— 菜单选项（开始游戏时保存、启动读取）；
  - `userdata/screenshots/` —— F12 / QA 钩子截图。
- **路径字符串禁止散落硬编码**：全部收敛到 `src/core/Paths.h`（`kDefaultConfigPath`、
  `kMapDataDir`、`kDefaultOptionsPath`、`kGeneratedMapDir`、`kScreenshotDir`、`ensureUserDataDirs()`）。
  新增默认路径 → 先加进 Paths.h 再引用。
- 约定：**从项目根运行**（`data/` 相对 CWD 解析），`userdata/` 由程序启动时自动创建。

## 2. 构建（CMake）约定

- **显式源列表，禁止 `file(GLOB_RECURSE)`**：新增 `.cpp` 必须手动加入
  `CMakeLists.txt` 对应目标列表（core/replay/input/render/app/tests）。漏加 = 链接错误，
  但这是有意的：杜绝"文件存在却不在工程里"的静默漂移。
- 项目目标统一 `-Wall -Wextra`（`landwar_warnings()` 函数）；告警纪律见 `.docs/代码卫生.md` §6。
- 预设：`default`（Debug，Windows/MSYS2 本机路径）、`release`（Release）、`linux`（Debug，
  Linux 系统 g++/Ninja，输出到 `build-linux/`）。ASan/UBSan 未内置（工具链缺
  libasan/libubsan，装好后可加 `asan` 预设）。
- Linux 构建依赖：`SDL2`、`SDL2_image`、`nlohmann-json3-dev`、`libspdlog-dev`、`libgtest-dev`；
  EnTT 为 header-only，**非 Windows 平台固定使用仓库内 `_deps/entt/include`**（Ubuntu 未打包
  EnTT；同时避免 WSL 继承的 Windows PATH 误命中 MSYS2 的 EnTT 而注入 MinGW 头），Windows 保持
  系统包优先、`_deps` 兜底。
- 本机 WSL / Linux 的依赖安装、vendored 依赖准备与编译/测试步骤见 `运行说明.md` 的
  「WSL / Linux 本地构建」；GitHub Actions 走同一套步骤。
- 第三方源码（`_deps/imgui-src`）本地目录、不锁 URL；升级时整体替换并注明版本。

## 3. 确定性红线

- **所有随机**来自注入的 `Rng`（mt19937）；模拟键 = `(mapSeed, seed, config, map, options)`。
- 系统内新增 RNG 调用必须走注入 `Rng`；**渲染层绝不消耗 sim RNG**。
- **语义基线**：`tests/test_baseline.cpp` 锁定
  固定随机地图（种子 42、2500 tick）下的**语义基线 hash**，只统计：
  每格势力归属 + 所有兵的类型/势力/位置/速度方向/速度。方/六/三角各一条。
   当前值：**方** `0x1af2b9df177f5fc1`、**六** `0x9f0e526b12255d7a`、**三** `0x03dd856c899e44d8`。
  任何影响这些核心状态的模拟行为变化 → 该测试失败。
  **config 序列化/快照字段增删/纯渲染改动不影响基线**。
  **更新流程**：
  1. 重跑 `landwar_tests --gtest_filter='Determinism.Baseline*'` 取新 hash；
  2. 改 `test_baseline.cpp` 期望值，并在提交信息说明原因。
- 如需完整快照级回归（含经济/科技/特效/RNG 等），仍可手工比较 `Snapshot::serialize`；
  但日常红线以语义基线为准，避免频繁无意义漂移。

## 4. 配置键纪律（config.json）

- **缺键回退默认是设计；打错的键名同样静默回退——所以未知键必须告警**：
  `Config::loadFromJson` 解析后整树校验，已知键集合外的键 → `spdlog::warn`（含路径，如
  `render.city.lineMinCellPx`）。**新增/删除 config 键时**：
  1. 同步更新 `Config` 结构与默认值（`Config.h`）；
  2. 同步 `loadFromJson` 读取 + `toJson` 输出（键严格对称，单测往返锁定）；
  3. 同步 `validateConfigKeys` 的已知键列表（`Config.cpp`）；
  4. 同步 `.docs/配置说明.md`。
- 允许 `_` 前缀键（如 `_comment`）作为文档注释，校验自动跳过。

## 5. 渲染器约定

- 共享绘制原子在 `src/render/RendererUtil.h`（纯头文件）：
  - `spriteSize(basePx, zoom)` —— 精灵绘制尺寸 = base×zoom，下限 2px；
  - `scaledColor(col, rate)` —— 颜色 × 系数（山 0.08 / 城 iconDarken / 玩家指示 0.8）；
  - `isVisibleOnScreen(cam, x, y, worldRadius)` —— **视野剔除**。实体渲染器
   （Army/Effect/Projectile）一律先剔除再画；半径取保守值（多画无害、少画是 bug）。
- **LOD 档位选择在 `TintCache::pickSizeIndex()`**，不要另写。
- 贴图管线：统一走 `TintCache`（Multiply / HueRotate），不直接 `IMG_Load` 画。
- 六个渲染器 = Map / Army / Effect / Projectile / City / CityMarker，各自只写"画什么"，
  "怎么换算/剔除/选档"用共享辅助。

## 6. 坐标变换规则

- **唯一实现 = 连续版**：`math::toScreenXf/Yf`（`ScreenTransform::toXf/toYf`、
  `Camera::toScreenX/Y`）。
- **新代码一律用连续版**，保留小数（城市中心等非整数坐标不能被抹掉）；
  需要整数像素时显式 `Camera::toScreenXi/Yi`（lround）。
- `toScreenX/Y`（int 截断版）与 `ScreenTransform::toX/toY` 禁止在新代码使用。

## 7. UI 约定

- **缩放公式唯一入口**：`src/ui/UiScale.h` —— `ui::scaled(base, uiScale)`、`kMinUiScale`/
  `kMaxUiScale`（0.6/2.0）、`kSliderWidth`（220）、`kButtonWidth`（140）、
  `kDropdownWidth`（120）、`mainPanelWidth()`。**禁止再手写 `x * uiScale`**；面板特有
  基准（菜单 620、可移动面板 340）保留在各文件但经 `scaled()` 缩放。
- **颜色转换唯一入口**：`src/ui/UiText.h` —— `rgbToImVec4`、`factionColor(sim, id)`。
  禁止各面板再写 `ImVec4(r/255, g/255, b/255, 1)`。
- **彩色文本唯一入口**：`TextSeg` + `drawSegmentedText` / `drawTextWithHighlight` /
  `drawTextWithFactionNames`（消息里一个或多个势力名着色；单名用 `drawTextWithFactionName`）
  （消息"前缀白+势力名着色+后缀白"、科技旧值黄/新值绿等场景）。不要手拼
  `PushStyleColor + TextUnformatted + SameLine + PopStyleColor` 链。
- **展示文本不进模拟核心**：`Simulation` 只发结构化事件（`GameEvent{kind,factionId,data,...}`），
  文案（中文、时间前缀、势力名）在 UI 层组装。新增消息场景照此办理。

- 跨模块的通用规则（不变量/断言、单一事实源、兜底与错误处理、日志、兼容与清理、编译门禁、
  文本格式、依赖、提交）全部收在 `.docs/代码卫生.md`；文档规则收在 `.docs/文档卫生.md`。
- 本文只保留模块/接口约定。两者冲突时以本文为准。

## 9. 模拟规则唯一入口（友敌 / 可占领）

- **友敌判定** = `src/sim/ConquestRules.h` 的 `areAllied` / `areEnemies`；**可占领判定** = 同头文件的
  `canConquerCell`（势力 + 兵种 + 格）。近战、子弹、爆炸/地雷/激光击杀、激光"进入非己方陆地停止"、
  征服总闸（`Faction::conquerIndex`）与移动分流全部走这里，不得另写"同势力才友 / 不同势力就占"的分支。
- **盟友** = `Faction::allianceId` 同号（`-1` = 无联盟；同号构成等价关系）。来源 = `Options.alliances`，
  由 `Simulation::initFactions` 在征服首都之前写入；随快照 `allianceIds` 保存。
- **兵运动规范**（不可占领格的规则 1/2/3 与海洋闸门）见 `.docs/兵运动与盟友系统开发文档.md` §4。
- **盟友陆地判定** = 同头文件的 `isAlliedLand`（`canConquerCell` 共用之）；判定某次反弹是否
  "发生在盟友边界上"只允许用它，不得改写"目标归属 == 盟友"。
- **盟友边界闸门**（`comp::AllyGate` 的 CUSUM、速度归一泄漏、报警放行一次）见开发文档 §12；
  参数在 `config.allyGate`，统计量随快照 v15 保存。
- **整城易主判定** = `Faction::conquerIndex` 内的 `allBaseCellsInAlliance`（城市全部基建格同属
  征服者所在联盟 → 城市归**当次征服者**）；它读 `areAllied`，不得另写"同势力才易主"的分支。
  规则与例外见 `.docs/兵运动与盟友系统开发文档.md` §5.8。
