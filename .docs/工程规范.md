# 工程规范（供后来开发者阅读）

> 本文件汇总本项目**约定俗成的工程规范**，与 `.docs/开发计划.md`（阶段功能计划）、
> `.docs/翻新计划.md`（行为规格）、`.docs/配置说明.md`（config 全键）互补。
> 新代码请先读本文件再动手——多数"重复实现"的教训都收敛成了这里的规则。

---

## 1. 目录与路径约定（2026-08 工程改进）

- **资产（只读、随源码分发）** 一律在 `data/`：`map_*.bmp`、`army*.png`、`config.json`、`towers.png` 等。
- **运行期产物（可写、可丢弃、不进版本库）** 一律在 `userdata/`：
  - `userdata/options.json` —— 菜单选项（开始游戏时保存、启动读取）；
  - `userdata/maps/gen_*.bmp` —— 随机地图生成物（P6，确定性：同 seed+参数再生成同文件）；
  - `userdata/screenshots/` —— F12 / QA 钩子截图。
- **路径字符串禁止散落硬编码**：全部收敛到 `src/core/Paths.h`（`kDefaultConfigPath`、
  `kDefaultOptionsPath`、`kGeneratedMapDir`、`kScreenshotDir`、`ensureUserDataDirs()`）。
  新增默认路径 → 先加进 Paths.h 再引用。
- 约定：**从项目根运行**（`data/` 相对 CWD 解析），`userdata/` 由程序启动时自动创建。

## 2. 构建（CMake）约定

- **显式源列表，禁止 `file(GLOB_RECURSE)`**（2026-08 改进）：新增 `.cpp` 必须手动加入
  `CMakeLists.txt` 对应目标列表（core/replay/input/render/app/tests）。漏加 = 链接错误，
  但这是有意的：杜绝"文件存在却不在工程里"的静默漂移。
- 项目目标统一 `-Wall -Wextra`（`landwar_warnings()` 函数）；**新代码不得引入新警告**。
- 预设：`default`（Debug，本机路径）、`release`（Release）。ASan/UBSan 未内置（工具链缺
  libasan/libubsan，装好后可加 `asan` 预设）。
- 第三方源码（`_deps/imgui-src`）本地目录、不锁 URL；升级时整体替换并注明版本。

## 3. 确定性红线（最高优先级）

- **所有随机**来自注入的 `Rng`（mt19937）；模拟键 = `(mapSeed, seed, config, map, options)`。
- 系统内新增 RNG 调用必须走注入 `Rng`；**渲染层绝不消耗 sim RNG**。
- **基线机器化（2026-08）**：`tests/test_baseline.cpp` 锁定
  `--headless --seed 42 --ticks 20000` 的 `state_hash`（**方** `0x230960a67e857bb0`、
  **六** `0x525b2d8fd4be80ab`、**三** `0x43061e47462627e3`；P12 起三密铺各一条）。
  方形基线沿革：双色势力渲染并入 config（`factions.secondary` / `render.tile` /
  `render.city.mix` 新键 + `sea.cyanSeaMult` 死键删除 + 中立主色 127→96）；
  2026-08-14 用户调数据文件渲染值（tile 主0.5/副0.3/白0.2、city.mix 主0.7）；
  P12 起步新增 `map.tiling` + `city.hex/city.tri` 形状表（sim 行为均不变：
  land=3139 army=276，纯 config 序列化变）；P12 快照 v6（cells 按密铺格序 +
  城市 baseIndex）→ `0xbd90b94d52be9413`。
  任何模拟行为变化 → 该测试失败。**更新流程**：
  1. 重跑 `build\landwar.exe --headless [--tiling hex|tri] --seed 42 --ticks 20000 --summary` 取新 hash；
  2. 改 `test_baseline.cpp` 期望值，并在 `.docs/开发计划.md` §0 基线记录注明原因。
- 序列化（`Snapshot`/`Config::toJson`）字段增删**也会**改变 `state_hash`（hash = 全状态
  序列化字符串的 FNV-1a）——行为不变但 hash 更新是预期，按上述流程走。

## 4. 配置键纪律（config.json）

- **缺键回退默认是设计；打错的键名同样静默回退——所以未知键必须告警**（2026-08 改进）：
  `Config::loadFromJson` 解析后整树校验，已知键集合外的键 → `spdlog::warn`（含路径，如
  `render.city.lineMinCellPx`）。**新增/删除 config 键时**：
  1. 同步更新 `Config` 结构与默认值（`Config.h`）；
  2. 同步 `loadFromJson` 读取 + `toJson` 输出（键严格对称，单测往返锁定）；
  3. 同步 `validateConfigKeys` 的已知键列表（`Config.cpp`）；
  4. 同步 `.docs/配置说明.md`。
- 允许 `_` 前缀键（如 `_comment`）作为文档注释，校验自动跳过。

## 5. 渲染器约定（2026-08 收敛）

- 共享绘制原子在 `src/render/RendererUtil.h`（纯头文件）：
  - `spriteSize(basePx, zoom)` —— 精灵尺寸 = base×zoom，下限 2px；
  - `scaledColor(col, rate)` —— 颜色 × 系数（山 0.08 / 城 iconDarken / 玩家指示 0.8）；
  - `isVisibleOnScreen(cam, x, y, worldRadius, wrap, wrapBand)` —— **视野剔除**。
    实体渲染器（Army/Effect/Projectile）一律先剔除再画；wrap 开启时贴界带恒可见
    （副本可能在对侧视口内，不能按主位置剔除）。半径取保守值（多画无害、少画是 bug）。
- **LOD 档位选择在 `TintCache::pickSizeIndex()`**（2026-08 从 Map/CityRenderer 副本收敛），
  不要另写。
- 贴图管线：统一走 `TintCache`（Multiply / HueRotate），不直接 `IMG_Load` 画。
- 六个渲染器 = Map / Army / Effect / Projectile / City / CityMarker，各自只写"画什么"，
  "怎么换算/剔除/选档"用共享辅助。

## 6. 坐标变换规则（2026-08 收敛）

- **唯一实现 = 连续版**：`math::toScreenXf/Yf`（`ScreenTransform::toXf/toYf`、
  `Camera::toScreenX/Y`）。
- **新代码一律用连续版**，保留小数（城市中心等非整数坐标不能被抹掉）；
  需要整数像素时显式 `Camera::toScreenXi/Yi`（lround）。
- `toScreenX/Y`（int 截断版）与 `ScreenTransform::toX/toY` 仅存历史逐像素路径，不要在新代码用。

## 7. UI 约定（2026-08 收敛）

- **缩放公式唯一入口**：`src/ui/UiScale.h` —— `ui::scaled(base, uiScale)`、`kMinUiScale`/
  `kMaxUiScale`（0.6/2.0）、`kSliderWidth`（220）、`kButtonWidth`（140）、
  `kDropdownWidth`（120）、`mainPanelWidth()`。**禁止再手写 `x * uiScale`**；面板特有
  基准（菜单 620、可移动面板 340）保留在各文件但经 `scaled()` 缩放。
- **颜色转换唯一入口**：`src/ui/UiText.h` —— `rgbToImVec4`、`factionColor(sim, id)`。
  禁止各面板再写 `ImVec4(r/255, g/255, b/255, 1)`。
- **彩色文本唯一入口**：`TextSeg` + `drawSegmentedText` / `drawTextWithHighlight`
  （消息"前缀白+势力名着色+后缀白"、科技旧值黄/新值绿等场景）。不要手拼
  `PushStyleColor + TextUnformatted + SameLine + PopStyleColor` 链。
- **展示文本不进模拟核心**：`Simulation` 只发结构化事件（`GameEvent{kind,factionId,data,...}`），
  文案（中文、时间前缀、势力名）在 UI 层组装。新增消息场景照此办理。
