## 1. 目标与需求分解

把长期思路的原文拆成可验收条目。每条给出**验收方式**，后文按编号回指。

| 编号 | 需求 | 验收方式 |
| --- | --- | --- |
| **R1** | 河流是地块的**顶点和边的集合**，通常是边首尾相连 | 地图数据能表达边集合与（可导出的）顶点集合；孤立边/断链不崩 |
| **R2** | 代码基础：维护**地块顶点的几何关系接口**，重点是**邻点接口**；信息按顶点建立，创建地图时建立一次 | `TilingGeom` 暴露顶点邻接查询；构建发生在 `TilingTable` 惰性加载内（每种密铺一次）；单测覆盖 17 种密铺 |
| **R3** | 局内只影响兵的运动：撞河按**过河概率**通过，否则反弹；**过河不减速** | 单测：河上失败反弹且状态不变；通过则正常进入、速度不变 |
| **R4** | 判定顺序：**河 → 山 → 敌方地块**；前两阶段失败**不占领**，敌方格阶段即使反弹**也已占领** | 单测覆盖三种组合（河×山×敌 × 通过/失败） |
| **R5** | 河的边的**两个邻块不能有海** | 生成/编辑器都拒绝临海边；加载时校验/剪除并告警 |
| **R6** | 渲染：**粗的纯黑线**；不覆盖城/首都图标，不覆盖城基建地块边界线 | 目测 + 叠放次序论证（§7.1） |
| **R7** | 编辑器：地图信息新增河流；新增**河流按钮**；点击/拖拽 → 落格 → 最近边 → 记录为河 | 编辑器手测 + `MapEditorModel` 单测 |
| **R8** | 随机生成：输入**河流密度**；河数 = 密度 × 总格数；随机山地格的随机顶点作源；按**梯度 + 邻点方向**的 softmax 概率游走；终止规则完整；参数进 `config.jsonc` | 单测：同种子确定性、密度 0 时与旧输出逐字节一致、终止分支覆盖 |
| **R9** | 预留接口：日后可能有其他建立在地块**边**上的结构 | 边要素存储按通用容器设计，河只是第一个使用者（§5.2） |

## 3. 总体设计

### 3.1 分层

```
几何层  TilingGeom：规范顶点键 / 规范边键 / 顶点邻接 / 顶点-边关联   （无 RNG，纯几何）
  ↑
数据层  MapDefinition.rivers（边集合，文件格式）
        Map.riverEdges_（排序键，运行时 O(log n) 查询；预留通用"边要素"容器）
        Snapshot.map.rivers
  ↑
玩法层  MovementSystem：陆→陆分支最前插入"河骰"
  ↑
渲染层  MapRenderer 新增河图层（在城之前 → 自动不覆盖城）
  ↑
工具层  MapEditorModel 河边工具；MapGenerator 随机成河
```

### 3.2 关键决定（先给结论，理由见各节）

| 主题 | 结论 |
| --- | --- |
| 河流数据形态 | **以"规范边"为权威**（顶点可由边导出）；不单独序列化顶点。封边键为 `(cell, edge)` 对，规范到较小格。 |
| 规范键位置 | 只在 `TilingGeom` 定义一次（`edgeKey/vertexKey`），数据层/编辑器/生成器/渲染器全部复用，禁止各自比较浮点坐标。 |
| 顶点拓扑构建 | 放进 `TilingTable` 的 `loadTable`，随 `call_once` 缓存每类型建一次。 |
| 邻点接口粒度 | 新增**顶点级**接口 `vertexNeighbors(cell,v)`；既有 `pointNeighbor`（格级）不动，避免破坏征服/山修正语义。 |
| 河骰位置 | `processEnteredCell` 的**陆→陆**分支最前；失败 `doBounce(); return true;`（局部量不写回 → 状态零变化、不占领）。 |
| 过河减速 | 不修改任何速度/剩余长度（与山地相反）。 |
| 判定顺序 | 河 → 山 → 敌（敌阶段先占领后反弹，保持现状）。 |
| 临海约束 | **所有河边的两个邻块都必须是陆地**；“入海”表现为最后一段的**终点**是临海顶点，该段本身仍是内陆边（§9.4）。 |
| 渲染次序 | 河图层放在 `MapRenderer::draw` 内部（地形/山之后、边界线之前）→ 城市层晚于它，R6 自动成立。 |
| 版本号 | `MapDefinition` **保持 version 2，新增可选 `rivers` 字段**；快照升 `kSnapshotVersion` 11→12。理由与备选见 §5.4。 |
| 密度默认值 | `riverDensity = 0` → 零 RNG、零行为差异，**现有语义基线不漂移**（§9.9）。 |

## 4. 几何层：顶点/边拓扑接口（R1/R2/R9）

### 4.1 为什么必须是顶点级拓扑

生成器要在"当前顶点"上枚举**几何邻点**（只考虑方向、不考虑距离），并判断"这个候选点是否已是本河的点 / 是否在别的河上 / 是否临海"。现有接口只到"格"粒度：

- `pointNeighbor(cell,k)` 给共享顶点的**邻格**，但一个格与另一个格可能只共享 1 个顶点，无法知道是哪个；
- `cellEdge(cell,k)` 给边的**世界端点坐标**，若用坐标比较去重，就要引入容差与浮点相等，违反工程规范"少写兜底"。

因此新增的顶点拓扑必须**在构建期用容差把 (base,vertex,dr,dc) 归并成等价类**，运行期只做整数操作。

### 4.2 `TilingTable` 新增（构建期，一次）

在 Tiling.cpp:543 现有 `vertexNeighbors` 构建旁，新增两张表：

```cpp
// 顶点等价关系：对每个基础格 b、每个多边形顶点 i，列出在 ±2 周期块内与之重合的
// 所有 (nb, j, dr, dc)。同一几何顶点会出现在多条记录里；规范顶点键取其中最小表示。
struct VertexLink { int nb; int j; int dr; int dc; };
std::vector<std::vector<std::vector<VertexLink>>> vertexLinks;  // [b][i] → links

// 顶点关联的边（多边形边序号的两端顶点）：对 (b, i)，两条入射边在多边形序下是
// edge i 与 edge (i-1+n)%n；这里存的是**顶点在多边形序里的两个邻顶点**，
// 便于 O(1) 取"从该顶点出发的候选点"。
std::vector<std::vector<std::array<int, 2>>> vertexAdj;  // [b][i] → {i_prev, i_next}

// 每条基础边的反向边（同一条边在邻格上的 k）。边界边（leaf）记 -1。
// 供规范化 edgeKey 与 hasRiverEdge 热路径 O(1) 使用。
std::vector<std::vector<int>> edgeReverseK;   // [b][k] → k'（-1 = 地图边界）
```

构建伪代码见附录 A.1。要点：

- 重合判据沿用现有 `kTableTol`（Tiling.cpp:104）与 `samePoint`（:324）风格，构建期一次性容差比较，**运行期零浮点比较**；
- `vertexLinks` 必须记录**对端顶点 j**（现有 `vertexNeighbors` 只记 `(nb,dr,dc)`，不够）；
- `vertexLinks[b][i]` **必须包含自身表示 `(b, i, 0, 0)`**（不能像 `vertexNeighbors` 那样跳过自格）：它既用于规范键取 min，也用于经 `vertexAdj[b][i]` 取"同格内与该顶点相邻的两个顶点"；
- 平移窗口 ±2 已覆盖当前全部基础域（现有代码同窗口，:549）。所有等价表示两两相差 ≤1 个周期块，因此任取一个表示，其 ±2 窗口都能覆盖整个等价类 → 规范键一致（§4.4）。

### 4.3 `TilingGeom` 新增 API（运行期）

```cpp
// ---- 顶点（R2）----
// 格内顶点数（= cellPolygon 顶点数；方 4 / 六 6 / 三 3 / 表驱动 = 多边形边数）。
int cellVertexCount(int index) const;
// 顶点世界坐标（与 cellPolygon 的第 v 个顶点一致）。
void cellVertex(int index, int v, double& wx, double& wy) const;
// 顶点在**格坐标系**下的坐标（斜周期时 = R^{-1}·世界；非斜 = 世界）。
// 随机生成的梯度在同一坐标系下，方向点积必须同帧（§9.6）。
void gridVertex(int index, int v, double& gx, double& gy) const;

// 顶点规范键：把一个 (cell, vertex) 表示为全图唯一键（0 = 无效）。
// 编码 = canonicalCell * kMaxCellVerts + canonicalVert，kMaxCellVerts = 16。
std::uint64_t vertexKey(int index, int v) const;
// 解码 + 顶点几何（编辑器/调试用）。
bool vertexFromKey(std::uint64_t key, int& index, int& v) const;

// **顶点邻点接口（R2 核心）**：与 (index,v) 共享一条边的全部顶点，已按规范键去重，
// 越界/图外表示直接跳过。返回数量；k 越界返回 -1。
int vertexNeighborCount(int index, int v) const;
int vertexNeighbor(int index, int v, int k, int& outCell, int& outVert) const;
// 便捷版：只用规范键。
std::uint64_t vertexNeighborKey(int index, int v, int k) const;

// 顶点关联的边（格内边序号 k，与 neighbor 同序）：恰好两条（地图边界顶点可能一条）。
int cellVertexEdgeCount(int index, int v) const;
int cellVertexEdge(int index, int v, int which) const;   // which ∈ {0,1}

// ---- 边（R9 通用边要素的基础）----
// 一条边由两个端点顶点确定；返回连接 (cellA,vA) 与 (cellB,vB) 的格内边序号 k，
// 无此边返回 -1（vA/vB 必须是 vertexNeighbor 关系）。
int edgeIndexBetweenVertices(int index, int v, int neighborCell, int neighborVert) const;

// 规范边键：同一条几何边在两侧格上编码相同；地图边界边只在自己这侧编码。
// 编码 = canonicalCell * kMaxCellEdges + canonicalK，kMaxCellEdges = 16，0 = 无效。
std::uint64_t edgeKey(int index, int k) const;                     // 热路径：O(1)（用 edgeReverseK）
std::uint64_t edgeKeyBetween(int index, int neighborIndex) const;  // 便捷版：扫 neighbor 找 k，O(边数)
bool edgeFromKey(std::uint64_t key, int& index, int& k) const;
bool edgeEndpoints(std::uint64_t key, double& x0, double& y0, double& x1, double& y1) const;

// 边的两个邻格：out[0] 恒 = 规范键所属格，out[1] = 对侧（-1 = 地图边界）。
void edgeCells(int index, int k, int& outA, int& outB) const;
```

**语义约束**

- `edgeKeyBetween(a,b)` 要求 `b == neighbor(a,k)` 对某个 k 成立；否则返回 0。调用方在热路径已知道 k，用 `edgeKey(a,k)` 更省。
- `edgeKey` 规范规则：`(index,k)` 与对侧 `(nb,k')` 取 `(cell, k)` 字典序小者；对侧越界（地图边界）时保留本侧。**地图边界边永远不是河**（河边两侧必须陆地，边界没有第二个邻块）。
- 顶点规范规则：`(cell,v)` 与 `vertexLinks` 中全部 `(row+dr, col+dc, nb, j)` 取字典序最小；若最小候选落在图外，仍取**图内候选中的最小**（同一顶点的所有图内表示互相在 ±2 窗口内 → 结果一致）。

### 4.4 规范键一致性论证（实现时不要改坏）

- 单个几何顶点的全部基础表示构成一个等价类，类内任意两个表示相差 ≤1 个周期块（顶点星形最多跨相邻块）。
- `vertexLinks` 的窗口是 ±2，故任取类内一个表示，其窗口包含整个类；反之从另一个表示出发也包含整个类 → 两者取 min 得到同一键。
- 规范边同理：一条边只有两个基础表示（两侧格），且互为邻格（相差 0 或 1 个周期块），无需窗口。
- **推论**：编辑器/生成器/渲染器/读档四处共用同一函数，不需要任何浮点比较或再校验。

### 4.5 顶点-海判定

```cpp
// 用 vertexLinks 枚举 (cell,v) 的全部共点格，任一为海则 true。
// 只在生成器/编辑器使用；玩法层不需要（河骰只查边）。
bool vertexTouchesSea(const Map& map, int cell, int v);   // world/Map.cpp 或 RiverGenerator
```

### 4.6 兼容性

- `pointNeighbor*`、`neighbor*`、`cellEdge`、`crossEdge`、`worldToCell` 的**签名与行为全部不变** → 现有移动/征服/山修正/城市形状零影响，语义基线不动。

## 5. 数据层

### 5.1 `MapDefinition` 变更（文件格式）

```cpp

// 规范边引用（cell = 规范键所属格，edge = 该格内与 neighbor 同序的边序号）。
// 文件格式**不使用内存打包键**，避免常量 stride 变化破坏历史文件。
struct MapEdgeRef {
    int cell = -1;
    int edge = 0;
};

struct MapDefinition {
    ...
    std::vector<MapEdgeRef> rivers;   // 规范、按 (cell,edge) 升序、无重复

```

JSON（**保持 `version: 2`，新增可选键**）：

## 6. 玩法层：河骰（R3/R4）

### 6.1 判定顺序（权威）

兵从格 A 跨边 e 进入格 B（陆→陆，含 B 为山）：

1. **河骰**：若 e 是河 → 掷 `riverCrossChance`。失败 → `doBounce()`，**立即返回**（不进入、不占领）。
2. **山骰**：B 为山 → 掷 `mountainEnterChanceFor`（现状逻辑）。失败 → 反弹，不占领。
3. **敌方格**：B 非己方 → `conquerCell(...)` 先占领，再掷 `bounceMult`；即使反弹也已占领（现状逻辑，不改）。

三条规则来自长期思路原文，逐字对应：

- "先判定河，若通过再判断山，若通过再判断敌方地块" → 1→2→3；
- "此阶段（敌方地块）即使判定为反弹，也可占领该敌方地块，前几个阶段则不可以" → 1/2 失败走 `return true`，只有 3 在占领之后才可能反弹。

### 6.2 边定位：两条移动路径怎么拿到 e

| 路径 | 现状 | 河骰需要的输入 | 改法 |
| --- | --- | --- | --- |
| 密铺 `moveArmyTiled` | 已有 `cellIdx` 与 `crossed=k`（:325） | `(cellIdx, k)` | 直接传 |
| 方形 `moveArmySquare` | 只有 `boundaryCode` 与目标 `(gx,gy)` | `(srcIdx, k)` | 在循环内**显式维护 `srcIdx`**（初始 `gy*w+gx`，成功进入后更新），并用 `squareEdgeFromBoundaryCode` 映射 |

方形映射（由 `data/tiling_specs_regular.json` 的 `edgeOrder:[2,0,3,1]` 与 `findNextXY` 的边界语义推出）：

| `boundaryCode` | 撞的边 | 方向 | 方形边序号 k |
| --- | --- | --- | --- |
| 0 | `x = x1` | 左 | 2 |
| 1 | `y = y1` | 下 | 1 |
| 2 | `x = x2` | 右 | 3 |
| 3 | `y = y2` | 上 | 0 |

即 `static constexpr int kSquareEdgeFromBoundary[4] = {2, 1, 3, 0};`（放在 MovementSystem.cpp 匿名命名空间，或做成 `TilingGeom` 辅助——**只对方形有效**，密铺路径不用）。

> 为什么不在方形里用 `hasRiverBetween(srcIdx, goalIdx)` 走 `neighbor` 扫描：热路径每兵每跨格一次 × 4 邻扫描没有必要；显式维护 `srcIdx` 与映射表是 O(1)，且不依赖浮点位置反推。

### 6.3 修改点

`processEnteredCell` 签名增加 `(int srcIdx, int edgeK)`（或一个 `std::uint64_t edgeKey` 由调用方算好，减少参数）。在**陆→陆分支最前**插入：

```cpp

    // R3/R4：河骰最先。失败 → 反弹；局部量（nextSpeed/nextRemLength/nextInMountain）

            std::clamp(cfg.river.crossChance
                           * cfg.units[static_cast<size_t>(unit.type)].riverCrossMult,
                       0.0, 1.0);

            doBounce();
            return true;
        }
        // 通过：不减速，直接继续（无任何速度/剩余长度修改）
    }
    ... 现有山骰 + 敌方格 ...
}
```

- 陆→海 / 海→陆分支**不做**河骰：河边两侧必须陆地，这两类边不可能是河（§5.1 校验已保证）。若做也只是恒 false，徒增热路径成本，不建议。
- `goalCell->mountain` 的"离开山地复原速度"仍在河骰之后（现状位置），但注意它只写局部量；河骰失败已提前 return，所以不会残留。

### 6.5 确定性

- **无河地图**：`hasRiverEdge` 为 false → 不消耗任何 RNG，RNG 流与分支完全不变 → 语义基线不动。
- **有河地图**：河骰消耗 `rng.chance`（1 次）+ 失败时 `bounceJitter`（1 次），RNG 流改变 → 该地图的基线必然变化（属预期）。

### 9.2 算法总览

时机：**在"内陆山"确定之后、`finishDefinition`（建城/掷城骰）之前**。此时已具备 `land[] / isMountain[] / height[] / grad[]` 与 `TilingGeom`，且不依赖城市数据。放在建城之前使"河流消耗的 RNG"与"城市消耗的 RNG"顺序稳定可复现；密度 0 时不消耗 → 旧输出逐字节不变（§9.9）。

步骤：

1. 收集 `mountainCells`（`land && isMountain`）与 `landCells`（全部陆地）；
2. 循环 `riverCount` 次（每次 = 一次"河流生成尝试"）：
   a. 选源格：优先 `mountainCells`，为空则 `landCells`（"山地格数量不够，选择非山地的陆地格"）；`rng.get(n-1)` 均匀取；
   b. 选源顶点：`v = rng.get(cellVertexCount(src)-1)`；若该顶点临海 → 重试（最多 `sourceRetryPerRiver` 次；仍失败则本次尝试作废）；
   c. 游走（§9.3/9.4）得到本河边的集合；
   d. 结果为空 → 本次尝试作废；否则把新边并入全局边集合（去重）。
3. 输出 `MapDefinition.rivers`（规范、升序）。

> 关于"可能某些功能已实现随机顺序处理地块"：调研结论是**没有可复用的现成工具**——`Map::finishTerrain` 里那套 Fisher-Yates 已被整段注释（Map.cpp:232-379），现行 `finishGeneratedTerrain` 只按海拔/梯度排序。因此本设计自带一个 `pickUniform(rng, list)` 小工具（一行 `rng.get(size-1)`），不引入新的"随机顺序"概念。

### 9.3 概率分布

在当前顶点 `p`（规范键），候选 = `vertexNeighbors(p)` 经过滤后的可用点集合 `C`。

```
d_i      = unit(p_i - p)                      // 方向，只考虑方向不考虑距离
grad(p)  = Σ_{格 c 共点 p} area(c)·gradVec[c] / Σ area(c)   // 共点格梯度面积加权平均
sign     = flowDownhill ? -1 : +1

score_i  = gradientWeight      * dot(sign·grad(p), d_i)     // 含大小：坡陡处方向性更强
         + straightnessWeight  * dot(prevDir, d_i)          // 首段 prevDir = 0
         + mouthWeight         * (p_i 临海 ? 1 : 0)          // 可选引力，默认 0

P(i)     = softmax(score_i / temperature)                    // temperature > 0，clamp 下限
```

- 取下一个点用**一次** `rng.unit()` 做轮盘赌（与工程规范"注入 Rng"一致，且 softmax 只依赖几何，可复现）。
- 全部 `score_i` 相同时退化为均匀分布（softmax 性质），不会因温度趋 0 出现 NaN；实现上对 `temperature` 取 `max(temperature, 1e-6)`。
- "随机性"来自 softmax 采样本身；**不再叠加上层随机方向**，保持可解释、可调参（用户要求"我调整并观察效果"）。

### 9.4 终止条件（逐条对应长期思路）

| 触发 | 行为 | 原文 |
| --- | --- | --- |
| 候选点已在**本次**河流的 visited 集合 | 从 `C` 中剔除（不作为候选，也不终止） | "去掉已在本次生成的河流上的点（例如上一个点，或绕圈）" |
| 候选点已在**其它**河流上 | **保留在分布中**；若被选中 → 记下该段后**终止** | "选择这个点后直接停止…相当于河流支流交汇" |
| 候选点临海 | 保留为候选；被选中 → 记下该段后**终止**（入海） | "如果选取的点是海洋地块的顶点，则做完这一段就终止" |
| `C` 为空（全被剔除 / 无邻点） | 直接终止 | "如果所有邻点都不可用…相当于得到内陆河" |
| 步数达 `maxStepsPerRiver`（>0 时） | 终止（防御长河/数值边界） | 计划外防御，入 config |
| 连接候选的边临海（R5） | 候选剔除（不可走） | "河的边的两个邻块不能有海" |

**R5 与"入海"的统一解释（关键设计）**：所有**被记录的**河边的两侧邻块都必须是陆地（无例外）。一条河边两侧都是陆地 ⇒ 它是内陆边；但它的一端仍可能是一个临海顶点（某个海格只在该顶点处与它相接）。于是"入海"表现为：

- 走到一个临海顶点 → 该段是内陆边（合法）→ 记录 → 终止；
- 若通往某个临海顶点的唯一走法是沿"一侧是海"的边，则该边不可走，河在此处提前终止，不产生海岸线重叠。

这样既严守 R5，又让"选取的点是海洋地块的顶点则终止"这条原文逻辑非空。渲染上河末端停在海岸顶点，视觉上即"入海口"。

> 备选解释（不推荐，写入决策点）：允许最后一段是临海边（真正的海岸段），即给入海口开一个例外。代价是编辑器/加载校验都要分"末段/非末段"，复杂度显著上升。

### 9.5 梯度向量（现状缺口 F）

`estimateGradient`（MapGenerator.cpp:96）内部算了拟合平面 `(gx,gy)` 却只返回 `hypot`。为生成河需改为：

```cpp
// 返回拟合梯度向量（U 变化 / 坐标单位），模长即原返回值。
struct GradVec { double x = 0.0, y = 0.0; };
GradVec estimateGradientVector(const TilingGeom&, int index,
                               const std::vector<double>& height, bool gridCoordinates);
```

- 现有山脉用的 `grad[]`（标量）改为 `std::hypot(v.x, v.y)`，**数值与顺序完全一致** → 山分布/基线不变。
- 新增 `std::vector<GradVec> gradVec` 与 `height` 同长；顶点梯度在 §9.3 现算。
- 目标格无梯度（`det≈0`，现有 :130 回退 `maxSlope`）时返回 `{0,0}`，softmax 退化为"只看 straightness/mouth"，不会除零。

### 9.6 斜周期坐标系（易错点）

- `height` 在斜周期密铺下按**格坐标**（`gridCenter`）采样，`estimateGradient(..., gridCoordinates=true)` 也在格坐标拟合；
- 因此顶点方向向量必须用 `gridVertex`（§4.3）计算，`gradVec` 也留在格坐标；
- 若混用世界坐标顶点（`cellVertex`），斜周期地图上"梯度方向"会整体剪切，概率分布系统性偏向一侧（"横纹"类 bug）。
- 记录边键与坐标系无关（拓扑量），所以只有**概率计算**必须在格坐标帧。

见附录 A.2（`generateRivers` 与 `traceRiver`）。要点：visited 用 `std::vector<uint64_t>` + `std::sort/unique`（每河点数不大），或 `std::unordered_set`（非热路径，且不参与跨机复现——只影响同机结果，但为稳检仍建议排序 vector 以杜绝哈希顺序差异）；全局边集合用 `std::vector<uint64_t>`，每河合并后 `sort/unique` 一次。

### A.1 `loadTable` 顶点拓扑构建（一次性）

```cpp
// 在 Tiling.cpp loadTable 中 edge/vertexNeighbors 构建之后追加。
const int B = static_cast<int>(tab->cells.size());
tab->vertexLinks.assign(B, {});
tab->vertexAdj.assign(B, {});
tab->edgeReverseK.assign(B, {});

for (int b = 0; b < B; ++b) {
    const auto& cell = tab->cells[b];
    tab->vertexLinks[b].resize(cell.n);
    tab->vertexAdj[b].resize(cell.n);
    for (int i = 0; i < cell.n; ++i) {
        tab->vertexAdj[b][i] = { (i + cell.n - 1) % cell.n, (i + 1) % cell.n };
        const auto& p = cell.v[i];
        for (int dr = -2; dr <= 2; ++dr)
        for (int dc = -2; dc <= 2; ++dc) {
            const double ox = dc * tab->wx + dr * tab->hx;
            const double oy = dc * tab->wy + dr * tab->hy;
            for (int nb = 0; nb < B; ++nb) {
                const auto& other = tab->cells[nb];
                for (int j = 0; j < other.n; ++j) {
                    const auto& q = other.v[j];
                    if (std::fabs(p[0] - (q[0] + ox)) <= kTableTol &&
                        std::fabs(p[1] - (q[1] + oy)) <= kTableTol) {
                        tab->vertexLinks[b][i].push_back({nb, j, dr, dc});
                    }
                }
            }
        }
    }
    // 反向边 k（与现有 :511 邻接构建同一循环内顺手填；或在此按 edges 再扫一遍）
    tab->edgeReverseK[b].assign(cell.n, -1);
    for (int k = 0; k < cell.n; ++k) {
        const auto& e = cell.edges[k];
        if (e.nb < 0) continue;
        const auto& oc = tab->cells[e.nb];
        for (int kk = 0; kk < oc.n; ++kk) {
            if (oc.edges[kk].nb == b && oc.edges[kk].dr == -e.dr && oc.edges[kk].dc == -e.dc) {
                tab->edgeReverseK[b][k] = kk;
                break;
            }
        }
    }
}

struct RiverGenParams {  // 来自 cfg.river.gen
    double gradientWeight, straightnessWeight, mouthWeight, temperature;
    bool flowDownhill;
    int maxStepsPerRiver, sourceRetryPerRiver;
};

std::vector<std::uint64_t> generateRivers(const TilingGeom& g,
                                          const std::vector<bool>& land,
                                          const std::vector<bool>& mountain,
                                          const std::vector<GradVec>& gradVec,
                                          const std::vector<double>& cellArea,
                                          bool gridFrame,          // = g.hasSkewedPeriod()
                                          double riverDensity,
                                          const RiverGenParams& rp,
                                          Rng& rng) {
    const int n = g.cellCount();
    std::vector<int> mountains, lands;
    for (int i = 0; i < n; ++i) if (land[i]) { lands.push_back(i); if (mountain[i]) mountains.push_back(i); }
    if (lands.empty()) return {};

    auto seaVertex = [&](std::uint64_t vk) {   // 顶点任一共点格为海
        int c, v; g.vertexFromKey(vk, c, v);
        // 枚举 vertexLinks：任一共点格 !land → true
        ...
    };
    auto vertexGrad = [&](std::uint64_t vk) -> GradVec {   // 共点格面积加权平均
        ...
    };

    const int riverCount = static_cast<int>(std::llround(riverDensity * n));
    std::vector<std::uint64_t> all;
    for (int r = 0; r < riverCount; ++r) {
        const std::vector<int>& pool = mountains.empty() ? lands : mountains;
        bool traced = false;
        for (int attempt = 0; attempt <= rp.sourceRetryPerRiver && !traced; ++attempt) {
            const int cell = pool[rng.get(static_cast<int>(pool.size()) - 1)];
            const int v = rng.get(g.cellVertexCount(cell) - 1);
            if (seaVertex(g.vertexKey(cell, v))) continue;   // 源顶点临海 → 重试
            traceRiver(/*...*/ all, traced);
        }
    }
    std::sort(all.begin(), all.end());
    all.erase(std::unique(all.begin(), all.end()), all.end());
    return all;
}

void traceRiver(/* in: g, land, gradVec, cellArea, gridFrame, rp, rng, startKey */
                /* out: all（全局边集合）, hadEdge */) {
    std::vector<std::uint64_t> visited{ startKey };
    std::uint64_t cur = startKey;
    GradVec prevDir{0, 0};
    bool first = true;
    for (int step = 0; rp.maxStepsPerRiver <= 0 || step < rp.maxStepsPerRiver; ++step) {
        // 1) 候选：顶点邻点，剔除本次已访问 + 边临海/边界 + 无效边
        struct Cand { std::uint64_t key; std::uint64_t edge; double score; bool stop; };
        std::vector<Cand> cands;
        int c, v; g.vertexFromKey(cur, c, v);
        GradVec gv = vertexGrad(cur);
        if (rp.flowDownhill) { gv.x = -gv.x; gv.y = -gv.y; }
        for (int k = 0; k < g.vertexNeighborCount(c, v); ++k) {
            int nc, nv; if (g.vertexNeighbor(c, v, k, nc, nv) < 0) continue;
            const std::uint64_t nk = g.vertexKey(nc, nv);
            if (std::find(visited.begin(), visited.end(), nk) != visited.end()) continue;
            const int ek = g.edgeIndexBetweenVertices(c, v, nc, nv);
            if (ek < 0) continue;
            int a, b; g.edgeCells(c, ek, a, b);
            if (b < 0 || !land[a] || !land[b]) continue;     // R5：临海/边界边不可走
            const bool candSea = seaVertex(nk);
            const GradVec d = unitVec(vertexPos(nc, nv) - vertexPos(c, v));   // 只取方向
            const double score =
                rp.gradientWeight * (gv.x * d.x + gv.y * d.y)
              + (first ? 0.0 : rp.straightnessWeight * (prevDir.x * d.x + prevDir.y * d.y))
              + rp.mouthWeight * (candSea ? 1.0 : 0.0);
            cands.push_back({nk, g.edgeKey(c, ek), score, candSea});
        }
        if (cands.empty()) return;                            // 内陆河终止
        // 2) softmax 轮盘赌（一次 rng.unit()）
        const std::size_t pick = sampleSoftmax(cands, rp.temperature, rng);
        const Cand& chosen = cands[pick];
        all.push_back(chosen.edge);
        hadEdge = true;
        if (chosen.stop || isOnOtherRiver(chosen.key)) return; // 入海 / 支流交汇终止
        visited.push_back(chosen.key);
        const int cc, cv; g.vertexFromKey(chosen.key, cc, cv);
        prevDir = unitVec(vertexPos(cc, cv) - vertexPos(c, v));
        first = false;
        cur = chosen.key;
    }
}
```

> `vertexPos(cell,v)` = `gridFrame ? gridVertex : cellVertex`，与 `gradVec` 同帧（§9.6）；`sampleSoftmax(cands, T, rng)` 用一次 `rng.unit()` 做轮盘赌并返回下标；`isOnOtherRiver(key)` 查询"全局已记录边的端点顶点集合"（生成时维护一个升序 `std::vector<uint64_t>` 顶点集即可）。
