# 文档卫生

> **接手必读**。本文管文档放哪、叫什么、怎么写、改代码时同步哪一份。
> 代码习惯见 `.docs/代码卫生.md`，模块/接口约定见 `.docs/工程规范.md`。

## 0. 指导思想

- 文档只写"会被人执行的决定"：规则、边界、命令、索引。不写常识、不写心路历程、不复制代码。
- 一个约定只在一处详述，其它地方链接过去。互相矛盾的文档比没有文档更糟。
- 文档过期即 bug：改了行为不更新文档，等于没改完。
- 快速迭代期：**旧文档默认归档不保留**，不维护多份"最新版"。

## 1. 位置与文档地图

- 根目录 = 面向使用者；`.docs/` = 工程内部规格（权威来源）；`.docs/old/` = 归档；`rubbish/` = 废弃。
- 新增文档后，在下表登记一行（一句话权威范围）。

| 文档 | 管什么 |
|---|---|
| `README.md` | 怎么用、项目现状 |
| `运行说明.md` | 构建、运行、依赖、WSL/Linux |
| `地图编辑器说明.md` | 地图编辑器用法 |
| `CONTRIBUTING.md` | 改动入口与提交前检查项 |
| `CHANGELOG.md` | 版本记录 |
| `THIRD_PARTY.md`、`ASSET-LICENSES.md` | 依赖与资产许可 |
| `.docs/工程规范.md` | 模块/接口约定（目录、CMake、确定性、config 键、渲染、坐标、UI） |
| `.docs/代码卫生.md` | 写码习惯与质量门禁 |
| `.docs/文档卫生.md` | 本文 |
| `.docs/配置说明.md` | config 全键与合并规则 |
| `.docs/导出发行版.md` | 发行包打包步骤 |
| `.docs/地图尺寸比例映射.md`、`密铺块视图工具.md`、`增益语言.md` | 专题参考 |
| `.docs/兵运动与盟友系统开发文档.md` | 兵运动规范 / 盟友系统 / 密集防御的落地规格（实施中） |
| `.docs/old/` | 归档（历史计划/规格，非权威） |
| `.docs/*.txt` | 手写随笔与思路列表，**不要改内容** |

## 2. 命名与存放

- 长期有效文档不加日期；时点性/一次性文档用 `YYYY_MM_DD_主题.md`。
- `.md` = 规范/说明；`.txt` = 手写随笔，不改写。
- 临时脚本一律放 `tools/`，不散落在根目录。

## 3. 结构与写作

- 唯一 H1；开头一句话说清"本文是什么、给谁看、与其他文档的关系"。
- 一条规则一条 bullet，先规则后理由/例外；给可执行命令。
- 引用符号名/文件路径，**不引用行号**（行号必漂移）；本机绝对路径必须标注"本机"。
- 正文日期统一 `YYYY-MM-DD`。
- 每篇说明维护义务（改什么时同步本文）。

## 4. 单一事实源与同步

- 同一约定只在一处详述；`README.md` / `CONTRIBUTING.md` 只做入口与检查项，细节链接到 `.docs/`。
- 改动同步表：

| 改了什么 | 必须更新 |
|---|---|
| config 键 | `Config.h`/`Config.cpp`、`data/config.jsonc`、`.docs/配置说明.md` |
| 目录/路径、模块约定 | `.docs/工程规范.md`、`README.md` |
| 构建/依赖/运行 | `运行说明.md`、`THIRD_PARTY.md` |
| 行为/版本 | `CHANGELOG.md` |

## 5. 归档与失效链接

- 归档：移入 `.docs/old/`，重命名为 `YYYY_MM_DD_原名.md`；被取代的文档在新文档里声明取代关系。
- 归档或改名后，必须修掉所有指向它的链接；**失效链接视为 bug**（例如指向已归档并改名的计划文档）。
- 找入链：`grep -rn "文件名" --include="*.md" .`。
