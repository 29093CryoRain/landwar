1. `Init0()` — 窗口设置（**新版本无**，头less 时跳过；无弹窗，改用配置/命令行）
2. `seed = time(0); SRand(seed); srand(seed);` → 新版本 `Rng(seed)`，`srand` 不再需要
3. `Init_map()` — RNG 消耗：
   - 逐格城市判定 `get_chance(chancee)`（每个陆地格一次）
   - 8 个首都 `GetRand(Map_x-1)/GetRand(Map_y-1)` + 重试（距离 < 28 重抽）
4. `Init_faction()` — RNG 消耗：

6. `Init_effect()`
7. `LoadDivGraph("data/army.png", 64, 8, 8, 32, 32, army_image)` — 新版 `SpriteSheet`

> 注意：原版在第 4 步可能产生「初始即存在的品红免费兵」（id 随后被 Init_army 补上）。

> 以 `freeArmyEnabled=false` 征服首都（`ConquerContext.freeArmyEnabled`），即**无开局免费兵**；

## 2. 游戏行为规格（移植基准，以代码为准）

> 本节是执行 AI 的移植依据。所有数值同时要求外置到 `data/config.json`（键名见 §3.5）。
> 下文把原版「帧」统一定义为**逻辑 tick**（60Hz，见 §3.7）。

### 2.1 地图与初始化

- 网格 105×95；`mmap[i][j]`：`{x, y, land, city, belongi}`。
- `map.bmp` 解析（原版手写 24bit BMP 解析器，**必须 1:1 复刻语义**）：
  - 文件布局：54 字节头；随后每行 `105*3 + 1` 字节 = 316 字节（1 字节行填充）；行序为 BMP 规范的自底向上。
  - 原版 `for j=0..94 { for i=0..104 { 读3字节BGR } 读1填充 }`，即 `mmap[j]` 行 = 图片**底部**行。
  - 像素 (0,0,0)（全黑）→ `land=0`（海）；否则 `land=1`。
  - 城市判定：`brightness = avg(R,G,B)`（注意原版把负字节 +256 规范化）；`brightness<=99 → 概率0`；否则 `chance = pow(1.040909, brightness-100) / 500`，`get_chance(chance)` 决定 `city=1`。
    > **P5 改版（2026-08-04，地形基图）已取代本解析**：`map.bmp` 语义改为 RGB 概率权重
    > （任一分量<32=海；山概率=ramp(R)、城概率=ramp(G)、B 闲置；每陆格掷骰两次）。旧图已用
    > `tools/gen_probability_maps.py` 等效转换（备份在 `data/legacy_old_encoding/`），本段保留作
    > 历史规格。新解析见开发计划 P5 改版记录 + `.docs/配置说明.md` terrain 节。
  - 解析后统一 `belongi=0`，`x=i, y=j`。
- 首都放置：8 个，`GetRand(Map_x-1)/GetRand(Map_y-1)` 抽陆地格；与已放首都欧氏距离 < 28 则重抽（`i--` 重试技巧）；全部置 `city=1`。
- 清理：海上城市 `city=0`；统计 `total_citys`。
- **屏幕朝向**：`toscreeny = (Map_y - y)*15`（Y 翻转）。世界坐标系 y=0 在屏幕底。新加载器必须得到与原版完全一致的 `mmap`（包括 j=0 在屏幕底）。
- 加载方案二选一（**推荐 A**，均需用 §4 的 Python 黄金数据校验）：
  - **A（忠实）**：`std::ifstream` 按原版逐字节解析 BMP（含填充字节、BGR 序、自底向上），无任何图像库介入。
  - **B（SDL）**：`IMG_Load` 得到自上而下的 surface，然后 `world[j] = surface[Map_y-1-j]` 翻转回世界坐标。

### 2.2 单位（兵）属性与类型

六个类型（`type`）：普通0 / 先锋1 / 开拓2 / 激光3 / 爆炸4 / 地雷5。

> **细节改进（2026-08，先锋/开拓重置）**：先锋=快 + 碰敌方领土 60% 不反弹（`bounceMult` 0.4）；
> 开拓=连占上下左右 4 邻格 + 山地不减速 + 被山地阻挡概率降低（进入 0.8），**取消**敌方不反弹
> （`bounceMult` 1.0）。具体移动语义见 §2.3 注。

出生参数（`add_army`，原样移植）：
- 出生方向：`angle = get_rand_angle()`，再对 4 个象限方向 `±i*π/2` 做 ±π/4 **吸附**（离轴向 < 0.14π 则推开），防止贴着轴向走。（**Phase 9 改**：新版去掉吸附，`SpawnSystem::spawnArmy` 直接用 0~2π 纯随机。）
- `speed = 0.3`；加成链：势力3 ×1.5 → 类型1 ×2 → 类型2且势力4 ×2 → 类型≥3 ×0.6。
- `size = 1.1`；类型3 ×1.8；类型4 ×1.8；类型5 ×1.4。（**config 现值**：`army.baseSize=1`，翻新后调参。）
- 初始 `onland=1`、`lst_move_to_land_time = ttime`。
- 原版池满返回哨兵（`id==Max_army`）；新版**无硬上限**（可用 `config.debug.maxArmyGuard` 保护，默认大值）。

每 tick 移动末尾抖动：`angle += (GetRand(97) - 48.5) / 14447.0`（≈±0.0034 rad，全兵每 tick）。（**Phase 9 改**：取消每 tick 抖动，改为**反弹时**加随机小偏置，见 `config.army.bounceJitter*`。）

### 2.3 移动规则（`Army::move`）

网格穿越用 `find_next_xy`（见 §2.12）。主循环：

```
rem = speed
while rem > 0:
    resi = find_next_xy(x, y, angle, rem)     # 返回下次撞到的网格边界
    if find_and_attack(): return              # 战斗检查，见 §2.4（每跨一格一次）
    if resi < 0:                               # -2 走完本 tick 剩余量；-1 撞到角/平局
        x,y 夹取到 [eps, Map_x]/[eps, Map_y]
        若当前格非己方 → conquer((int)x,(int)y)
        return
    if resi==0&&x<=0: angle=π-angle; continue # 左边界反弹
    if resi==1&&y<=0: angle=-angle;  continue # 上边界反弹
    if resi==2&&x>=Map_x: angle=π-angle; continue # 右边界反弹
    if resi==3&&y>=Map_y: angle=-angle;  continue # 下边界反弹
    goal_map = 该方向相邻格（用 ±eps 取整）
    # --- 山地/海陆切换（细节改进 2026-08：下一格为山「不管当前格是什么」都掷进入/反弹）---
    if goal 是海 && 自己 onland:              # 陆/山→海
        若自己在山地: 复原山地速度（若该兵种在山地减速；开拓不减速）
        chance = (ttime - lst_move_to_land_time + 110) * go_sea_probability / 17700.0
        if 势力3: chance *= 0.666
        if get_chance(chance): 下海（onland=0; speed/=2; rem/=2）   # 不 break（见要点）
        else: 反弹（水平撞→angle=π-angle；垂直→angle=-angle）
    else if onland && goal 是陆地:             # 陆→陆（含山）
        若自己在山地 && goal 非山: 复原山地速度（若该兵种在山地减速）
        若 goal 是山:                          # 山地骰（含山→山）
            enter = mountainEnterChance × 兵种.mountainEnterMult   # 普通/先锋0.5、开拓0.8
            if get_chance(enter):
                若不在山地: inMountain=1; 若该兵种减速: speed×0.5, rem×0.5
            else: 反弹; 跳过攻占
        若已通过 && goal 非己方陆地:           # 敌方阻挡骰（与山地骰独立计算）
            conquer(goal); if 开拓兵: 连占上下左右 4 邻格
            reb = 兵种.bounceMult; if 势力4: reb*=0.6   # 先锋0.4=60% 不反弹；非先锋=1 必反弹
            if get_chance(reb): 反弹
    else if goal 是陆地 && 自己不在陆上:       # 海→陆 登陆
        若 goal 是山: 先掷山地骰（失败→反弹留海，不登陆）
        通过后: onland=1; 复原陆速（speed/0.5, rem/0.5）; lst_move_to_land_time=ttime
        若 goal 是山: 进山（若该兵种减速: speed×0.5, rem×0.5）
        conquer(goal); if 开拓兵: 连占上下左右 4 邻格
x,y 夹取到 [0,Map_x]/[0,Map_y]
angle += 抖动
```

> **细节改进（2026-08，先锋/开拓重置 + 山地碰撞）**：
> - 先锋（bounceMult 0.4）：速度快 + 碰敌方领土 60% 不反弹（继承旧开拓的穿透权）。
> - 开拓（bounceMult 1.0）：**取消**敌方不反弹；碰敌方领土时连目标格上下左右 4 邻格一起占领
>   （固定顺序上→下→左→右，保证势力8 免费兵 RNG 消耗可复现）；山地不减速
>   （`mountainNoSlow`）+ 被山地阻挡概率降低（`mountainEnterMult=1.6` → 进入 0.8）。
> - 山地阻挡先判（失败→反弹，不进入不征服）；敌方阻挡在征服**后**独立掷（反弹=「弹回」，原版语义）。
>   下一格既为敌又为山时两骰独立：非先锋（bounceMult=1.0）必反弹；先锋两骰都过才不反弹。

要点：
- `go_sea_probability` 初始 1，每 tick `+= 1.7/time_to_unify`（`time_to_unify=20000`），随时间游戏越发「海战化」。（**config 现值**：`sea.timeToUnify=40000`；`sea.goSeaIncrease` 为**独立常量** 8.5e-05（=1.7/20000），不再由 timeToUnify 推导。）
- 下海成功时 `speed/=2`、`rem/=2`，**不再 `break`**（2026-08 用户定夺：去掉原版紧随的 `break`，不再丢弃本 tick 剩余移动，下海后续走；速度与剩余量同步减半）。原版 `speed/=2; rem/=2; break;` 里 `rem/=2` 因 `break` 沦为死代码、白白丢半程。
- 登陆时 `rem*=2` 相当于补回额外移动量，方向不变。
- 攻占发生在**每次跨格进入敌方格**（途中一格一格刷领土），`resi<0` 结束点也补一次征服。
- 下海/反弹用的 `get_chance` 每次消耗一个随机数——保持调用次数与位置不变（影响同种子序列）。

### 2.4 碰撞战斗（`find_and_attack`）

- 每跨一格，与**全池**敌方活兵比对：`distance(p,this) < p.size + this.size` → 双方 `kill(0, 对方)`，返回 1（本兵本 tick 移动中止）。
- 双方**同归于尽**；`kill` 无论 `kill_type` 都会触发死亡者自身的类型死亡效果（§2.5）。
- 新版用**空间哈希**（§3.3 SpatialHash）等价替换 O(n²)，但**同一格内只判定一次**的语义要保留（用「本格已处理集合」防重复击杀一兵）。
- 新兵本 tick 是否移动：原版取决于环形池槽位相对循环下标（实现细节，无意义行为）。**新版统一规定：tick 内新出生的兵从下一 tick 才开始移动**（更清晰，且与大多数情形等价）。

### 2.5 死亡与死亡效果（`Army::kill` + 触发条件）

死亡效果**不区分死因**（战斗、爆炸、激光均触发），按死者的 `type` 与势力：

| type | 效果 |
|---|---|
| 3 激光 | 向击杀者方向 `add_effect(..., type2, creator=自身)` 激光；`belongi==5`（绿）时额外 ±π/11 两条（共 3 条）。激光角 = `get_angle(死位, 击杀者位)`。 |
| 4 爆炸 | `add_effect(..., type0)`，半径参数 `belongi==6`（橙）→ 4.08，否则 2.4。 |
| 5 地雷 | `add_effect(..., type1)` 地雷（布设）。 |

> 击杀者可为空？原版 `if(killer==NULL)return;` 已注释掉；战斗/爆炸/激光处均传入非空击杀者。新版本地雷超时爆炸的 `creator_id` 传地雷自身的 creator（即原布设兵）。

### 2.6 特效（`Effect`）规格

通用：`tt = ttime - create_time`（创建当 tick 即参与求解，tt=0；特效绘制见 §2.9）。
> **注（2026-08）**：新版求解前先**快照**特效列表，遍历中新建的特效（如地雷引爆的爆炸）与
> tick 末 `DeathSystem::flush` 产生的特效，均**下一 tick（tt=1）才求解**。原版的 tt=0 是
> 环形槽位依赖行为（`Solve_effect` 按 0..1999 下标遍历 + `effect_tr` 游标），新版已不存在。

**爆炸（type0）**：
- 半径参数 `lsdouble1`（bomb_range）：爆炸兵橙6 → 4.08，否则 2.4；地雷引爆 1.1/1.43（紫7），超时 1.3/1.95（紫7）。
- `r = sqrt(tt+1) * bomb_range`。
- `tt%2==0` 时：征服以 (x,y) 圆心半径 r 内所有格（判定用 `distance(i+0.5, j+0.5, x, y) < r`）；击杀半径内敌方活兵。
- `tt>8` → 消亡。总生命周期 9 tick。

**地雷（type1）**：
- 静态半径 1.4，布设后 `tt>=600`（10s）起每 12 tick 检测：敌方兵距雷 `< r*1.1 + 兵size` → 引爆（bomb_range 紫7→1.43 否则 1.1），雷消失。
- `tt>=3600`（60s）→ 直接爆炸（**2026-08 用户定夺：爆炸半径统一为引爆半径**——紫7→1.43、否则 1.1；原版超时更大 1.95/1.3 的差异已取消）。
- 引爆瞬间 `add_effect(..., type0, creator=布设兵)`。

**激光（type2）**：
- 寿命：绿5 → 33 tick，否则 22。长度：绿5 → 45，否则 30。
- 从 (x,y) 沿 `lsdouble1`（angle）用 `find_next_xy` 逐格延伸；**遇地图边界或「进入非己方陆地」停止**（继续穿过海与己方领地）。
- 每 tick：击杀「到光束线段的垂直距离 ≤ 兵size+0.1」的敌方活兵；光束长度渐进增长，**每 tick 至多 +2**（`length < lsttime_length+2 ? length : lsttime_length+2`），增长时对尖端格 `conquer`。
- 绿5 的 ±π/11 两条同规则（各自独立 angle）。

> **Phase 4 回填（2026-07-31，实现时发现，均以代码为准）**：
> 1. 激光尖端征服**时机相反**：代码是「光束提前停下（`length < lsttime_length+2`，即遇敌领土/边界）时征服尖端格」；自由增长时（`else final_length = lst+2`）**不**征服。上面「增长时对尖端格 conquer」有误，以代码为准。
> 2. 地雷 `solve1` 探测循环**无 break**：多个敌兵在范围内时会对每个敌兵各生成一个爆炸特效（然后雷消失）。（**Phase 9 修**：新版加 `break`，每雷只产生一个爆炸特效；击杀效果与单敌情形一致，仅不再重复生成多个同效爆炸。）
> 3. 爆炸半径两版公式不一致：`solve0` 用 `r = sqrt(tt+1)*bomb_range`（逻辑权威）；`draw0` 用 `r = sqrt((tt+1)*bomb_range)`（原版绘制疑似笔误）。Phase 7 渲染按 solve 版绘制。
> 4. 激光 `goal_map` 默认值 = 特效所在格（`&mmap[(int)x][(int)y]`）；新版因 `Map::at` 无越界哨兵列，夹取到界内（仅影响激光死在精确地图边缘的罕见情形）。

### 2.7 经济与产兵（`solve_economy` + `Init_faction`）

**经济积累（每 tick，每个有城市的势力）**：
```
cr = fcitys / total_citys
at = ttime / time_to_unify
economy += pow(cr + 0.01, 0.45 + at^3 * 0.35) * economy_base * 0.017 * (1 + 2*at)
```
- `economy_base=1`、`time_to_unify=20000`。起始 `economy=1.1`。（**config 现值**：`economy.economyBase=1`、`economy.gainFactor=0.1`（原 0.017）、`sea.timeToUnify=40000`，翻新后调参。）
- 思路.txt 要求：**经济系统与产兵系统分离**。新架构：EconomySystem 只负责经济累积；ProductionSystem 消费经济产兵（见 §3.3、Phase 5）。行为保持不变（下式）。

**产兵（每势力每 tick，6 个类型）**：
```
for type i in 0..5:
    while next_produce_goal[i] <= economy:
        选 fcitys 中 lst_produce_army_n 最小的城市 mini
        无城市 → return
        在 mini 城市 (x+0.5, y+0.5) 产 type i 兵
        （原版池满返回哨兵 → 停止；新版用 maxArmyGuard）
        next_produce_goal[i] += army_cost[i]
        mini.lst_produce_army_n = ++num_army_have_produced
```
- 基础 `army_cost = {1, 3.97, 4.03, 17, 23, 13}`（对应类型 0..5）。
- `next_produce_goal` 初始 = `army_cost[i]`。

> **Phase 9 用户定夺（经济改为留存值 + 公平调度堆）**：economy = **库存**（每 tick 累加收益、
> 产兵扣该兵成本，≥0）。产兵改为维护**最小堆**：元素 `{兵种编号, 单价(=army_cost), 该兵种
> 累计花费}`，**排序键 = 已花费 + 单价**（开局 spent=0 时按单价排 → 先产便宜普通兵占地，
> 而非按类型顺序各产一个；产兵后键值升高 → 兵种随键值平衡而多样化）；每逻辑帧
> `库存 ≥ 堆顶单价` → 出堆产该兵、库存扣单价、累计花费 +单价再入堆，重复直至库存 < 堆顶单价。
> 实测 seed42/7/123 六类型均现、经济≥0；总产兵量受预算约束（比原版累计模型少，符合"留存值"
> 认知）。实现：`ProductionSystem::produce` + `Faction.producedCost`。

### 2.8 势力征服（`conquer/insert_city/remove_city`）

- `conquer(x,y)`：越界忽略；同势力忽略；若 `city`：旧主 `remove_city`、新主 `insert_city`，且**势力8** `get_chance(0.6)` 免费产普通兵于 (x+0.5,y+0.5)（**init 阶段除外**：`ConquerContext.freeArmyEnabled=false` → 无开局免费兵，见 §1.4）；若 `land`：旧主 `flands--`、新主 `flands++`、`belongi=新主`。（**势力0 landCount 初始 = 无主领地数**，随征服递减至 0，2026-08 用户定夺。）
- `insert_city`：`mmap[x][y].city` 为真、`id∈[1,8]`、去重后追加到 `citys`。
- `remove_city`：找到后与末位 `swap` 再 `fcitys--`（**顺序无关，原版用 swap**）。
- 城市列表新版用 `std::vector<CityRef>`（无 1000 上限）。

### 2.9 渲染规格（SDL 复现基准）

坐标变换（原版精确移植）：
- `toscreenx(x) = x*15 + 600`；`toscreeny(y) = (95 - y)*15`。窗口 2175×1425。
- 背景黑（`ClearDrawScreen` 清黑 → 海即背景黑）。

**地图**：每格 15×15：
- 海：原版 `DrawBox(x,x 同点, …)` 为**零宽空操作**，实际显示为背景黑 → 新版直接填黑即可（视觉等价）。
- 陆地非城市：`mix_color(势力色, 白(255,255,255), 0.6)`（rate 为**第一色占比**）。
- 城市：`mix_color(势力色, 黑(0,0,0), 0.8)`。
  > **P5 改版（有意视觉变化）**：城市不再填实心暗格，改为**陆地基色 + 线条城贴图**
  > （`data/city.png`，tint 为 `mix_color(势力色,黑,0.85)` 略深）；山格再叠加线条山贴图
  > （`data/mountain.png`，tint `mix_color(势力色,黑,0.08)` 近黑），山下城上。见开发计划 P5。
- `mix_color` 逐通道 `c1*rate + c2*(1-rate)`，`RGB_COLOR` 为 `0xFF000000|r<<16|g<<8|b`。

**兵**：`army.png` 256×256，8 列 × 8 行 32×32 子图。`army_image[type][faction-1]` = 行 type、列 faction-1（DxLib `LoadDivGraph` 按行优先，`序号 = type*8 + (faction-1)`）。绘制：以 `(toscreenx, toscreeny)` 为中心，48×48 拉伸，**启用 alpha**（`TransFlag=TRUE` → SDL `SDL_BLENDMODE_BLEND`），**不翻转**。第 6、7 行子图供激光特效复用（见下）。

**特效**：
- 爆炸：半透明圆，`半径 = r*15`，`alpha = (9-tt)/9*255`，填充色 = 势力色。
- 地雷：`army_image[5][faction-1]` 48×48；`tt>=600` 且 `tt%12 ∈ {0,1,2,10,11}` → alpha 220，否则 alpha 60（闪烁）。
- 激光：`army_image[6][faction-1]` 以 `(toscreenx,toscreeny)` 为中心、缩放 1、`角度 = get_rand_angle()` 随机旋转（每帧换角度的“火花”）；`army_image[7][faction-1]` 用 `DrawRotaGraph3(x, y, cx=16, cy=0, ExtRateX=0.5, ExtRateY=15*final_length/32, Angle=-angle-π/2, TransFlag=TRUE)` —— 即**以图像上边中点 (16,0) 为旋转中心**，横向 0.5（宽 16px）、纵向 `15*final_length` px，旋转角 `-angle-π/2`（DxLib 正角=顺时针，屏幕 y 向下）。
  - SDL 等价：`SDL_RenderCopyEx(tex, rect, center=(16,0), angle_deg=(-angle-π/2)*180/π, flip=无)`。**视觉处理（Phase 8 反馈）**：光束贴图是「白核+势力色边缘」实心条带，原版 alpha 混合下边缘色压进白色火头内部 → 新版改为**分层**：光束先画、火花（BLEND）盖在其上（白色头部盖住光束顶缘描边）。曾试 ADD 发光风格，但本机 direct3d 渲染器在 logical-size 下 ADD 静默失效（`RenderCopyEx` 返回 0 无错误却什么都不画，探针实测）→ 回退 BLEND。绿势力三束同源，按 entity 创建序迭代中心束最后画（交汇处基本被火花遮盖）。

**排行榜面板**：原版 `DrawFormatString(0, 1070+i*44, color, "%d: land:%d town:%d")`，字体 40，8 行，按 `flands` 降序（`ranked_fact`）。新版用 **ImGui 面板**呈现（左栏），样式与内容一致。原版面板在窗口左侧（x<600）区域、y 从 1070 开始（地图下 2/3 处），新版 ImGui 放左侧栏即可，不要求逐像素一致。

**截图**：加 F12 保存当前帧 PNG（便于与原版 exe 对拍）。

### 2.10 主循环与时间基准（`Solve`）

原版每渲染帧依次：
```
UpdateKeys → Solve_army → Solve_faction → Solve_effect → Draw → ESC双击暂停 → ttime++ → go_sea_probability += increase
```
- `ttime` 即逻辑帧计数（60fps 下 1 tick = 1/60s）。特效定时（600=10s、3600=60s）以 tick 计。
- ESC 暂停：原版是**阻塞**等第二次 ESC。新版改为非阻塞状态机（ESC 双击=暂停/继续，并加空格暂停）。

新版固定步长（见 §3.7）：模拟每 1/60s tick 一次，顺序同上；渲染独立帧率。

### 2.12 关键数学工具（`useful_tools.cpp` 原样移植）

- `get_chance(p)`：`GetRand(9999999)/10000000.0 < p`。
- `get_rand_angle()`：`GetRand(14447-1)*π*2/14447`（离散化到 14447 档）。（**Phase 9 改**：新版 `MathUtil::getRandomAngle` 用连续均匀 `[0,2π)`，`kRandAngleMax` 仅留历史注记。）
- `get_angle`、`distance`、`mix_color`：直接照抄。
- `find_next_xy(x, y, angle, remlength)`：返回本次移动先撞到的网格边界方向并更新位置/余长：
  - 返回 0/2 = 水平边界（x1/x2），1/3 = 垂直边界（y1/y2）；更新 `x/y` 至该边界，`remlength -= res`。
  - 返回 `-2`：`rem > remlength`，整段走完（`x += rem*cos, y += rem*sin, rem=0`）。
  - 返回 `-3`：两个方向边界距离相等（撞角）→ `angle += π + 4*kEps` 反向，不动位置（2026-08 用户定夺；原版为随机角 + 返回 -1）。调用方：兵 `continue` 继续移动、激光 `<0` 即停。微小偏置打破格心对称，防止重复撞角卡死。（**含 `|x1-x|<eps → x1--`、`|y1-y|<eps → y1--` 的 eps 前处理。**）
- `point_distance_from_segment`（激光用，两版本照抄）。

> 这些纯函数是单元测试重点，必须逐分支覆盖（见 Phase 1）。

### 3.2 设计原则

1. **行为以代码为准**（D2）；思路.txt 的改进要求必须落实。
2. **模拟/渲染严格解耦**：`Simulation` 零 SDL/平台依赖；渲染层只读 Simulation 状态。这是无头/回放的前提。
3. **无全局可变状态**：一切状态归 `Simulation`；系统通过参数接收 `Simulation&` 或内部上下文。
4. **确定性**：所有随机来自注入的 `Rng`；`(seed, config, map)` → 结果唯一可复现。
5. **固定逻辑步长 60Hz**：`ttime` = 逻辑 tick；渲染独立。
6. **魔法数字外置**：全部进 `config.json`；代码中禁止散落业务字面量（仅数学常量 π、容差等除外）。
7. **现代 C++20**：entt、spdlog、nlohmann、gtest；消灭 `gpt`/`RGB_COLOR` 宏（用 range-for/constexpr）。
8. **UTF-8 无 BOM**，注释保留中文；文件内不混 GBK。
9. **不搬运死代码**（dialogue/font）。
10. **性能**：空间哈希碰撞；无固定池上限（`maxArmyGuard` 兜底）。
11. **可扩展点**：单位/势力/特效以 config 数据驱动；模拟状态可序列化（为存档/回放/联机铺路）。

### 3.3 ECS 设计

**实体**：
- **兵**：`Position{x,y}` + `Velocity{angle}` + `Speed` + `OnLand` + `FactionId` + `UnitType` + `Collider{radius}` + `LandHistory{lastLandTime}`。
- **特效**：`Position` + `FactionId` + `EffectType` + `EffectTimer{createdTick}` + `EffectParams{angle,length,lastLength,radius}` + `Creator{entt::entity}`。
- **地图格 / 城市 / 势力**：**不进 ECS**。地图是稠密 105×95 网格（`Grid` 结构），城市归 `Faction` 的 `std::vector`，与类型/语义匹配且查询更简单（这是一个有意的设计取舍，执行时不要强行 entt 化）。

**系统**（每 tick，顺序 = 原版 §2.10）：
1. `MovementSystem` + `CombatSystem`（`Solve_army`）
2. `EconomySystem` + `ProductionSystem`（`Solve_faction`，含回合顺序随机化）
3. `EffectSystem`（`Solve_effect`）
4. （渲染阶段）`MapRenderer/ArmyRenderer/EffectRenderer/PanelRenderer`（`Draw`）

**死亡处理**：战斗/爆炸/激光把实体标为「待销毁 + 记录死亡事件（含击杀者）」，`DeathSystem` 在当 tick 结束时统一销毁并生成死亡效果。避免遍历中销毁实体。

**空间哈希**：以地图格（105×95）为桶；每 tick 重建一次桶索引；战斗查询只查所在格及 8 邻域。半径碰撞仍用精确 `distance < sum(radius)`（与激光用 `point_distance_from_segment`）。

### 3.4 数据流

```
main → App/Headless
  App:  Init SDL → 构造 Simulation(config, seed) → 固定步长循环 { Input → sim.Tick() → render(sim) }
  Headless: 构造 Simulation → 循环 N 次 sim.Tick() → 输出摘要
Simulation.Tick(): rng → Movement/Combat → Economy/Production → Effect → ttime++
render(sim): 只读 state → 画地图/兵/特效/面板
```

### 3.6 随机数策略（`Random.h`）

- `class Rng { std::mt19937 mt; }`。
- API：`int get(int n)` → [0,n]（镜像 `GetRand`）；`bool chance(double p)`；`double angle()`（[0,2π) 离散化到 14447 档可选）；`void seed(u32)`；`std::string state()` / 可恢复。
- **同种子确定性**是新引擎的承诺；与原版 GetRand 序列不要求一致（技术不可行，DxLib xorshift 内部未知）。
- RNG 调用**位置与次数**在每次代码修改后必须保持不变（含 init、conquer、move、effect），否则同种子结果漂移。用 Phase 6 的「同种子回归」测试锁住。

### 3.7 固定步长（`TimeControl`）

- 模拟步长 1/60s；`ttime++` 每步一次。渲染独立，可 60/120/144Hz。
- 倍速：每帧渲染前按倍速累积运行 `speed×` 次 tick（或按真实时间累积）。暂停时不 tick。
- 速度与暂停只影响渲染节奏，**不改变模拟状态**（保证确定性回放成立）。

   - **根因（探针隔离定位）**：SDLRenderer2 后端渲染 ImGui 前调用 `SDL_RenderSetViewport(renderer, nullptr)`。当窗口纵横比与逻辑画布(2175×1425)不一致时，SDL 用 **letterbox 视口**（逻辑坐标，含居中偏移，如 16:9 下 `(179,0,2174,1424)`）实现内容缩放；`nullptr` 重置把视口变成逻辑空间全窗口 `(0,0,窗口/scale)`（比画布宽）→ ImGui 几何丢到 letterbox 偏移处渲染 → 渲染位置与输入命中区错位。窗口纵横比匹配时偏移=0 不受影响（非最大化正常）；逐渐改变窗口大小 → 偏移逐渐变化 → 交互逐渐跑偏。
   - 输入侧实测一直正确（`io.MousePos` 在各窗口尺寸/letterbox 下均与光标逻辑位置一致），纯渲染位置问题。
   - **修复**：本地补丁 `imgui_impl_sdlrenderer2.cpp`，`SetupRenderState` 不再重置视口（保留 SDL 默认 letterbox 视口；本应用渲染循环从不自定义视口）。clip reset 无害保留。
   - 验证（探针，非目测）：16:9 letterbox 窗口下渲染面板 → 光标到逻辑 (100,100)/(300,700)（面板内）`WantCaptureMouse=true`、(1000,100)（面板外）`false`，与匹配纵横比一致。
9. **兵点选交互区（第二轮反馈「缩小好点/放大交互区不变大、交互区在显示区上方」）**：
   - **根因**：① 阈值 = `drawSize/(2*cellPx)` = `1.6/zoom`，随缩放反变（缩小交互区巨大、放大不变大）；② 点选用兵的世界坐标，未计渲染的 +16 y 偏移（sprite 实际画在逻辑位下方 16px）→ 交互区偏在显示区上方。
   - **修复**：`Application::pickSelection` 改**屏幕空间点选**——锚点 = sprite 绘制中心 `(toScreenXi(x), toScreenYi(y)+off)`，`off = spriteSize/2*zoom`；阈值 = sprite 屏幕半宽 `armyDrawSize*zoom/2`，随缩放与视觉同比。`ArmyRenderer` 魔法数 16 → `spriteSize()/2`（32/2=16，派生值），渲染逻辑不变。
   - 验证（探针）：各缩放档 `half` 恰为 sprite 屏幕尺寸一半、中心命中、超出半宽不命中。
10. **兵种视觉半径（第三轮反馈「点到普通兵空白区也选中」）**：
   - 问题：不同兵种贴图视觉大小不同（army.png 子图占位相近），统一半格阈值(24px)会点到邻近普通兵的空白区。
   - **方案决策**：外置到 `data/config.json` 的 `units[].visualRadius`（**数据驱动表，开发时算一次**）。理由：与 §3.2「魔法数字全进 config.json」一致、显式可调可单测、运行时不跑图片分析（避免"什么是视觉"的阈值歧义）；新增兵种只需在表里加一行。
   - 量法：`tools/measure_visual_radius.cpp`（SDL_image 加载 army.png，每兵种取各势力子图，可见像素到子图中心的最大距离 × 绘制缩放 48/32=1.5，跨势力取最大）。量得：普通12/先锋13/开拓16/激光25/爆炸22/地雷17（各势力同型一致）。更新 army.png 后重跑工具写回 config。
   - 实现：`Config::Unit` 增 `visualRadius`（解析/序列化对称，快照往返无损）；`pickSelection` 用 `ratio = 距离/(visualRadius*zoom)` 取最小者且 <1 命中（选"光标相对其视觉最居中"的兵）。
- 验证：`ctest` 全绿；`--seed 42 --ticks 200 --screenshot` 截图中合并左栏满全高、中文正常、单字势力名、帮助行完整、右栏无遮挡。

## 6. 风险与注意点

1. **BMP 朝向**（最高危）：原版自底向上 + 屏幕 Y 翻转；用黄金数据锁死，防「图上下颠倒」。
2. **`find_next_xy` 撞角/eps 细节**：分支多且隐蔽，必须逐分支单测。
3. **随机调用顺序漂移**：新增/删除任意 `rng` 调用都会改变同种子结果；确定性回归测试兜底。
4. **特效绘制参数**：`DrawRotaGraph3` 旋转中心/角度约定与 SDL 不同 → 视觉对拍为准，不做数学强求。
5. **速度语义**：新引擎逻辑步长 60Hz 才与「600=10s」等价；渲染 fps 与逻辑解耦后不要用真实时间算特效 `tt`。
6. **原版怪癖保留（2026-08 现状）**：`resi<0` 时的征服、海格绘制零宽（视觉=黑）——不要「修好」它们，除非用户明确要求。（下海 `rem/=2` 死代码、地雷引爆 vs 超时半径差异已于 2026-08 按用户定夺移除/统一。）
7. **势力8 初始化免费兵**：发生在 init 阶段（§1.4 顺序），遗漏会改变初始局面抽样。
8. **`maxArmyGuard`**：只作防跑飞保险，默认远超正常量级，不得成为实际瓶颈。
