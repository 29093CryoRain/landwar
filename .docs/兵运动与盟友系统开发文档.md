## 1. 范围

本轮做三件事：

- **兵运动规范**：把"不可占领格"从"只有海洋"推广为"每个兵各自判定"，并统一落地规则 1/2/3。
- **盟友系统**：盟友是等价关系；全战场"友 / 敌"判定收敛到唯一入口；主菜单可选联盟；排行榜标注联盟。
- **科技「密集防御」**：普通兵失去征服敌方地图格的能力，造价 -50%。
- **盟友边界闸门**（B6，盟友系统的后续修订）：仅盟友系统暴露出的问题——己方小飞地被盟友领土
  完全围住时，己方兵在内侧永久反弹、大量单位滞留，影响体验与性能。为每个兵维护一个 CUSUM
  统计量检测"持续受压"，报警后放行一次；详见 §12。

不做（本轮明确排除）：

- 战场迷雾 / 联盟视野（`.docs/长期思路.txt`「战场迷雾系统」依赖盟友，但独立立项）。
- 动态结盟 / 解盟 / 外交 AI：盟友只在开局菜单设定，一局内不变。
- 其余长期思路条目（关卡、野化、技艺、新兵种等）。

## 2. 现状（代码事实）

三条事实决定了本方案的形状。

1. **"同势力 = 友、其它 = 敌"硬编码在多处**，目前没有盟友概念：

| 位置 | 现状判定 |
|---|---|
| `MovementSystem::processEnteredCell`（陆→陆） | `goalCell->belongi != fid.value` → 征服 + 掷反弹 |
| `Faction::conquerIndex`（`conquerOne`） | `&oldOwner == this` → 跳过 |
| `Systems.h::conquerAtIndex`（统计口径） | `belongi != factionId` → 记占领 credit |
| `CombatSystem::checkAt`（近战） | `otherFaction.value == fid.value` → 跳过 |
| `ProjectileSystem::hitEnemyAt`（子弹） | `FactionId(a).value == fid.value` → 跳过 |
| `CombatEffectSystem::solveBomb` / `solveMine` / `solveLaser`（击杀） | 同上 |
| `CombatEffectSystem::solveLaser`（地形停止） | `gc.land && fid.value != gc.belongi` → 停止延伸 |

2. **海洋是唯一的"不可占领格"**：`MovementSystem::processEnteredCell` 现按（原格海/陆）×（目标格海/陆）
   分成三个分支——海→海直行、陆→海掷下海骰、海→陆登陆 + 征服。规则 1/2/3 事实上已由这套分支实现，
   只是被写死成"海洋专属"。

3. **科技一个等级只能带一条 Buff**：`Config::Tech::TechDef::Level` = `BuffDef`（单条），
   `Buff.cpp::techBuffs` 只取当前级那一条，`Application::drawTechResearchModal` 也按"单条旧值 → 单条新值"
   渲染。而「密集防御」是"机制 + 数值"两个效果。

## 3. 术语与唯一入口

- **友方**：同一势力，或互为盟友。
- **敌方**：不同势力且非盟友。**中立（势力 0）与任何非盟友仍算敌方**（保持现状 `!=` 语义：中立土地照旧可征服）。
- **可占领 / 不可占领**：对"某势力 + 某兵种 + 某格"三元组而言。

新增纯头文件 `src/sim/ConquestRules.h`（与 `sim/systems/Systems.h` 的共享辅助同风格：只放判定，不放状态），
作为**唯一入口**：

```cpp
namespace lw {

// 盟友关系：a != b 且同属一个联盟（allianceId >= 0）。越界 / 自身 / 无联盟 → false。
bool areAllied(const std::vector<Faction>& factions, int a, int b);

// 敌我：a != b 且非盟友（中立 0 与任何非盟友仍为敌，保持现状语义）。
bool areEnemies(const std::vector<Faction>& factions, int a, int b);

// 势力 factionId 的 unitType 兵能否占领 index 格。
// unitType < 0 = 不施加兵种机制限制（仅保留海与盟友两条）。
bool canConquerCell(const Map& map, const std::vector<Faction>& factions,
                    int factionId, int unitType, int index);

}  // namespace lw
```

`canConquerCell` 真值表：

| 格 | 结果 |
|---|---|
| 海 | `false` |
| 己方陆（含山） | `true`（占领是 no-op） |
| 盟友陆 | `false` |
| 中立陆 | `true` |
| 敌方陆，兵种无「禁征服」 | `true` |
| 敌方陆，兵种有「禁征服」 | `false`（密集防御，见 §6） |

**所有征服路径必须过它**；新增征服来源时不得另写判定。需要改造的调用点见 §5.2、§6.4。

## 4. 兵运动规范

### 4.1 三条规则

对一次跨边（`crossEdge` 返回边序号 → 进入目标格）：

1. 目标格不可占领、原格也不可占领 → **不反弹、匀速直线进入**；不征服。
2. 目标格不可占领、原格可占领 → **反弹，不占领**。
3. 目标格可占领、原格不可占领 → **占领目标格、不反弹**，匀速直线进入。

### 4.2 海洋闸门（已定）

**海自成一套闸门，不参与规则 1/2 的"不可占领"分流**：只要目标格是海，一律走现有下海骰——
成功入海（不征服，因为海不可占领）、失败反弹；海→海仍直行；海→陆仍登陆 + 复原陆速 + 征服（= 规则 3）。
规则 1/2/3 从此只作用于**陆地目标**。

理由：陆地单位不应"走进海里"，任何陆地→海都应过概率闸门；且这是改动最小、RNG 消耗与现状逐位一致的做法。

> 若不加此限定，会出现反直觉行为：兵从海进入盟友领地后，再从盟友陆走向海，
> 会因"原格与目标格都不可占领"而**必然入海**，绕过下海概率。

### 4.3 与地形规则的边界

河骰、山骰、下海骰是**地形规则**，判定顺序与现状一致（河 → 山 → 归属）；本规范只替换其中"领土归属"那一步。

- 原格不可占领、目标格是山：仍掷山骰（这是地形规则，不是"占领反弹"）；山骰失败导致的反弹是地形结果，
  不违反规则 1。
- 河骰仍在最前，失败即反弹、不进入（现状不变）。

### 4.4 分支行为表

| 原格 | 目标格 | 行为 |
|---|---|---|
| 可占领陆 | 海 | 掷下海骰：成功入海（减速、不征服），失败反弹（现状不变） |
| 不可占领陆 | 海 | 同上（海洋闸门优先；失败反弹回原格） |
| 海 | 海 | 直行；速度不变（现状） |
| 海 | 可占领陆 | 登陆 + 复原陆速 + 征服（规则 3；目标为山先掷山骰）（现状） |
| 海 | 不可占领陆（盟友 / 禁征服敌土） | 登陆 + 复原陆速；不征服、不反弹（规则 1） |
| 可占领陆 | 己方陆 | 无占领动作；不掷反弹（现状） |
| 可占领陆 | 可占领的敌 / 中立陆 | 征服 + 掷 `bounceMult × mods.bounceChanceMult` 反弹（现状） |
| 可占领陆 | 不可占领陆 | 规则 2：不征服、不掷反弹、**确定反弹**（不乘 `bounceMult`） |
| 不可占领陆 | 可占领陆 | 规则 3：征服、不掷反弹、继续前进 |
| 不可占领陆 | 不可占领陆 | 规则 1：不征服、不反弹、继续前进 |

### 4.5 实现要点

- 保留 `processEnteredCell` 现有陆 / 海分支结构；只把"征服 + 掷反弹"那一步替换为
  `srcOk` / `dstOk` 分流（`srcOk = canConquerCell(..., srcIdx)`、`dstOk = canConquerCell(..., goalIdx)`）。
- `conquerCell` 只在 `dstOk` 时调用；规则 1/2 分支**不消耗 sim RNG**（海分支的下海骰照旧）。
- 统计口径：`Systems.h::conquerAtIndex` 的 `landChanged` 必须先过 `canConquerCell`，
  避免"被拦下却记了占领 credit"。
- `Faction::conquerIndex` 是最后一道总闸：`conquerOne` 对目标格与原格（`ConquerContext.originIndex`）
  都过 `canConquerCell`。`ConquerContext` 增加 `attackerUnitType`（`conquerAtIndex` 填入；
  `Simulation::conquerIndex` / 首都初始化传 `-1` = 不施加兵种限制）。
- "匀速直线"= 不改变方向、不反弹、剩余步长照走；**地形速度切换照旧**（下海 `×seaSpeedMult`、
  登陆复原、进 / 出山缩放）。

## 5. 盟友系统

### 5.1 数据（SSOT）

- 在 `Faction` 上新增 `int allianceId = -1;`（`-1` = 无联盟；否则联盟序号 `0..K-1`）。
- **不新增并行容器**：`Faction` 已经传遍 `MoveContext.factions` 与 `ConquerContext.factions`；
  `areAllied` 只读这一个字段，避免"成员表 + 映射表"双簿记。
- 等价关系由"同号"天然保证（自反 / 对称 / 传递），不需要并查集；成员 = 遍历势力取同号者。
- 不变量：`allianceId >= 0` 的势力必须是本局选入势力；中立势力 0 恒为 `-1`。
- 唯一写入点：`Options.alliances` 在 `Simulation::initFactions` 的选入循环里写入（**必须在征服首都之前**，
  否则首都初始化征服看不到联盟）。

### 5.2 触发点全表

| 行为 | 位置 | 改法 |
|---|---|---|
| 兵不占领盟友格 | `MovementSystem`（见 §4） | `canConquerCell` 分流；盟友目标走规则 1/2 |
| 兵碰友军不攻击 | `CombatSystem::checkAt` | `otherFaction.value == fid.value` → `!areEnemies(...)` |
| 子弹不杀友军 | `ProjectileSystem::hitEnemyAt` | 同上 |
| 爆炸不占友土、不杀友军 | `CombatEffectSystem::solveBomb` | 征服已走 `conquerAtIndex` 总闸；击杀改 `!areEnemies` |
| 地雷不探测友军 | `CombatEffectSystem::solveMine` | 同上 |
| 激光不杀友军 | `CombatEffectSystem::solveLaser`（击杀段） | 同上 |
| 激光穿过盟友领土 | `CombatEffectSystem::solveLaser`（停止条件） | `fid.value != gc.belongi` → `areEnemies(fid.value, gc.belongi)` |
| 城市不跨盟友易主 | `Faction::conquerIndex` / `allBaseCellsOwned` | 由 `canConquerCell` 总闸保证；`allBaseCellsOwned` 不改 |
| 统计不记盟友占领 | `Systems.h::conquerAtIndex` | 见 §4.5 |

说明：中立土地仍可被征服；激光仍会在进入中立陆地时停止（`areEnemies(fid, 0) == true`），
与现状一致。

### 5.3 主菜单联盟选择

在 `Menu.cpp::drawMainScreen` 的"势力配置"区内新增"联盟配置"：

- 列表式：初始为空；"增加联盟"按钮追加一个空联盟行。
- 每个联盟行有"添加势力"按钮，弹窗只列出**已加入本局且未加入任何联盟**的势力
  （势力名按势力色渲染，复用现有添加势力弹窗的交互）。
- 每个成员可单个移除；联盟可整体移除（成员回到"无联盟"）；联盟可改名（可选，默认显示"联盟 N"）。
- 约束（保存时由 `Options::validate` 兜底）：势力必须已在本局；每个势力至多属于一个联盟；
  无联盟 = 与所有人敌对。
- 尺寸经 `ui::scaled()`；颜色经 `ui::factionColor` / `drawFactionName`（不手写 `ImVec4`）。

### 5.4 排行榜：势力榜与联盟榜分为两个面板

`LeaderboardPanel` 增加 `Mode{Faction, Alliance}`，`Application` 注册两个实例，主面板「面板」区各一个开关：

- **排行榜(势力)**：`id="leaderboard"`，标题"排行榜(势力)"，默认可见（同拆分前）；列
  `名次/势力/领地/城市/兵力/科技/最高城/经济每秒/科技每秒`，只列本局选入势力。
- **排行榜(联盟)**：`id="leaderboard_alliance"`，标题"排行榜(联盟)"，**默认隐藏**（避免与势力榜叠在
  同一默认位，从主面板打开）；列 `名次/成员/领地/城市/兵力/经济每秒`。
  - 一行 = 一个联盟（同一 `allianceId` 的势力）；**未入盟势力也作为"单势力联盟"参与排名**。
  - 聚合列按成员求和；名次按领地降序 → 城市降序 → 首个成员 id 升序（同值与势力榜同口径）。
  - 渲染按需求："除势力名以外，全部用白色"——成员名用 `drawFactionName` 着色，`、` 与数字用固定白色。
- 未持久化位置的可移动面板在 `PanelManager::draw` 里按出现顺序**错开 24px** 级联，避免默认位完全重叠。

### 5.5 持久化与快照

- **`Options`**：新增 `std::vector<std::vector<int>> alliances;`（每个元素 = 一个联盟的成员势力 id 列表）。
  - `options.json` 读写与现有 `factions` / `map` / `panels` 键严格对称（缺键回退空 = 无联盟）。
  - `Options::validate` 增加：成员必须在本局 `factions` 内、不得跨联盟重复。
- **快照**：`allianceId` 影响模拟，必须入档。建议在 `Snapshot` 根节点新增 `allianceIds`
  （长度 = `factionCount`，`-1` = 无联盟），在 `serialize` / `deserializeInto` 各补一处，
  并把键加入 `Snapshot.cpp` 的已知键校验列表。
- 快照采用严格匹配策略：新增字段后旧档不再兼容，符合项目现行口径。

### 5.6 确定性

- 无联盟（默认）时 `areAllied` 恒 false、`areEnemies` 等价于 `a != b`、`canConquerCell` 等价于
  "陆地且非己方则占"——**与今天逐位一致，语义基线 hash 不变**。
- 盟友判定是纯布尔、无 RNG；联盟只改变分支走向，不改变 RNG 调用次数（规则 1/2 分支不掷骰，见 §4.5）。
- `alliances` 属于 `Options`，已经在模拟键 `(mapSeed, seed, config, map, options)` 之内。

## 6. 「密集防御」科技

### 6.1 效果与表示

需求原文：**普通兵失去征服敌方地图格的能力，但造价 -50%**。

- 机制：新增 `BuffType::UnitNoEnemyConquer`（`param` = 兵种下标或 `-1` = 全兵；算子 = 特性 ✓；
  `magnitude` 忽略，约定写 `1.0`）。
- 落点：`FactionMods` 新增 `std::array<bool, kArmyTypeCount> noEnemyConquer{};`；
  `computeMods` 中 `param` 命中的兵种置 `true`。
- `canConquerCell` 读 `factions[fid].mods.noEnemyConquer[unitType]`，**仅对"敌方"生效**
  （`owner > 0 && owner != fid && !areAllied`）——中立土地仍可征服。
- 文案：`BuffKind` 增加 `Feature`（`kindOf`）；`buffValueText` 对特性返回固定短语
  （如"失去敌方占领"），不输出百分比。

### 6.2 一等级多效果：`levels` 格式（已定：方案 A）

现状 `TechDef::levels` 是 `std::vector<BuffDef>`（一级一条），而「密集防御」一级需要两条。
**已定采用方案 A**：`levels` 改为 `std::vector<std::vector<BuffDef>>`（一级 = 一组效果）。改动面：

- `Config.h`（`TechDef`）、`Config.cpp`（解析 / `toJson` / 校验）；
- `Buff.cpp::techBuffs`（该级全部 buff 依次追加）；
- `TechSystem::applyTech`（行军重缩放遍历该级全部 buff）；
- `Application::drawTechResearchModal`（逐条效果渲染"旧值黄 → 新值绿"）；
- `data/techs.jsonc`（**现有全部科技**的 `levels` 改成嵌套数组）；
- `tests/test_tech.cpp`、`tests/test_buff.cpp` 与配置往返单测。
- 好处：任何"机制 + 数值"组合都能表达，后续科技（掠夺、涅槃重生等）不再受限。

### 6.3 数据文件

`data/techs.csv` 追加一行：

```csv
dense_defense,密集防御,造价/占领
```

`data/techs.jsonc` 的 `techs` 数组追加（按方案 A 的嵌套格式）：

```jsonc
{
  "id": "dense_defense",
  "levels": [
    [
      {"type": "UnitCostMult", "param": "normal", "magnitude": 0.5},
      {"type": "UnitNoEnemyConquer", "param": "normal", "magnitude": 1.0}
    ]
  ],
  "preferenceUnits": ["normal"]
}
```

单级科技（`levels` 长度为 1）。`desc` 定为"造价/占领"；`preferenceUnits` 按"非全兵种科技"规则给
`normal`（AI 偏好 +0.5 / 级）。

### 6.4 挂接点

- `BuffType` 枚举 + `buffTypeName` / `buffTypeFromString`（`Config.cpp`）；
- `FactionMods.noEnemyConquer` + `computeMods` 一个 `case`；
- `canConquerCell`（§3）读取。

其余不动：征服总闸 `Faction::conquerIndex` 与运动分流都已走 `canConquerCell`。
实施后自查遗漏判定：`grep -rn "value == fid\|value != fid\|belongi != \|belongi == " src/`。

### 6.5 基线影响

**本批实现后语义基线 hash 不变**（实测）：`TechSystem::availableTechs` 的候选集虽多了一条科技，
但 AI 触发科研需要攒满阈值（默认 `thresholdBase=100`、`pointsPerCityLevel=0.005`，1 级城约 2 万 tick），
而语义基线只跑 2500 tick，AI 尚未取得任何科技 → 走向不变。

若以后调快科技节奏（或在基线里延长 tick 数），新增科技会改变 AI 的随机科研结果 → 基线漂移。
届时按 `.docs/工程规范.md` §3 流程更新：

1. 重跑 `landwar_tests --gtest_filter='Determinism.Baseline*'` 取新 hash；
2. 更新 `tests/test_baseline.cpp` 期望值，并在提交信息说明原因。

## 8. 测试计划

新增 / 扩展单测（全部无头可跑）：

- `ConquestRules`：三个函数的真值表（含中立、越界、`unitType < 0`、有 / 无禁征服）。
- 运动规范：规则 1/2/3 各一条；海洋闸门（原格不可占领 → 海，成功入海 / 失败反弹）；
  海→盟友陆登陆但不征服；盟友陆→敌陆（规则 3）征服且不掷反弹；山骰与规则 1 并存。
- 密集防御：普通兵不占敌格但占中立格；造价 ×0.5；碰敌直接反弹（原 `bounceMult=1.0` 必反弹，现不掷骰）。
- 盟友战斗：近战互不伤害；子弹 / 爆炸 / 地雷 / 激光不伤友军；激光穿过盟友领土但在敌 / 中立陆地停止；
  爆炸不占盟友格。
- 城市：盟友占满城市基建格不触发整城易主。
- 等价关系：三势力同号互盟；两联盟之间互不友好；无联盟者与所有人敌对。
- Options 往返：`alliances` 读写对称；`validate` 拒绝重复入盟与未选势力。
- 快照往返：含联盟的 `allianceIds` 存读一致，读档后继续 tick 与直跑一致。
- 基线：B1/B2 后 hash 不变；B5 后按 §6.5 流程更新。
- 盟友边界闸门（B6）：`isAlliedLand` 真值表；被困单位反复撞边界 → 报警后放行一次（不反弹、
  不征服）并清零；泄漏项乘步长（同一次反弹、同初值，步长越大统计量越低）；直接穿过盟友领土
  与盟友领土内部的河/山反弹不喂养闸门；敌方反弹不喂养；1 格飞地被盟友全围 → 有限 tick 内脱困；
  快照 `allyGate` 往返一致且缺字段被拒；无联盟时语义基线 hash 不变。

## 12. 盟友边界闸门（B6）

**问题**：盟友规则 2（目标盟友陆、原格可占领 → 确定反弹）对"己方领土被盟友领土完全围住"的
小飞地是致命的：飞地内的己方兵每次撞边界都被弹回，`V_i ∪ ⋃盟友V_j` 内又不含可占领格，
于是永久滞留。数量一多既拖累体验也拖累性能。

**目标**（`.docs/包围检测.md` §6 的 G1/G2/G3）：平时边界像墙；对被围死的单位一定放行；
判据与单位寿命、兵速无关；不把"路过边境带时的短促连撞"误判为被困。

### 12.1 状态量与更新律

每兵一份 `comp::AllyGate.cusum`（CUSUM / 漏桶统计量 `S`），每 tick 更新一次：

```text
S ← max(0, S − (leakPerCell + tolerancePerCell) × 本 tick 步长) + 本 tick 盟友边界反弹数
```

- **观测 = 盟友边界反弹数**。"盟友边界尝试"的定义：目标格是**盟友陆地**、且原格**不是**盟友陆地
  （即从外部试图进入盟友领土）。无论这次反弹由哪条规则造成——河骰失败、山骰失败、还是盟友规则 2
  的确定反弹——**都计入**（用户口径）；反弹可能在一次移动中发生多次，逐次 +1。
- **不计入**的情形：规则 1/3 的**直接穿过**（原格也不可占领 → 直行；目标可占领 → 不反弹）；
  原格已是盟友陆地时在盟友领土**内部**的河/山反弹；敌方 / 中立 / 地图边界上的反弹。
- **泄漏项乘本 tick 步长**（≈ 该兵速度；有 `moveCarry` 过河停顿时用结转步长）→ 判据按
  "每格尝试次数"计，与兵速无关（`.docs/包围检测.md` §3：核心状态必须是速率而非次数）。
- 无联盟时不存在盟友边界反弹 → `S` 恒为 0 → 与旧行为逐位一致（无 RNG、无分支差异）。
- 更新顺序：`moveArmyGeom` 在移动前结算本 tick 泄漏（反射于 0），反弹处在 `processEnteredCell` 内 +1；
  因此单 tick 内多次反弹也能被同 tick 的放行判定看到。

### 12.2 放行

`S ≥ alarmThreshold` 即"该兵在此边界上持续受压"：

- 下一次"盟友边界尝试"走到**归属判定**那一步时（河/山骰已通过，避免用闸门覆盖地形规则），
  规则 2 的反弹被**跳过**：兵进入盟友格、**不反弹、不征服**，并把 `S` 清零（一次报警只放行一次）。
- 任何原因**成功进入盟友领土**（含海→盟友陆的规则 1、放行本身）也把 `S` 清零：尝试成功即压力解除。
- 放行后兵在盟友领土内按规则 1 直行，可自行离开飞地；若再被围，则重新累积、再次放行。

### 12.3 落点与参数

| 关注点 | 位置 |
|---|---|
| 状态量 | `comp::AllyGate`（`src/sim/components.h`）；新兵由 `SpawnSystem` 置 0 |
| "是否盟友陆地"唯一入口 | `ConquestRules.h::isAlliedLand`（`canConquerCell` 共用之） |
| 观测 + 放行 | `MovementSystem::processEnteredCell`（`bounceAtBorder` / 放行分支） |
| 每 tick 泄漏 | `MovementSystem::moveArmyGeom`（移动前，按步长归一） |
| 参数 | `config.allyGate`：`leakPerCell`(c)、`tolerancePerCell`(η)、`alarmThreshold`(h) |
| 持久化 | 快照 v15 的 `allyGate` 字段（影响模拟分支，必须入档） |

数值全部外置（`.docs/配置说明.md` 的 `## allyGate`），默认 `c=0.06 次/格`、`η=0.006 次/格`、
`h=5`：普通兵 0.15 格/tick → 约 0.009 次/tick，落在 `.docs/包围检测.md` §7 建议的 r* 区间内；
`h=5` 时泄漏概率约按几何衰减（`.docs/包围检测.md` §5）。**待实验**。
