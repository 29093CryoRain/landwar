# 不合规配置的现有行为

本文记录当前实现的观察结果，暂不改变解析策略。

## 核心配置

- JSON 语法错误、根节点不是对象：记录 warning，整个配置回退为 `Config` 内置默认值。
- 已知键类型错误：解析抛出异常，记录 error，整个配置回退为内置默认值。例如数字写成字符串、布尔值写成数字。
- 已知数字越界、非有限值或跨字段不满足约束：`Config::validate()` 失败，记录 error，整个配置回退为内置默认值。
- 缺少键：保留 `Config.h` 中的内置默认值，不报错。
- 未知键：记录 warning 并忽略；下划线开头的键视为注释，不告警。
- `units` 或 `factions` 中不是对象的数组元素会被跳过。未知兵种会被跳过；势力 ID 为负数或超过上限会被跳过。
- 势力 ID 必须最终连续对应数组下标。追加 `id: 9` 会扩展配置；缺少中间 ID 时仍可能因最终校验失败而整体回退。

## 配置片段

`render.json`、`techs.json`、`factions.json`、`units.json` 缺失、无法打开或 JSON 解析失败时，记录 warning，保留核心 `config.json` 中对应段的值。

片段缺少自身段名，或包含意外的顶层段时，记录 warning；只有对应段会覆盖核心配置。

片段合并后仍走完整的类型解析和 `Config::validate()`。因此，片段中的已知键类型错误或数值越界会导致最终配置整体回退，而不是只回退单个字段。

## 城市贴图表

`city_icon_fits.json` 缺失、解析失败或根节点结构不对时，保留空表；渲染时缺失的贴图拟合值使用 1 倍或 0 偏移兜底，并记录 warning。该文件的坏条目多数被跳过，不会像核心配置一样使整个核心配置回退。

## 选项文件

`userdata/options.json` 语法错误或文件不存在时，使用默认选项并记录 warning/info。选项字段类型错误时，当前读取辅助函数会忽略该字段并使用默认值；不会使程序退出。

选项中的 `factions` 是本局已选势力列表，每项用 `id` 指向势力定义库并保存 AI 和加入顺序。
最多一个已选势力可以设置为玩家。无效时主菜单禁用“开始游戏”。旧的按位置保存的 options
会按 `1..8` 迁移；新势力不会自动加入，需通过主菜单末尾的“添加势力”加入。

## 死配置核查

已确认不再作为核心配置读取的旧键包括 `map.file`、`map.width`、`map.height`、`sea.timeToUnify`、`sea.cyanSeaMult` 和旧的经济公式键；`render.city.iconScale` 也已由城市贴图表取代。这些键目前保留在兼容说明/历史文档中，代码会对其中多数未知键告警，但本次没有删除历史资料。

当前没有发现仍写在正式 JSON 中、同时完全没有读取路径的有效配置键。`Config::Map` 的文件和尺寸默认值虽然不再从核心 JSON 覆盖，但仍是无菜单/CLI 路径的兜底值，不应误判为死配置。原按 ID 返回势力简称的 `factionShortName()` 已确认无调用并删除，显示名统一来自势力配置。

## 影响

当前核心配置的容错粒度是“字段缺失保留默认，结构/类型/数值严重异常整体回退”。回退后程序通常仍能启动，但用户可能只从日志看出配置没有生效。发布前应考虑把日志错误显示到 UI、增加独立 schema 校验命令，并为“保留有效字段、拒绝无效字段”的细粒度策略补测试。
